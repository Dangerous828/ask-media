# 短内容

## 目标

把一件事压成读者愿意停下来的几行字。停下来的理由来自首行的具体性，读完的理由来自后面那条支撑它的事实。成稿要能直接复制发布，字数、链接位置、发布顺序都已按目标平台核对过。


## 执行流程

1. 定平台、读者、目的（见下节三条）。
2. 按平台核实当期字数上限与链接规则。
3. 写首行，再写支撑它的事实与代价。
4. 一条装不下就拆成串推，每条自成一块。
5. 交付前核对字符数、发布顺序与回复位。

## 动手前定三件事

1. **平台**：决定字数、链接放哪、能不能换行、要不要话题标签。
2. **读者是谁 + 他为什么停下来**：一句话说清这条给谁看、他看完能得到什么。
3. **目的**：讲清一件事、引一场讨论、还是把人引到一个链接／产品。目的决定结尾那句怎么写。

从用户已有账号内容、项目里的风格文件、他给的样本推这三项，推不出来才问，且只问会改变方向的。


## 平台规格：先核实再落笔

下面的常见值要按目标平台当期规则确认，不确定就 web_search 查官方页；平台改过限制，记错比查一次贵。

- **X**：标准权重 280 字符，CJK 每字权重 2，等于中文约 140 字。Premium 更长。串推每条各算各的长度。
- **微博**：普通账号日常上限与长文规则不一致，写前确认当期限制。
- **即刻**：单条可写到两千字量级，动态卡片首屏截断，重要信息放前两行。
- **公众号**：标题上限 64 字、摘要上限 120 字、封面常用 2.35:1（900×383）。这三个值直接决定文章能不能被点开，见 write-article。
- **小红书／抖音文案**：首行截断位置与话题标签用法各不同，需当场确认。


## 一条的写法

第一行必须独立成立：把钩子写在首行，别靠"接下来我要说"撑。首行给冲突、数字、结论、或一个具体场景，任选一个真的属于你要说的事的。

> 弱：今天想跟大家聊聊我们做这个功能的一些思考。
> 强：我们把导出从 40 秒压到 3 秒，代价是删掉了一个没人用过的选项。

一条只说一件事。想塞两件就拆成两条，或者转成串推。

正文顺序：钩子 → 支撑它的具体事实（数字、时间、原话、场景）→ 一句转折或代价 → 可选 CTA。CTA 只留一个，且要么给动作要么不给。

链接：X 上正文带外链会降低分发，常见做法是链接放本条下方的首条回复；其他平台按当期规则确认。这个话题标签：X 上堆标签通常不减分发就是无感，最多一个且必须真的分类；微博／小红书按平台习惯处理。表情符号：作者本人用就用，别用 🚀✨ 给句子加权重。


## 串推

- 首条是承诺："下面讲清 X 怎么做到的，N 条。"它要单独看完也有价值。
- 每条自成一块：读者从中间任何一条切入都能读懂并愿意转发这一条。做不到就合并。
- 一条一个信息点。举例给真例子（截图、数字、原话），不给抽象第三点。
- 末条回收：一句结论 + 那个 CTA。不要"感谢阅读"。
- 编号按平台习惯（不编号更干净，除非长度需要进度感）。


## 调用契约

输入：要说的那件事（一段素材、一个观点、一篇长文的摘要），可选的平台与账号风格样本。平台没指定时按用户常用平台推，推不出来问一句。

输出：可直接复制的成稿块，含平台、条数、每条的字符数与发布顺序；单条或串推首条另给 2–3 个候选钩子，各带一句差异说明，让用户挑而不是替他猜。

```
【平台】X · 串推 5 条 · 每条 ≤140 字
1. （正文，字数 128）
2. （正文，字数 96）
...
回复位：链接放第 1 条的回复
```

不做什么：不代登录账号、不代发、不刷互动、不编数据撑效果；长文章不在这里写，转 write-article。


## 安全与权限边界

发布、定时、跨平台同步按当前 Host 提供的工具或对应通道执行，没有通道就只交付文本。不代用户登录或发布，不替用户承诺效果，不编造互动数据。引用他人内容注明来源，转发他人作品先确认授权状态。


## 自检

必须过 humanizer：短句收尾、三连排比、加粗标签、"不是 A 而是 B"、"值得一提的是"、"让我们一起"这类在短内容里更刺眼，因为屏幕小、密度高。事实锁同样适用：不能为了效果编数字、编时间、编"很多人说"。要引用别人的话，得有原话出处，没有就改成自己的判断并标明是自己的判断。

逐条念一遍：首行单独看能不能站住；每条是否有且只有一个信息点；字符数是否按目标平台核过；链接位置是否符合该平台当期规则；CTA 是否只有一个。
