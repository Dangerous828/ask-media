# H3 视频提示词:人工 / 模型判断项清单

闸门(`scripts/h3_gate.py`)退出码 0 之后再过这份清单。每条只写"怎么判"和"依据"。
依据缩写:ref = 官方 ref-en.txt;base = 官方 base-en.txt;方言 = minimax-h3-dialect.md;
OPS / SPEC-R / STATUS = H3-Studio 的 OPS-NOTES.md / RENDER-SPEC.md / STATUS.md;审查 = opus-review-s1-s6.md。

## 1. 口型落点

- 怎么判:逐句台词问"这句话时画面里谁的脸最显眼"。说话人在画外或背对镜头,而画内有正脸人物时,必须写 `<Subject N> does not speak; his lips remain completely closed.`;说话人在画内时,写清是谁开口、嘴部动作在哪个时间段。两人同框对话,一句只让一个人动嘴。
- 闸门边界:G17 只查 off-screen 附近有没有 lips + closed 字样,不判断写的对象对不对。
- 依据:方言 246–249(模型把口型放到最显眼正脸上,实测 3 次中 2 次);ref 官方示例 "while his lips remain completely closed"。

## 2. 保留强度档位(retention marker)

- 怎么判:对每个标签问"这一镜允许它变多少"。
  - `fully_preserved`:身份、服装、构图都不许变(角色身份图、首帧构图锚点)。
  - `partially_preserved`:保留主体,允许姿态 / 局部变化。
  - `attribute_transfer`:只借颜色、材质、风格等属性。
  - `weak_reference`:只作氛围参考。
  - 音频:`fully_copy` / `partially_copy` / `reference` / `weak_reference`,按要不要原样复刻音色与内容选择。
- 逐图核对实际可继承的维度：认可光色不自动认可布局。若正文要求改变图中朝向/位置，不能一边保留整套几何、一边说只借材质；明确partial边界或回上游更换输入。参考职责冲突见 [停车案例](../../h3-prompt-writing/corpus/ep002-parking-contracts.md)。
- 闸门边界:G09 只查 marker 在枚举内。
- 依据:ref retention_analysis 规范;SPEC G09。

## 3. 对白装不装得进时长

- 怎么判:按"开口时间 + 字数 ÷ 语速"排一条时间线;默认 4.1 字/秒(与 G18 同口径),儿童、哭腔、拖音按 3–3.5 字/秒,成人快语速可到 5 字/秒(都用 `--rate` 传给闸门复核)。每句结束后留 ≥0.3s 再接下一句;尾句结束距片尾留 ≥0.3s。还要扣掉表演动作(捏鼻、叹气)占用的时间。
- 装不下时的处理顺序:删字 → 提前开口 → 加长到下一个 17k+5 帧数 → 拆成两次生成。
- 闸门边界:G18 用平均语速(默认 4.1)机械估算,不懂停顿与表演。
- 依据:方言 223(语速经验值);SPEC G18;审查对 s2 叠词的发现;SPEC-R 帧网格。

## 4. 跨镜服装 / 道具 / 状态连续性

- 怎么判:按镜序列一张表——角色 × 服装 / 配饰 / 污渍 / 手持物;道具 × 开合状态 / 位置 / 剩余量;场景 × 时间段 / 光向。逐镜比对:
  - 上一镜结束状态 = 下一镜开始状态(碗盖开了就一直开着;嘴角红油出现后不会无故消失)。
  - 身份定义句跨镜逐字复制(S02 只提示不一致,不判断哪个对)。
  - 光向、时间段一致(下午顶光不能一镜在右上、一镜在左)。
- 闸门边界:S01 / S03 只查 series-config 里写进去的词;配置没写的词它不知道。
- 依据:审查中服装词漂移(beige cardigan 与 apricot 设定冲突)等发现;SPEC S01–S03。

## 5. 音色一致性

- 怎么判:同一角色跨镜的嗓音描述用同一句(如 "a bright, slightly husky toddler voice");有音色参考时每镜都绑定同一 `<Audio N>` 并标 `fully_copy` 或 `partially_copy`。不要指望 Sx 编号保持音色——Sx 每次生成都按发声先后重新编号。
- 闸门边界:S04 只提示编号与 speaker_map 不一致。
- 依据:ref §5.4(Sx 按单次视频内首次发声先后编号);SPEC S04 说明。

## 6. `<Picture N>` 与上传顺序

- 怎么判:把实际上传列表写在稿边,逐张对照:第 N 张图 = `<Picture N>`;每张都在 `subject_definitions` 里说清用途(身份图写进 `<Subject N> is ... in <Picture 2>`;构图锚点单列 `<Picture N> is the composition anchor for [Shot 1]: ...`)。不要上传稿子里没提到的图。
- **席位纪律**(2026-10-30 按官方 ref-en §2.2 补):
  - 同一角色的多视图/多张身份图,合并进**同一个** `<Subject N>` 的图源引用(`<Subject 1> is ... seen in <Picture 1> and <Picture 2>`),不拆成多个独立 `<Picture N>` 条目——拆条会让模型当成多个实体(多出一个人/某个角色整段消失)。
  - `<Picture N>` 单列只允许五种用途:首帧 / 关键帧 / 尾帧 / 编辑后关键帧 / 构图锚点 / 分镜参考。纯身份图、纯场景板不单列。
  - 分镜板当参考时必须写清映射:`<Picture N> is a storyboard reference for [Shot 1] and [Shot 2], defining their viewpoint, subject placement, and shot order.` 缺这句裁定为"未声明用途"。
  - 多格分镜板上的双绑定标签(`[char:…] [scene:…] [shot:…] [dur:…] [hook:…]`)与分格线、箭头、时间码**不得进入正文**,渲染前剥离。
- 闸门边界:G08 / G08b 只核张数(需要 `--refs`),核不了哪张图对应哪个编号,也核不出是否把多视图拆成了多个条目——这几条必须人工逐图确认。已有图未准入时不自动删图或改让环境板接管构图；先解决缺口并同步参考职责，图数本身不能证明职责齐全。
- **参考图体检按链路走**(2026-10-30):`ref_guard.py --chain still|ref2va|first_frame`。Ref2VA 的多视图板是合法身份来源,命中只告警;首/尾帧必须是单画面,命中才阻断。图像判据对 AI 无缝拼版实测 0 检出,**真正拦得住的是正文里的版面压制句**(`no grid lines / no split screen / one continuous frame`),挂多视图或分镜板时用 `--prompt` 一起查。
- 依据:ref §2.2 / §2.3;SPEC G06 / G08b;官方模型能力(图像 ≤9、混合 ≤12);2026-10-30 官方 Ref2VA 分工核对。

## 7. 风格不得来自风格卡

- 怎么判:画风只由 `detailed_description` 开头 1–2 句英文风格句决定(如 "vertical 3D CG animated shot in the style of a modern animated feature: soft global illumination, warm filmic grade")。检查:
  - 没有把风格卡 / 风格样张当 `<Picture N>` 上传;
  - 没有 "style follows <Picture N>" 一类写法;
  - 各镜风格句逐字一致。
- 闸门边界:G04 只查风格句存在。
- 依据:ref §5.2;本工作流约定(参考图只承担身份与构图)。

## 8. 画面可见文字与中文

- 怎么判:除台词外,稿中不应有中文。确需出现的招牌 / 包装文字写成 `the sign reads "..."`,并预期模型可能写错字;关键文字后期贴。发音说明用拼音英文写(`the word wai-mai`)。
- 依据:SPEC G15;审查对 s1_v5 "外卖"的发现。

## 9. 时长规划

- 怎么判:先定帧数(17k+5:124 / 141 / 158 / 192 / 243 …),再写时间码;最后一个动作在片尾前收住并写 "holds until MM:SS.mmm"。
- 依据:SPEC-R 帧网格(非网格向上取整会导致时间码错位、尾镜被截);OPS 实测。

## 10. 生成后:音频转写核对(必须做)

- 怎么判:成片用 Whisper 转写(已验证 mlx-whisper large-v3-turbo):
  1. 首轮自动识别实际语音语言，不将所有短口号强制解成zh。中文剧情对白仍逐字核对；拟声、专名与混拼可按实际音节跨语言复核，字幕始终取创作者原文。
  2. ASR不是发音真值。重复循环、零长度词和高压缩率应标低可信，不能据此声称角色新增台词。发现真实吞字、错读、额外词才修补；不为迎合转写器改原句。
  3. 记录实际发声起止与口型。硬同步事件按本镜容差核对；没有硬落点时，若句意、表演顺序及可剪区间成立，不因统一±0.5s门槛重抽合格画面。
  4. 看画面确认嘴动的是说话人，再按真实尾音确定切点。2026-10-24本片首镜自动/en转写为“Goo goo gaga. Doro.”，强制zh却误写为“咕咕咕/呜呜”，故单次字面不一致不足以否决。
- **专用读法与既有录音**：跨语言ASR用于定位歧义，音近或语义相同不足以证明创作者指定的混拼发音正确。有已认可声源时先检索项目voice/audio目录与既有记录，复用真实裁片，记录声源指纹、落位及音高/速度处理；不能把多语转写一致当作发音验收。没有声源对照或音节听辨依据时，标未核验。
- 响度不足:在后期做人声 EQ 与增益,不要改提示词——"loudest / ducked" 实测仅 +0.15 dB,还会抬高底噪。
- 依据:STATUS 响度 A/B 实验与《角色D螺蛳粉》转写验证。

## 10b. 生成前物理与写法自查（人工项，闸门查不出）

- **主动者与跨界顺序**：按分镜核对谁先行动、哪只肢体先过哪道边界、对方看见什么才回应、接触在哪个空间。邀请、接触、穿越都出现仍须检查因果先后。
- **新增服饰不继承首帧豁免**：已接受A帧后，视频新长出的高反差白袖边等仍要对照角色设计；局部修补需保护原有颈饰、白肚皮、手指和其他角色。
- **手的物理预算**：逐角色数"手里持着什么、牵着谁、还要做什么手势"，合计不得超出两只手；三人牵手队形里"回头挥手"必须写明挥的是**相牵的那条手臂整体**（joined arm），否则物理矛盾。
- **高风险写法对照**：单镜动作节拍过载（3.5s 塞急停+转身+直视+O嘴+歪头+台词）→ 拆动作或延长；"冲破玻璃"→ 水波涟漪（否则玻璃碎片）；"身躯半透明"→ 只写轮廓金光+粒子、实体不透明（否则肢体融化）；多人同时间窗说话 → 错开发声窗（否则串音）。
- **同一声音/动作事件时间戳唯一**：时间码表、动量链、音轨三处必须同一时间戳，不允许"3.5s 行写第三击、5.5s 行又写余音"式漂移。
- **代号/物种词字面化**：`tiny penguin` 会被画成真企鹅；写 `a black-haired little girl in a penguin hoodie costume` 这类"服装+物种"全句。

## 11. 提交前最后确认

- 闸门退出码 0;所有保留的 warn 都有理由。
- 参考图张数、顺序与稿一致;帧数、分辨率(32 的倍数,≤768×1344)与稿一致。
- 依据:SKILL.md §2、§6。

## 12. 第 0 秒、构图帧与时间线(2026-11-06 补)

- 怎么判:
  1. 真实首帧逐项对 `00:00.000` 的人物、手位、持物与光；构图帧对其声明时刻的 read，结束帧对终点。后段构图帧已有稍后入画的人可以成立，正文写清入画时刻；只有被声明为开场的图才必须与0秒一致。
  2. `用途：构图` 的图写成 `composition anchor` 并带它对应的镜内时刻;只有 `用途：起始帧` 才写 first frame。G31 会对 `opening composition` / `begins from` 报 warn,warn 不是错误但每条都要有答案。
  3. 时间码自上而下递增(G11 倒退只是 warn,但几乎总是真错);反应晚于触发;每个动作落在分镜 reads 对应的时间窗里。
  4. 每句 `<d>` 前后有开口时刻;依赖这句话的反应排在它之后。
  5. G38 列出的每个绝对词,到时间线里找同一对象有没有在别处动过。
  6. 出片后:`seam_check.py --before <首帧.png> --after <本段.mp4>` 看 `luma_mean.change_pct` 与并排图，核对本片已接受的亮度关系和可比区域；−5–6% 仅是下述案例读数，没有通用通过阈值。变化或逐环累积时共同检查文字、实际输入、色彩转换及画面内容，不从均值直接归因（两边使用同一解码与色彩转换路径）。
- 闸门边界:G11/G31/G38 只做字面提醒,不知道谁该先动、谁是触发、图里到底有谁。这几条必须人工对着图和分镜 reads 读。
- 依据:midnight-cream-veil EP001 MOTION-003(`<Picture 1>` 写成 opening composition,图里已有男人而正文 1.4 秒才让他入画;她的反应 3.4 秒早于他开口 5.0 秒);MOTION-001("左腕全程贴着下巴"与"左手平放桌沿"同段并存);三段成片第 0 帧亮度比送入首帧低约 5–6%（seam_check 口径），续接每环再暗约 5%。
