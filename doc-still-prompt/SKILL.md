# 单帧图片提示词

## 任务与边界

把创作者已确定的事实组织成一幅可理解、可核对的画面。英文正文是提交给图片模型的内容；中文译文忠实对应事实，审计说明保存来源、取舍和制作要求。正文连贯与事实齐全须同时成立。

本技能只写文字。生成、付费、队列和媒体验收分别按当前生产与审查技能执行；写词、跑文字检查、既有接受状态都不自动授权新生产。未生成或未看原图时只报告文字审读，不能宣称画面已验证。

工作链只有四层：**本帧事实与用途 → 唯一模型正文 → 参考/参数/通道绑定 → 风险审计**。事实先于正文；参考与参数不能另造一套画面事实；审计按本帧实际风险选择证据，不用审计 prose 代替正文。

## 先识别任务，再加载资料

先确定：本帧用途、项目介质、必要可见主体、输入来源、输出落点。分开记录写作者能看的来源图与生成器实际收到的输入。**纯文生图**时，来源图只用于观察，唯一英文正文须独立承载目标的画风、受光、空间、主体与接触关系；**垫图/编辑**时，明确图像实际控制哪些属性。不为填字段新增镜头、角色、道具或改变已接受的画风。

| 本次任务 | 必要输入与协作 | 输出落点 |
|---|---|---|
| 独立静帧/反推现有图片 | 创作者要求；反推读取实际图片、[外观与纯文生图核对](references/appearance-reconstruction.md)、[成文](references/visual-prose.md)及本帧对应的介质参考，区分观察与推测；先查 [语料库](corpus/README.md) 有无同类介质/场景条目，有则对照其观察陷阱与已验证句式 | 用户指定位置；无既有格式时用下方单帧模板 |
| 短剧资产板、视图、状态变体 | 读取 [资产图片提示词](../drama-skills/skills/short-drama-image-prompts/SKILL.md) 的 Look、参考职责与制版要求 | 现有《图片提示词.md》条目；不叠加第二套项目文档 |
| 短剧镜头静帧/冻结关键帧 | 读取 [分镜](../drama-skills/skills/short-drama-storyboard/SKILL.md) 的本镜职责、取景、状态、连续性及 [镜头语言](../drama-skills/skills/short-drama-storyboard/references/keyframe-camera-language.md) | 现有《分镜.md》或对应提示词条目；必要运行快照从同一正文导出 |
| 多人、画中画、背影、局部裁切 | 写前读 [场面与可见身份](references/multi-character-scenes.md) | 明确实例、区域、可见部分和归属 |
| 3D具体翻车 | 读 [3D排障](../anim3d-still-pitfalls/SKILL.md) 中实际命中的问题 | 根据原因修本帧，不全量追加避坑清单 |

只有跨阶段、初始化或查项目状态时才读 [短剧总路由](../drama-skills/skills/short-drama/SKILL.md)。协作见 [路由契约](../SHORT-DRAMA-ROUTING.md)。当前任务已明确时直接完成，不循环派单。

## 一、确定本帧事实（L0）

先读已接受的上游与本帧实际输入。以身份库、视觉设定、分镜和创作者决定为依据；参考图按身份、画风、地点、构图或姿势分别说明用途。参考中的正面、站姿、闭嘴、背景不自动成为本镜事实。

1. **身份与实例**：谁在画面里、分别有几个、属于现实还是屏内/反射/图片中的哪个区域。权威库把完整身份写在实际角色标题下并给 `presence` 出场标记；同库可登记可见视角锚点。正文引用本帧适用的完整或已登记可见视角锚点，不能让通用库标题冒充角色身份。不能为润色改衣换脸，也不能为照抄不可见脸眼而强改取景。缺合适锚点时按既定身份登记可见版本，不另建平行身份库。
2. **用途与瞬间**：沿用上游的 `composition / start / pose_proof / end` 或同义用途。构图参考选能说明本镜关系的瞬间；作为视频首帧时才写该段真实起态；姿势证据与终态不能冒充起态。运镜相位、物件状态分别判断。关键数字文字如何在后续形成由上游制作方案决定，不因写词统一改为亮着或空白。
3. **接触与支撑**：保留剧情需要的站、坐、蹲、躺、跑、跳或特殊姿势，写清当下承重、接触与运动相位。悬空可能是跳跃/飞行的正确瞬间；复杂交互要说明力与归属。确有实现风险时给出有依据的实现选择，不能自动改成端坐或删核心动作。
4. **构图边界**：画幅、视点、人物位置、可见范围与焦点服从本镜任务。中心构图、深焦、无前景都可成立。只在有用且有依据时给占比、角度或距离；不强制三层纵深、固定占幅、大俯角或非居中。

已接受资料互相矛盾时，指出具体冲突与受影响事实；能由现有上下文解决的直接处理，核心剧情或画风真实分叉才交创作者决定。无证据不转写为肯定设定。

## 二、记录依据与取舍

只记录本帧必要事实和会影响画面的推导。生计、季节、衣饰功能、物件史等仅在影响当前可见内容时查；资料已经在项目里就复用。需要外部事实再检索，给出实际出处；未经查证的常识或设计选择如实标明，不编检索记录。

| 事实/选择 | 本帧可见结果 | 来源及状态 |
|---|---|---|
| 项目事实、画面观察或明确设计选择 | 当前身体、空间、接触、受光或材质关系 | 指向实际资料；区分已接受/观察/推断/待验证 |

按需要增减行数。不可见项写原因；不适用项可省略或记 NA；未知且关键的事实需解决，未知且非必要的细节降低具体度或不写。不为凑十行添加伤痕、脏污、人物履历或光学参数。

## 三、建立空间与动作关系（L1）

先用中文确定机位、各主体位置与此刻状态，再组织英文。

- 人物的身体朝向、头部朝向、视线目标是三个独立事实，可在同一句中表达。目标用实际对象；眼不可见或眼部方向非必要时在裁决注明。头部背面可见但眼睛不可见时仍写可见头向，不给 `head_en=NA`；只有头部方向未指定且对本帧非必要，或头部本身不可见时才记 NA 并给原因。不要按 body/head/gaze 各造一句。
- 多主体要同时读清眼睛时，核对躯干朝向、头部回转与眼睛目标的共同几何。要求双方互看不等于两张脸正面相对；可通过相向站位、略向相机侧的躯干或头回转保留可见双眼。不得把互不相容的朝向当作分别“有字段”就通过。
- 机位的左右、角色自身左右与屏幕左右分清；换机位后重新投影，跨镜规则不能原封照搬成“恒在画左”。轴线由上游决定。
- 持物、身体部位、接触和特效逐个归属。多个同类物件先在事实层裁决数量并给稳定实例名，如 `BOWL-A / BOWL-B`；正文用可理解的位置或外观回指同一实例，不把实例 ID 当画面文字。物体有容器或承托层时，各层关系须成立；提出的内容物回指同一容器。可合写，不按层数分句。
- 遮挡由真实纵深、实体边界或取景形成。需要遮一部分时描述交界位置与可见结果；不靠删人体部位。普通多人分置不强制重叠、遮眼或亲密接触。
- 几何比例、边界、分隔线可帮助表达精确布局，数量和文字事实仍如实保留。它们是输入约束，不是模型执行保证；反复失效须核对实际参考、画布和输出，再调整方案。

细节词表按需读 [调度](references/blocking-staging.md)、[机位](references/camera-angles.md)、[构图](references/composition.md)、[动作动机](references/action-motivation.md)。这些是选择工具，不覆盖已定分镜。

## 四、选择介质、光与表演（L2–L3）

反推、画风复刻或本帧外观尚未建立时，写前读取下表对应介质的基础参考；眼部等专项仍按可见性选择。先保留线条/色层或成像影调、光落在哪、哪些面收暗及材质如何响应，再成文。`anime`、`photorealistic`、`high quality` 等类别词不代替这些关系。具体相机、灯型与软件未经来源确认时只写可见效果。

**写前对照**：观察原图后、成文前，按 [语料库观察陷阱表](corpus/README.md) 逐条自问（肢体沿连线归属、遮挡末端不猜接触、亮色形态只写光学外观、机位要有投影证据、影调先锚最亮最暗、逐眼核对表情）；同类条目里已验证的句式优先复用其结构。

| 分支 | 写作重点 | 对应基础参考及按需资料 |
|---|---|---|
| 真人摄影 | 与项目一致的一套成像系统、可见皮肤与衣物、实际光路、必要曝光与清晰范围 | [真人质感](references/global-quality-prefix.md)、[眼部](references/eye-anatomy-catchlight.md)（只有眼区可读且重要时） |
| 3D动画 | 项目选定的造型、体积与表演，合适的材质/渲染方式 | [3D介质](references/animated-3d-look.md)；SSS、PBR、轮廓光按该 Look 需要选择 |
| 2D插画/漫画 | 项目选定的线条、色块、明暗与表情形状 | [2D介质](references/comic-styles.md)；不混入真人泪膜/毛孔或强制摄影景深 |

**光**：说明必要光源、方向、落点、遮挡与材质响应。光源可以在画外，可以多源；人物看向的目标与主光不必同向。暗部可有反弹、过渡，也可按画风成为剪影或平涂色块。背景灯、天空与屏幕可比脸亮，按叙事选择亮度层级。

需控制光比时，以可识别的两处表面作相对锚点，档差标为设计值或观察估计。避免把反平方衰减套到所有距离与面光源，也不靠任意精确数值制造可信感。按需读 [光位](references/lighting-angles-shadows.md)、[光比](references/lighting-ratios-falloff.md)、[预设](references/lighting-presets.md)。

**表演**：本帧有表演任务时，把对目标的态度落在一两个可见笔触；可以直接以动作和形状表达，不强加情绪标签。资产中性态、远景、背影、手部或无表演任务可 NA。按需读 [微表演](references/performance-micro.md)。眉、眼睑与嘴部可有多种组合；不以简化肌肉对抗表否决真实表情。

**细节**：身体体积、皮肤、接触形变、材质、高光与成像质感按景别、可见性、画风和任务选择。材质种数、器官细节、缺陷签名、光源数量均不设通用配额。

## 五、成文、译文与摘录

首次写词、正文呈清单状、混入生产备注或构图反复改词无效时，读 [连贯画面正文](references/visual-prose.md)。

- 开场明确介质、必要身份和核心关系。随后沿动作目标、接触、前后景与受光展开；换主语时交代其空间或动作联系。
- 同一处的姿态、衣料、受力与受光可合写。允许长短句和自然段，不以句长、主语数、层级顺序或固定填空模板衡量质量。
- 英文只写当前可见状态与形成它的必要关系。后期用途、未来动作、参考职责、帧相位标签、跨镜持续要求留在制作说明；其当前可见结果进入正文。
- 中文译文忠实覆盖英文事实，可自然分句。核对事实覆盖，不要求一行账本对应一句英文。
- 人物事实需要几何审计时，从成文摘录 `camera_en / body_en / head_en / gaze_en` 的连续片段，允许共处一句。短语须能证明对象与方向，可以用清楚的代词回指同一对象；若同一事实对多人一致，可给多人摘录同一短语。改正文后重新摘录。不可见或非必要项记录原因，并将对应英文证据记为 `NA`，不为了锚点补画。
- `camera_en` 必须表达实际机位；画幅、介质或场景开场句不能替代机位事实。镜头静帧（含空镜）必须有一条机位锁和非 NA 的 `camera_en`；普通静帧/资产可省略整行，或在机位未指定且非必要时写 `camera_en：NA` 与具体原因。是否真正表达位置、角度和高度由 `6c` 人工审读，结构检查不猜测语义。
- 英文正文可以包含引号内的中文或其他精确画面文字；精确文字由 `exact_text` 契约逐字核对。中文译文仍放在独立译文段，不混入唯一英文正文围栏。

```text
- 机位锁｜位置：<中文机位事实>｜camera_en：<正文片段>
- 人物构图：<角色>｜身体：<朝向或不可见及原因>｜头部：<朝向或不可见及原因>｜视线目标：<实际对象或不可见及原因>｜body_en：<片段或NA>｜head_en：<片段或NA>｜gaze_en：<片段或NA>
```

直视镜头可以是有意选择，在裁决说明用途；正面身份参考不自动授权直视。七项镜头语言是镜头静帧的取景事实，沿用上游；普通资产或独立静帧不强制创建七项记录。镜头静帧包含起态、姿势证据、构图参考和终态；本技能以 `--frame-kind keyframe` 或裁决 `帧类型：keyframe` 表示，不要求上游已有完整分镜时才使用。相位标签留在裁决，英文写该瞬间实际状态。

优先写正向可见关系。自然语言中的数量、比较、画外目标或必要否定不因词面自动判错；回读它是否表达清楚、是否携带无关对象。排除项另列拦截表，只有目标通道有启用的独立负向槽时才映射；人体部位、身份特征与剧情元素应通过正向关系解决。通道能力按 [h3-queue](../h3-queue/SKILL.md) 当前档案确认，不在本技能复制采样配方。

### 千问（Qwen-Image）成文结构

千问是用 LLM 生成的长段落 caption 训练的，**原生语体是"描述画面里有什么"的连贯段落**，不是 SD 那套逗号标签堆叠。照官方改写器的骨架组织：

1. **开场句给全三要素**：`The image is a ⟨风格⟩ ⟨媒介：photograph / illustration / poster / portrait⟩ of ⟨主体⟩, ⟨背景与色调⟩.` **媒介名词不能省**——省了模型不知道该出照片还是插画。
2. **背景紧接开场句**，不要压到最后。
3. **方位铺开**：约三分之一句子以方位短语开头（`On the left side of the frame…` / `In the upper-left corner…` / `Across the lower third…`），覆盖四角、边缘与中心，不要全挤在中间。
4. **人像顺序**：族裔 → 性别 → 年龄段（写年龄段不写具体岁数）→ 服装（带面料）→ 五官/肤质 → 姿态与视线 → **手部动作单独写清**。
5. **光照单独一句**，写光从哪来、哪些面受光、哪些面入暗。
6. **收尾一句总览**，只写一句。
7. **风格词只写一次**（开场句里），结尾可呼应一次；**不写质量词**（`masterpiece` / `8K` / `highly detailed` / `award-winning`）——官方明令禁止，且会被画成画面里的文字。
8. **画幅与分辨率不进正文**，走参数（图片通道是 `--size WxH`；`--width/--height` 是视频参数，给到图片分支会被丢弃）。

**长度**：本机 Qwen-Image 2.1 目标 200–350 词。英文约 1.3 token/词，350 词≈455 token 仍有余量，400 词以上就贴着截断线走，后半段可能等于没写。宁可少写不可堆满。**200–350 是本机 ComfyUI 链路短提示词场景的目标，仅适用于本机这条链路**：官方 Qwen-Image 写作建议的 400–500 词是通用长 caption 场景的目标，两者面向不同链路（本机实测有效长度／截断经验 vs 官方通用语料），不互相替代，也不要把官方词数目标当本机硬指标。
这里的截断线是**实测有效长度／短提示词场景下的经验值**，不是编码器的 token 上限；编码器 4.5K token 上限是编码器侧硬上限（社区博客，未在本机验证），两者不是同一件事，不要把 4.5K 当成可以写到那个长度。

**否定与排除项**：正文只陈述存在什么，不写指令句。要压制的伪影、不要的字幕水印、不要的多余道具，全部走 `--negative`。

负向映射与跳过条件见 [engine-params-qwen §2](references/engine-params-qwen.md)（标准 CFG 双条件结构与两种跳过情况）；术语分层（两层丢弃）见 [still-api-params 术语与分层节](../h3-queue/references/still-api-params.md)。

**手部这类"别拿东西"的意图用正向写法**：写手掌张开、掌心朝向、指尖松弛，让手看起来本来就空着；不写 `neither hand holding anything` 这类否定声明——声明不改变模型画什么，只会占注意力。

## 六、参考与执行绑定

在制作元数据记录实际参考 ID、目标主体、用途、顺序、路径与允许/禁止控制范围；记录目标通道实际接受的画幅、尺寸、种子、采样和独立负向槽。绑定只解释唯一正文怎样执行，不创建第二份场景正文。

- 参考职责使用 `identity / style / location / composition / pose` 等明确用途；正面、站姿或背景只约束被授权的槽位。
- `composition / start / pose_proof / end` 是本帧用途。生产从《分镜.md》选图时使用 `SHOT-...#KF-...` 复合选择器定位具体帧；缺起始帧正文须补写或改选真实参考，不把构图正文当首帧。
- 视频参考的 `用途：起始帧` 对应 `role:first_frame`，`用途：结束帧` 对应 `role:last_frame`；构图、姿势证据与普通身份参考保持各自用途。
- 通道需要 JSON、中文、参考标签或负向字段时，由执行适配器从同一正文和绑定生成；手写候选不进入提交层。
- 绑定交接给提交时必须带上参考文件清单（每张图的路径、用途、顺序），不能只给用途词：提交方按这份清单核对 `--refs` / `reference_bindings` 是否齐全，清单上有图、提交里没有图，就是漏提交；`--generation-mode` 必须与清单一致，有参考图用 `reference-to-image`，无参考图才用 `text-to-image`。
- 垫图改纯文生图时，重新检查原先由图控制的必要事实是否已经进入正文，更新实际上传清单与模式；只有删除 `refs` 不算完成转换。文字相同、输入变化也要重新审读。

## 七、交付与核对

已有正式条目沿用其结构，把同一英文、译文与必要依据落回当前条目。没有既有格式时，可用 `<项目>/prompts/<帧号>.md`：

1. **账本**：必要事实、可见结果与实际来源，行数按本帧需要。
2. **裁决**：用途/瞬间、画风、输入取舍、实际风险及冲突。记录 `帧类型：still / keyframe / asset`、`用途：composition / start / pose_proof / end`（独立静帧可记 `standalone`）、`审计：core / full` 和适用的 `风险：multi, exact_text, contact, continuity`。keyframe 指镜头静帧，不等于首帧。
3. **提示词**（可用 `唯一英文正文` 标题）：唯一一份实际提交英文放在 `text` 围栏；中文译文另列。不要把多个英文候选、负向串或身份示例混成可提交正文。
4. **验收单**（可用 `文字核对表` 标题）：按下方模块回答 yes / no / NA＋证据或原因。缺项与不适用分开；NA 必须写实际理由，不能拿检查项题干代替理由。

### 核心项与风险模块

每帧回答核心项 `L0_1, L0_4, 0f, 9, 12, 16`。根据 CLI 下限、裁决声明和明确结构证据启用模块；未声明风险只表示本次未选择该模块，不证明风险不存在。

| 模块 | 追加核对项 | 必要证据 |
|---|---|---|
| `multi` | `0c, 6c` | `出场：甲,乙` 登记全部可见人物；每个实例各一条人物构图。普通多人静帧不强制机位锁 |
| `exact_text` | `5b` | 每处精确文字一条 `文字契约：ID｜exact：逐字文字｜位置：画面区域`；正文逐字包含 |
| `contact` | `L0_2, 0c` | 每条关键关系一条 `接触契约：ID｜主体：谁/哪部位｜对象：实例｜关系：当前接触或相位｜可见性：实际可见结果`；不可见关键关系标 NA 并审读制作影响 |
| `keyframe` | `L0_3, 6c, 15` | 帧类型自动启用；明确用途、七项镜头语言和实际机位锁；有人物时逐人摘录 |
| `continuity` | `14, 15` | 权威身份视图、上游用途/时刻、跨镜连续物及来源 |
| `full` | 全部 15 项 | 仅创作者或项目明确要求完整表时使用；已填写的其它行仍全部校验 |

`contact` 的左右手、坐/站、承托面与可见性分别核对；不能由“有坐姿字段”推断支撑可见，也不能由“有持物字段”推断左右手已经落实。多人且存在复杂接触时同时启用 `multi` 与 `contact`。

L0 的 no 表示人工确认存在未解决的重要事实冲突，应先处理。其它 no 按实际影响修订或明确记录创作者接受的偏差。不能靠填写 yes、NA 或冻结备案证明事实正确。

可用 `python3 scripts/gate_check.py <帧稿> --skill <技能目录> --audit core [--risk multi|exact_text|contact|continuity]` 检查格式、风险契约与摘录一致性；镜头静帧加 `--frame-kind keyframe`，自动启用对应模块。需要全表时显式 `--audit full`。独立 SHOTLIST/IDENTITY 布局可加 `--project`；已有其它布局用明确的 `--identity` / `--shotlist` 来源，只有其中一项也会检查该项，或在正式条目人工核对，不重建三件套。

脚本只检查可确定的结构和引用。缺少某个情绪词、光学名词、前景或容器不等于语义错误；命中词表也不证明画面成立。输出必须区分结构问题、待审提示与未评估内容，退出码不是出图授权。

纯文生图反推或外观复刻时，在既有核对表中实际回答 `7`：对照来源图，给出正文中承担画风与受光关系的片段及观察差异，不能只填“anime/闪光/细节丰富”。先遮住原图与账本只读英文，检查能否还原关键视觉关系，再回图查漏；漏项修正文，不靠补 yes 消除。结构检查不替这一遍作结论。**闭卷回读必须留痕**：验收单 `7` 的证据里写“闭卷回读：读出了 X／漏了 Y”；没有这行即视为未完成自审，返修稿同样重做。

复杂多人、已有失败、纯文生图复刻或重要交接另请未参与写作者审读本镜必要事实、实际英文和真实参考；处理实质问题后交付。文字审读只证明这次读稿的覆盖情况；只有真实纯文生图输出经实看才能报告其效果通过，垫图成功不能替代。生成物的画风、剧情和连续性由 [short-drama-review](../drama-skills/skills/short-drama-review/SKILL.md) 实看验收。本技能不要求凭文字先验收尚未生成的图片，也不以 contact sheet、文件存在或队列完成冒充已看原图。

## 工具与参考选择

可选 `scripts/k3_write.py` 按指定画风和任务载入主技能与必要参考；`--frame-kind` 与 `--generation-mode text-to-image|reference-to-image` 必须显式给出，默认 `--audit core`，风险用可重复的 `--risk` 声明。写词API仅接收文字：反推前由调用者实际观察来源图，通过 `--context` 提供必要事实，并用 `--reference appearance-reconstruction.md` 加载对应方法；不能把文件名当作已看过图片。同类介质/场景有已验证语料时用 `--corpus <条目名>` 加载（见 [语料库](corpus/README.md)），复用已验证句式并对照观察陷阱。反推/复刻任务建议显式 `--model` 指定强推理档。项目只自动读明确的基础资料，当前条目、审核结论与真实参考用 `--context` 明确选择。缺失显式输入须报错，历史产物不自动遍历注入；写词模型不被当作拥有检索工具。

模型响应只有完整结束才写正式稿。截断、空响应与读取错误保留现有文件，报告实际状态；草稿写入成功与文字检查状态分别报告。密钥只从已配置环境或供应商配置读取，不打印、不写交付物。
