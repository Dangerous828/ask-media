# 变更记录

## 3.4.0

- 新增 `references/engine-params-qwen.md`：记录「同一份正文，GPT2.6 一次就对、千问压成黑块」的参数层成因与刻度。实测（2026-11-09，本机 h3q，seed 42，40 步，两场景对照）：
  - 整段曝光形容词近乎无效：加了 `WELL-EXPOSED KEY IMAGE / 55% luminance / nothing crushed to pure black`，平均亮度只从 9.5 → 10.9（0–255）。
  - `cfg` 是主杠杆且**方向反直觉**：调低才变亮。本机甜点 2.0–2.5；3.5 压黑；4.5 崩坏出绿斑。与 ComfyUI 官方「高值使曝光偏向过亮或过暗（偏移而非单调）」一致。
  - 负向词必须配 `cfg > 1`：本机默认 `cfg=1.0` 会把 negative 整段丢弃，这才是「加了负向词没反应」的原因。
  - 正文用官方「观察体」（`Observe, don't instruct.`，不写 `make sure` 与质量词，光单独一句）比指令体更接近参考：官方体+负向词 70.2／近黑 25.9%，对 GPT 的 51.7／29.0%；原提示词+负向词反而过亮到 82.2／15.2%。
  - 垫图能救约一半（9.5 → 28.0）但会压构图，只在必须复刻构图时用。
- 边界：本页只管 Qwen 静帧，**不外推到 H3 视频**（静帧负向槽与视频负面通道是两套），不覆盖已验收项目写法，步数/档位/LoRA 仍归 `h3-queue`。
- **补记「不止是光」一层**（同日第二轮实测）。只补曝光会让画面"亮起来但空"，真正拉开观感的是丰富度与质感：
  - 裁同一区域放大对比：千问的人脸细节其实接近 GPT（皱褶、发丝、毛孔在），差的是**人脸背后是一整块无信息平面**，GPT 背后有窗帘/相框/门框暗部/墙面脏污。补环境密度后边缘密度 4.9 → **7.9**（GPT 4.6）、局部反差 19.7 → **29.3**（GPT 17.7）、色彩数 4969 → **6381**（GPT 3322）。
  - **但超过不等于更好**：补完密度那张饱和度到 68%（GPT 29%），细节多而**均匀**，像样板间；GPT 的脏是**不均匀**的。这个差异量化指标测不出，只能实看——自审不能省。
  - **调色与细节此消彼长**：加调色段把 B/R 从 0.423 拉回 **0.721**（GPT 0.758），但边缘密度同时 7.9 → **2.9**。压饱和+统一色偏会顺手抹掉质感，调色必须很轻且重看细节。
  - 记录可用句式：写"有历史的表面"（the varnish worn through in a broad band where forearms have rested for years）优于写"有什么东西"（clean wooden table）；冷暖要两套光源**重叠而非融合**（the two sources overlap rather than agree），写"柔和温暖"只会得到一片橙。
- **补记选型边界一节**（2026-11 核对）。结论：对 16GB 本机换模型基本不通，卡在许可/显存/中文脸三件事：
  - **许可**：Qwen-Image-2.1 是 Qwen Research License（仅研究评估），商用需另签；Qwen-Image-2512、Z-Image-Turbo、FLUX.2 klein 4B 为 Apache 2.0。官方「输出物不属于授权材料」的澄清只解决图归谁，不解决能否接活。
  - **显存**：2512（20B，Q4 13.2GB + 编码器）与 FLUX.2 dev（32B，需 24GB）本机跑不动。
  - **Z-Image-Turbo 实测**（已装 Q8 GGUF，同词同 seed 1536×896）：皮肤与织物真实度确实最好——前臂汗毛逐根可见、桌面有菜汁污渍与酱油圈、领口磨损可信；但**默认出欧洲面孔**，加东亚脸约束后曝光塌回（亮度 55→15），等于重走千问的坑。
  - 结论：不换模型，继续用千问 2.1 + cfg 2.5 + 负向词 + 补环境密度；Z-Image 另开一轮实验。
- **修正「欧洲脸」的成因，并回查 LoRA 生态**（2026-11-10）：
  - **真因是介质词，不是模型**。同词同 seed 只改开头：`wide cinematic 3D-rendered scene` → 四个中国角色全成白人；`wide cinematic photograph` → 中国人面孔、曝光正常。量化：边缘密度 2.9 → **4.4**、色彩数 2696 → **4008**，两项都超过千问 D3（2.9 / 2856）、逼近 GPT2.6（4.6 / 3322）。
  - 机理：`3D-rendered` 不只改渲染风格，会连带改写人物族群——模型学到的是「西方 3D 动画/游戏角色」整包特征。写中文写实题材必须用 `photograph`，不能沿用「3D CG」说法。
  - 这解释了社区为何说 Z-Image 默认偏亚洲脸（MindStudio：`strong tendency toward young female subjects with Asian or Han Chinese features`）：社区看到的是默认行为，先前看到的是被 `3D-rendered` 带偏后的行为，两者不矛盾。反方向才需要 LoRA（Reddit：Western LoRA 0.6 strength 才能出白人）。
  - **LoRA 生态结论：本场景不需要**。无官方 LoRA，官方只提供训练支持与推理加速；第三方 Civitai 有族群向条目（`Chinese Male Handsome` 等）但为 2025-12 第三方整理、未本机验证；Turbo 直接训 LoRA 会破坏蒸馏，需 de-distillation adapter，社区亦有训崩身份的报告。**LoRA 改画风/身份，不修写错的介质词。**
  - 结论更新：Z-Image + `photograph` 纳入商用候选（Apache 2.0、6B、Q8 GGUF、9 步约 16 秒），但尚未接进 h3q，需先打通提交入口。
- **补充 Z-Image 完整档案 + 多画风实测，并更正一处自己写错的成因**（2026-11-10）：
  - **更正**：上一版把「欧洲脸」归因于介质词 `3D-rendered`，**错了**。那次对比同时改了两处（换 `photograph` 且加了 `Chinese`），混淆了变量。补做单变量（保留 `3D-rendered`、只加 `Chinese`）→ **出中国面孔**。真正起作用的只有族群标记，介质词只管风格。过程与更正理由保留在文档里，因为「同时改两个变量」是容易再犯的错。
  - **官方四变体**：Turbo 8 步 / **不支持 CFG 与负向词**（官方写死 `guidance_scale=0.0`，本机节点 tooltip 亦印证）/ 多样性 Low / 不可微调；base（Z-Image）50 步 / 支持 CFG 3–5 与负向词 / `cfg_normalization: True 用于写实`。**想精调曝光必须换 base 权重，本机只装了 Turbo。**
  - **多画风实测**（同 seed 42 / 1536×896 / 9 步）：日戏窗光 Z-Image 略胜（姿态与陈设更自然）；阴天医院平手（都需显式写族群）；夜戏餐桌平手；**3D CG 玩偶千问胜**（毛毡纤维与雨衣污渍更重，Z 偏"干净新玩偶"）。3D CG 那组量化：千问饱和 63%/亮度 46 vs Z 31%/69。
  - 落地分工：内部试构图/日戏用 Z-Image Turbo；写实短剧帧与"脏旧质感"用千问 2.1；商用交付走 Z-Image（Apache 2.0）但族群必须两处都写。
