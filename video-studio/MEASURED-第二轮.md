## 致命 1：管线把「死黑阴影」注入正向词流

### 复核说的

`build()` 无条件把 profile 的【规避】追加到尾部。cfg=1.0 没有负向通道，
`死黑阴影` 会被按正向渲染 —— 等于每一张图都在要求模型画死黑阴影。

### 我核实

```python
# 修复前 build_prompt.py:141-147
parts = [profile["anchors"], shot]
if profile["avoids"]:
    parts.append(profile["avoids"])       # ← 无条件追加
return "，".join(...)
```

产物实际结尾：
```
…【画幅】16:9，照片写实，廉价塑料，低多边形，死黑阴影，完全平面化。
```

**成立。** 而且违反我自己上轮立的规则：「排除项只放末尾，且只写风格/介质，不写场景否定」。
`完全平面化`、`死黑阴影` 是场景否定，本就不该出现。

### 这正是问题 8 的答案

「替换而非追加」要替换的不是镜头层，是**【规避】的存在方式**：

> **cfg=1.0 下规避不能以文本存在，只能以拦截规则存在于脚本里。**

### 修复

`build()` 不再拼接【规避】。profile 的【规避】并进禁用词表，由脚本拦截，不进词流。

## 致命 2：闸门会拒绝全数据集最优的输入

### 复核说的

官方基准词（亮度 125.2 / 暗部 4.9%）过闸会被拦。

### 我核实

```
$ python3 build_prompt.py --profile 3d_anime --shot official264.txt --check-only
FAIL: 镜头层含禁用词（色彩权归 profile 独占）
  行1  [色彩]  blue
  行1  [色彩]  golden
exit=1
```

**成立。** 而官方那些色彩词恰恰附着在发光实体上
（`golden particles` / `neon blue data streams` / `luminescent code`）——
**正是我 R3b 要的"哪片表面被光铺满"。全局色彩禁令把让官方词生效的机制本身禁掉了。**

### 修复

禁令收窄到**全局调色类**（色温/调色/配色/滤镜/暖调/饱和度），
放开**实体+发光色**（金色粒子 / 蓝色光带 / 暖光）。

验证：官方 264 字现在 `PASS: 镜头层无禁用词`。

## 指标错误：`gray<50` 在惩罚正常中间调

复核指出：我用的「暗部占比 gray<50」方向错了。

- Toonflow 原文要的是「亮暗过渡柔和，**暗部不死黑**」→ 对应量纲是**死黑占比 gray<16**
- `gray<50` 在暖调室内是**正常中间调**

### 修正为三件套

| 指标 | 定义 | 目标 |
|---|---|---|
| **死黑占比** | `gray < 16` | < 5% |
| **中间调占比** | `50 ≤ gray < 200` | > 60% |
| **灰度熵** | 直方图熵 | 防平化护栏（降暗部把画面写平，熵会掉） |

---

## 关键对照：官方 264 字裸跑 vs 过管线

这是复核要求补的、此前缺失的一格：

| 版本 | 亮度 | 死黑<16 | 中间调 | 暗部<50 | 熵 |
|---|---|---|---|---|---|
| **官方 264 字 裸跑** | 35.7 | **30.7%** | 21.1% | 78.3% | 6.55 |
| **官方 264 字 过管线(+3D锚词)** | **56.4** | **5.5%** | **46.9%** | 52.2% | **6.94** |
| 官方基准（Gemini） | 125.2 | 0.0% | 84.8% | 4.9% | 7.67 |
| 旧 skill 长词 | 44.8 | 30.4% | 33.8% | 65.5% | 6.92 |
| 三轮（含"死黑阴影"） | 39.5 | 18.9% | 17.2% | 80.9% | **6.41** |

### 三个结论

**① 病不在词，在链路。**
官方 264 字（Gemini 跑出 125.2 亮度的词），在本地 Qwen 上**裸跑只有 35.7 亮度、30.7% 死黑**。
同一句话两个模型差 3.5 倍亮度 → **本地 Qwen 的默认明暗倾向就是偏暗**，不是提示词写错。

**② 加 3D 锚词反而改善。**
同一句官方词 + `3D动画渲染/柔和暖调电影打光` 前置 → 亮度 35.7→56.4，
死黑 30.7%→5.5%，熵 6.55→6.94。

**profile 前置锚词是有效的。** 这条以前没验证过。

**③ 三轮数据的熵最低（6.41），说明"死黑阴影"确实把画面写平了。**
对比旧 skill 长词 6.92 —— 我那三轮不只是暗，还**变平了**。

这正是复核警告的：**「为降暗部把画面写平，熵会掉」**。我确实掉进去了。

## 为什么会这样

我三轮的做法是**不断往提示词里加「发光」描述**：
- 第一轮加「光充满画面」
- 第二轮加「环境密度三层都要发亮」
- 第三轮加「整个空间由光构成」

结果：**每处都被照亮，画面失去明暗对比**，熵下降。

而旧 skill 的长词是**散文式描述**，光影是有层次的（该暗的地方暗），死黑高但层次在。

## 正确的方向

不是「让画面更亮」，是「让**死黑**降下来但**层次**保住」：

| 错误做法 | 正确做法 |
|---|---|
| 到处加「发光」，全画面均匀照亮 | 只给**该亮的表面**光源，该暗的保留暗但有细节 |
| 死黑 24%→17%（好），熵 6.84→6.51（坏） | 死黑降到 <5%，熵保住 6.8+ |
| 目标：均值达标 | 目标：**每格都达标**（旧 skill 有 6/9 格熵达标，我三轮只有 2/9） |

## 下一步

1. **回到旧 skill 的散文式写法**作为基线，不要全盘推翻
2. 只在**死黑 >20% 的格**（旧 skill 的第 1、5、6 格）做针对性修正
3. 每次改动后用 `qc_image.py` 检查**熵不能掉**
