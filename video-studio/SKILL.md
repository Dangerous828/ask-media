# video-studio

## 自看硬规则

任何产物出来都要自己看过才往下走：**视频一秒一帧，闸门过了不算看过。** 完整细则与"什么叫不算看过"见 [开发纪律](../ask-media/references/discipline.md)，本条不复述。

## 短剧项目协作（命中即读，保留本职）

本技能继续做工程检查、适配判断和问题定位，并提供测量（四件套、介质信号）。**短剧生成图片与视频是否可用，由 [short-drama-review](../drama-skills/skills/short-drama-review/SKILL.md) 的「媒体验收」裁决**：它用 `../drama-skills/skills/short-drama-review/scripts/look_check.py` 对照《视觉设定.md》「画风基准」先审画风，再审剧情；本技能的测量作为证据附上，不单独放行。涉及连续段时读 [short-drama-storyboard](../drama-skills/skills/short-drama-storyboard/SKILL.md) 的事件边界。规则见 [协作契约](../SHORT-DRAMA-ROUTING.md)。已读上下文复用；只有跨阶段、状态或初始化才读取short-drama主路由。

## 三、出图实验纪律（仅限 Qwen 静帧生图链路）

> **适用范围**：本节各条规则的证据全部来自本地 Qwen Image 2.1 静帧出图的小样本实验（角色C EP01 / 赛博题材）。
> 它们约束**生图提示词的槽位写法**，不约束剧本、分镜或 H3 视频提示词：不得据此否决夜景、黄昏戏，
> 不得为满足这些规则改写剧本时间设定。换画风或换后端时视为未验证，需重测。
> **现行口径**：风格词写在散文首行有效（剥离成前置锚词反而失效，证据见 `结论-提示词体系适用性.md` §二）；
> 「实体+发光色」词（金色粒子/蓝色光带/暖光/霓虹）允许——描述某个在发光的实体不是全局调色。

### R1b profile 的【规避】不进词流，只进拦截表

**规则：profile 的【规避】不进词流，只进拦截表；cfg=1 档无负向槽。**
负向生效阈值与丢弃层次只在此处定义：[still-api-params.md](../h3-queue/references/still-api-params.md)「术语与分层」节，本节不复述。
事故经过（无条件追加【规避】把被排除概念注入正向）与后续修复见 `MEASURED-第二轮.md` 致命 1。
H3 的 negative 槽与正文否定须分开判断，不从图像实验外推；见 [H3 剧本适配参考](references/craft/h3-script-fit.md) §5。

### R1c 五槽标签不进词流

`【景别机位】`/`【主体】`/`【画幅】` 这些标签是给写词人看的清单，**拼装时必须剥掉**。
`【画幅】` 整行丢弃——那是渲染参数，不是提示词。

官方 264 字符散文效果好不是因为"散文"，是因为**零噪声 token**。

### R2 「可见光源」槽不许写暗

`【可见光源】` 必须指出**哪个实体在发光、照亮了什么**。
禁止 `暗` / `暗处` / `夜色` / `void` / `darkness` / `black` / `深蓝` 这类"没有东西"的描述。

实测：同一格只把后景从「夜色」改成「灯塔塔顶有光」，暗部从 78.0% 降到 67.3%（−10.7 pt）。

### R3 必须命名 1–3 个「会过曝的光源实体」+ 受光面

**不要靠「整个世界在发光」这类句式去救一个本身不发光的被摄体。** 对一个普通室内/人物场景，
写环境光弥散会让模型全局抬底噪，像素落进 16–50 带 —— 产出「均匀暗灰雾」而不是「被照亮的表面」。
但这不是句式禁令：当被摄体本身就是发光群体（整座灯塔城、成片灯火），这句是准确的描述，不是雾的成因。
**判据在被摄体，不在句式**——详见本节末尾「权威裁决」与 `结论-提示词体系适用性.md` §五。

#### 频带证据

本地 16–50 带 46–71%、官方仅 4.9%；高光带官方 10.3%、本地全部 ≤3.4%。
`r3b` 是铁证：死黑已达标但暗灰雾最严重，不是「面光源失败」而是写法制造了雾。
逐图数值与两次测量口径的辨析见 `MEASURED-第三轮.md` §一 与 `MEASURED-Opus六信号复验.md` §一。

#### 正确的写法：两个都要

| 要什么 | 提供什么 | 对应频带 |
|---|---|---|
| **高亮光源实体**（会过曝的那种） | 火、灯丝、太阳、屏幕、粒子、霓虹管 | **>200 高光** |
| **它们照亮的具体受光面** | 墙面、桌面、地面、脸的一侧 | **50–200 中间调** |

**只写受光面 → 得到 r3b 那种无高光的雾。只写发光体 → 高光有了但中间调空。**

官方提示词给的是**离散高亮物体**：
`golden particles` / `rivers of luminescent code` / `neon blue data streams`
—— 它们占 >200 带（官方 10.3%）。**有高光才有层次。**

#### 保留的规则

- **静帧槽位里少写抽象时间词**（夜/夜晚/夜色/深夜/黄昏）：Qwen 静帧单变量实验 −10.7pt。夜戏照拍，把“夜”写成具体发光实体（路灯、窗光、月光照在哪）；不适用 H3 视频正文。
- **不设「每个场景必须有『整个世界在发光』定义句」这条硬规则**：按被摄体裁决，见下方权威裁决表。

**权威裁决（2026-11-23；本条是「整个世界在发光」与五槽拼装的唯一口径）**：

| 说法 | 裁决 |
|---|---|
| 「整个世界在发光」该不该删 | **按被摄体决定，不按句式一刀切**：普通室内/人物场景删（防 16–50 雾）；灯塔城/灯海这类本身发光的被摄体保留（tB 用它拿到当时全集最好成绩）。`MEASURED-第五轮.md` §4.1 判定「该删『整个世界在发光』的建议是错的」，该结论仅对 tB 这类发光群体被摄体成立；`MEASURED-第三轮.md` §七记录的是普通场景「不再强制」此句——两者分别指这两类场景，不矛盾。 |
| 五槽拼装 vs 散文 | 两者各有适用范围，不是谁取代谁：真实项目散文首行写法 21 张指标接近官方（`结论-提示词体系适用性.md` §一）；修掉两个 bug 后的五槽拼装产物 nx1_clean 四项全过（`MEASURED-第五轮.md` §3.1）。**选哪种按实测产物判定，不由本 skill 规定。** |
| 本 skill 定位 | 工具组 + 排障规律，不规定提示词正文（见本文件开头定位与 `结论-提示词体系适用性.md` §七）。 |

### R3b 环境密度：给「画面四边」分配光源实体，但不许写成弥散

**规则**：受光面给中间调，发光体给高光，两个都要；四边各分配一个会过曝的**实体**，不写「均匀打亮」。
例句：`前景是桌面上一支点亮的蜡烛（火苗过曝），桌面被它照出一圈暖光；中景朝向火的半张脸亮、另半张沉入阴影；后景书架上方一盏射灯打亮顶层书脊。`
点光源/弥散光的失败经过与 r3b 逐图数据见 `MEASURED-第一轮.md` R3b 验证结果一节。

### R3c 验收指标是四件套

**不要用 `gray<50` 当主指标。** 那个量纲在惩罚正常中间调——
Toonflow 原文要的是「亮暗过渡柔和、暗部不死黑」，对应的是**死黑**。

| 指标 | 定义 | 目标 | 作用 |
|---|---|---|---|
| **死黑** | `gray < 16` | ≤ 5% | 底部别塌 |
| **暗灰带** | `16 ≤ gray < 50` | **≤ 15%** | **防「暗灰雾」← 新增，最关键** |
| **中间调** | `50 ≤ gray < 200` | ≥ 60% | 主体有层次 |
| **高光** | `gray ≥ 200` | **5–12%** | **「被照亮」的度量 ← 新增** |
| 画幅 | 边长 32 倍数 | — | |

**熵不作门控**：它与明暗分布测的是同一根轴，不是独立护栏；熵低不是因为"平"，是因为"暗"。
相关系数与 `sk_grid09` 例证见 `MEASURED-第三轮.md` §二。

```bash
# 档位必须显式给（QC 无默认档：把 3D 卡通片错套 `virtual-void` 档（高光 5–12%）判 1/9，正确档 3/9、目检 9/9；见 MEASURED-Opus六信号复验.md §4.1/§11）
python3 scripts/qc_image.py <图片或目录> --qc-profile cartoon3d

# 介质信号（四带查不出的那一半：粒子密度/体积光/噪点），相对基准、默认只告警
python3 scripts/qc_signals.py <图片或目录> --baseline <项目>/qc/baselines/cartoon3d/
```

**⚠️ 四带只测亮度分布，对「介质」完全盲。** 实测 example-project S09 四带两档全过、目检可用，
小亮块数只有官方参照的 1/5 —— 粒子/代码流/体积光这些**四带查不出来**，要用 `qc_signals.py`。
但介质信号**只能告警不能门控**：好/差两组区间重叠（官方 min=175 vs 差组 max=318），
绝对线会误杀，详见 `MEASURED-Opus六信号复验.md`。

**⚠️⚠️ 四带也不看「内容是否符合提示词」。** 词长梯度实测（264 档四带 PASS 但内容没画出来，800 档四带 FAIL 但内容正确）
说明用四带选词长会把正确的那一档判成失败；逐档数字见 `MEASURED-Opus六信号复验.md` §十七。
档名是标记、不是字符数：w264 实际 269 字符、w800 893、w1600 1783、w3200 2534（见 `MEASURED-Opus六信号复验.md` §17.1）。

**分工**：四带判「这张图像不像话」（同题材同构图横向比 + 灾难线）；
「词写进去了没有」要看**具体物件是否出现**（光柱、地平线、姿态、道具）。不要把四带当提示词好坏的判据。

参照：官方 Gemini 基准 = 死黑 0.0% / 中间调 84.8% / 熵 7.67。

**不要拿官方的 14.1% 当跨题材 KPI**——那是 Gemini 在「金色发光虚空」题材上的产物（14.1%＝作者留档的官方 9 格均值口径，量纲 gray<50；单格值与均值不得并列比较）。
第 8 格（塔顶俯瞰）曾到 33.5%，说明旧指标奖励的是大景别+亮天空，继续优化会收敛成「全片大全景」。

### R3d 9 格批次稳定性未解决

单格能到 21.4%，9 格批次仍大幅波动；在稳定性解决前本流程的暗部问题不算修好。
逐轮均值与批次内极差见 `MEASURED-第一轮.md`「三轮暗部占比」与「关键对照实验」两节。

### R3e 场景骨架：出图和出视频共用，但语言不同

`profiles/<画风>.md` 第七节的 20 条场景骨架（景别 + 空间特征 + 具体陈设 + 光源实体）
**不是只给生图用的**。

| 用途 | 怎么用 | 语言 |
|---|---|---|
| **出图**（Qwen 生图提示词） | 直接填进 `【环境密度】` 槽，中文 | 中文 |
| **出视频**（H3 提示词） | 翻译成英文，嵌进 `detailed_description` 的对应 `[Shot N]` 段 | **英文** |

官方 `base-en.txt` 对 `integrated_multimodal_description` 的要求是
「Describes visuals, actions, shots, speakers, dialogue, singing, and diegetic audio
along the timeline」——**画面/场景描写本来就是它的一部分**。

**但 H3 必须英文。** 中文骨架进 H3 前必须翻译，且要遵守：
- `[Shot 1]` 无时间戳，后续 `[Shot N] At MM:SS.mmm`
- 运镜写成自然英文（type / amplitude / speed）
- 对白用 `<d>[Language] ...</d>`，人声源给 `(S1)(S2)`

### R4 H3 提示词必须过官方结构

字段名、段序、时序记号一字不许改：

- 三段式（base）：`integrated_multimodal_description` → `overall_soundscape` → `non_diegetic_music`
- 六段式（Ref2VA）：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`
- 时序：`[Shot 1]` 无时间戳；后续 `[Shot N] At MM:SS.mmm`，严格递增
- 参考标签：`<Picture N>` / `<Subject N>` / `<Video N>` / `<Audio N>`
- 四档保留标记：`fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference`

#### R4a FL2VA / L2VA 默认单段，分段等于点名切镜（实测）

官方 `references/official/base-en.txt:62` 要求 FL2VA 默认单段、仅显式指定才多段；官方 8 秒范例两张帧都标 `(from Shot 1)`。
**本项目实测**：三段式写法在帧 66 诱发真硬切；物理实测与 A/B 对照见 `MEASURED-闸门复验.md` §二「2.0 事故现场」。
**规则**：首尾帧同属一段，运镜在段内连续写；只有真要硬切才分段，按官方 §4.2 用 `the camera cuts to`。
同一批里另外 5 段三段式未触发 ⇒ 概率性诱发，「这次没炸」不能当通过。

仍保留人工复核：P0-4 / G28 只查「段数 vs 硬切词」，查不出「本该有切点却写成了连续」，那仍要人看片。
两条闸门都改为**结构判据**（非 Ref2VA + 同时加载 Picture 1/2 = FL2VA），措辞判据会被等价改写绕过；修闸门经过见 `MEASURED-闸门复验.md` §二「缺口 3」与「缺口 4」。
白名单收紧（硬切须在剧本事件清单有对应 `transition`）仍是待实现提案，见 `MEASURED-Opus六信号复验.md` §五。

### R5 送 GPU 前双目检

任何出图/出片提交前，必须**逐张打开参考图本体**看：
画风与 profile 一致、是本镜第 0 秒起始态、图内文字无乱码、身份与角色锚点一致。

### R6 排障两次不成就换方案

同一处连崩两次（同一只手、同一个人数不对），说明问题更可能在提示词或参考图，不在随机性。
**优先**改提示词 / 换参考图 / 改景别，三选一；重抽种子只作对照，不作为主要手段。

### R7 改动传播

上游（剧本/分镜/资产/提示词）变更后，下游（视频提示词、成片）按变更性质处理：

- **实质性变更**（事实、台词、参考图、时长、机位）→ 受影响的下游视为过期，必须重写重验；
- **文字/格式修正**（措辞、标点、排版）→ 只复核受影响处，不做全链重写。

判断不了算哪类时按实质性处理。

## 四、生产：怎么真出图 / 真出片

> **唯一提交入口是 h3q 队列（`h3qc.py` / 8200）。** 不要手调 `h3q_img.py` /
> `h3_quick.py` / `h3_render*.py` —— 它们直连 ComfyUI 8199，绕过 admission gate：
> 抢卡、不与队列互斥、看不到排队位次，也拿不到队列那道 VRAM 保护。
> `h3q_img.py` 自己的 docstring 就写着「never by hand; direct only to debug one still」。
>
> SSH 通道按 `h3-queue` §2 选择（同网段优先 `<渲染主机SSH别名-直连>`，远程走 `<渲染主机SSH别名-中转>` 等），以当时实测可连为准。
> 队列端口 8200 **只在 Windows 本机监听**，Mac 上查不到。

### 4.1 出图

```bash
# 在 Windows 上跑（h3qc 与队列同机）
# h3qc.py 为渲染机侧私有脚本，须另行部署（见 h3-queue §8）
# 尺寸与种子为示例，非缺省
python h3qc.py submit --kind image \
  --prompt-file p.txt --out <渲染机产物目录>\o.png \
  --size 1344x768 --seed 42 --label my-shot \
  --idem-key my-shot-s42 --wait
```

- 出图默认档按实读方法查 [still-api-params.md](../h3-queue/references/still-api-params.md) 与 [h3-queue 出图章节](../h3-queue/SKILL.md)，此处不复述数字；为什么如此见 [档位实测快照](../h3-queue/references/still-standard-tier-20261105.md)（2026-11-05）
- **负向生效阈值与丢弃层次只查 [still-api-params.md](../h3-queue/references/still-api-params.md)「术语与分层」节**；排除项写进正文正向、不依赖 negative。`--fast` 仍被接受但被忽略。档位配置与退役档记录详见 `h3-queue` §2.7 与上述档位实测文档
- **身份板、资产板**参考图按项目侧预处理约定（非通道限制，见 `scripts/ref_guard.py` 的参考图检查说明与 `MEASURED-Opus六信号复验.md` 第 3 项）压到长边 768 + JPEG q80；**首帧、起始状态与构图参考**按目标画布无损 PNG 上传，不要压（short-drama adapter 已自动区分）
- **要挂参考图就走 `h3qg.py`**（= h3qc + 提交前闸门）：`python h3qg.py submit ...`
- **`--idem-key` 必须含 seed / 输出名**：同 prompt 换 seed 是不同活，
  只按 label 去重会让后续提交被静默吞掉（实测：12 张提交只渲出 4 张）

### 4.2 出视频

```bash
python h3qc.py submit --kind video \
  --prompt-file s1.txt --slug s1 --version v1 \
  --width 768 --height 1344 --seconds 10 \
  [--first-frame f.png | --refs a.png,b.png] --wait
# 示意为已有单帧/全参考模式；首尾配对、互斥输入和tier查h3-queue，短剧走produce adapter
```

当前输入、`draft/final` 与耗时依据统一查 [h3-queue](../h3-queue/SKILL.md#输入能力与续接职责)；本工具箱不缓存这些口径，pdd 采样语义以该处为准。

**查队列**：`h3qc.py queue` / `health` / `ls` / `stats`（Windows 本机 127.0.0.1:8200）

### 4.3 帧数换算

H3 帧网格是 `17k + 5`（24 fps）：

| 秒 | 帧数 | 17k+5 |
|---|---|---|
| 2.5 | 60 | 56（短 4 帧）或 73（长 13 帧） |
| 3 | 72 | **73**（误差 +1，正好） |
| 15 | 360 | 362 |

**帧网格只约束本次任务的合法帧数，不决定镜头长度。** 先按事件、表演和生成分组确定任务时长，再选合法帧数并记录实际秒数；73 帧只是约 3.04 秒的换算示例。一个任务可含连续表演或有明确切点的多个镜头，成片入出点按实际素材选择。

## 五、排障索引（按症状查）

| 症状 | 大概率原因 | 处置 |
|---|---|---|
| 画面里有「一块脸」贴在角落 | 参考图是拼接板，被当构图模板 | 参考图裁成单人单景；或加长提示词 |
| 人物消失只剩背景/道具 | 参考图是竖构图单人图 | 换横向多视图；或去掉参考图 |
| 画面整体偏暗 | `【可见光源】` 写了暗色/夜色 | 改写成「哪个实体在发光」 |
| 画面空、没氛围 | `【环境密度】` 三层没写满 | 每层补一件具体物 |
| 风格改不动 | 风格词写太弱 | 换 profile，把介质名词写实（`cel-outlined` / `volumetric 3D`）；Qwen 静帧里不追加 `no color` 类【规避】清单，见 R1b 拼词实测。H3 优先正向描述，但正文否定的效果须按 [适配参考](references/craft/h3-script-fit.md) §5 区分，不从图像实验直接外推 |
| 亮度异常高 | `not A but B` 句式 | 拆掉，直接写 B |
| 构图跑偏 | 提示词太短（<300 字） | 补齐五槽 |
| 出图很慢 / OOM | 显存被占 | `/interrupt` 后重试；或降尺寸 |
| 远景人物脸糊 | 景别越远，文字越锁不住身份 | 身份交给参考图，别加堆词。**［社区二手，本机未测，且社区本身有争议：1376×768/24 步救不了 vs 1.0MP+Turbo 是甜点位（该 Turbo 指已退役档，见 [still-standard-tier-20261105.md](../h3-queue/references/still-standard-tier-20261105.md) §三）。不作绝对阈值］** |
| 屏幕小字 / logo 逐帧漂 | 帧级一致性要求超出模型稳态 | **［社区二手］** 但另一条社区案例说大字卡反而稳（片假名标题渲染正确）。两条判据分开，不要笼统说「文字能力」。**本机未测** |
| 剧烈动作 + 复杂运镜复刻源片时溶解崩坏 | 运动幅度与运镜复杂度同时拉满 | 换舞蹈类 / 无运镜片源，或拆成段。**［社区二手，本机未测］** |
| 想用超分救画质 | latent upscaler 毁细节并破坏时序；EasyCache 降质 | **［本机一手实测 2026-11-15 已推翻旧二手结论］** `h3_upscale_video(width=1536, aspect="16:9")` 纯 latent 放大相对 lanczos 插值基线 lap_var **+34.17%**、只加细节不重绘，是有效成品超分；前提是装配层不缩回 1024（缩回再放大 −20.73%），且**只加细节救不了台词/口型/结构问题**——结构坏了仍按 R6 改输入。像素超分 SeedVR2 才是真毁细节（过锐化 FAIL）。详见 `../h3-queue/SKILL.md` §2.15 |
| 风格 LoRA 抢走参考图身份 | 风格 LoRA 与参考图竞争注意力 | adherence 优先时强度压到 ~0.5。**［官方原文，本地存档未随公开版发布，出处：MiniMax-AI/MiniMax-H3 官方文档 minimax-h3-native 第 13 条］** |
| **段子内部黑框自己消失** | **同一次空间穿越被相邻两镜重复承担** | **跑 `segment_guard.py` 确认；修法是从结构上删掉重复的那一镜** |

### 排障：黑框在段内自溶

提示词层查不出来，必须用帧级数据：

```bash
python3 scripts/segment_guard.py <成片段目录>       # 退出码 1 = 检出自溶
```

**判据**：外环 6% 带死黑曲线递减且只有环带在变；递增与整帧同步变暗都不拦。
它不能区分「非法自溶」与「合法地把黑框拉出画面」（几何同形），真要这么拍用 `--allow-decay` 放行并写明理由。
三轮判据订正、反例与退出码回归见 `MEASURED-Opus六信号复验.md` §十五。
