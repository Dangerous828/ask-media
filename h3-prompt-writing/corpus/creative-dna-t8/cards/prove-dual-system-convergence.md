Create a new execution from the reusable mechanism, not a surface reskin of any reference video.

## Workflow

1. Read [references/summary.md](references/summary.md) for fit, input slots, and the concise starting example.
2. Read [references/template.md](references/template.md) completely before drafting.
3. Preserve the user's subject and objective, then fill every missing scene, trigger, event-chain, camera, sound, and payoff slot.
4. Treat these anchors as mandatory:

- 两个系统先独立成立
- 材质或运动规则明确不同

- 第三状态同时保留双方证据

5. Change source-specific people, setting, props, palette, dialogue, shot boundaries, sound family, and payoff surfaces together.
6. Compile MiniMax H3 and Seedance 2.0 independently; do not leak one model's field syntax into the other.
7. Silently verify anchor coverage, continuity, timing, physical causality, and anti-copy distance before returning the final prompts.

## MiniMax H3

- Use the current official H3 task grammar and language profile.
- Separate integrated visual action, overall soundscape, and non-diegetic music or explicit silence.
- Use timestamps only to make event order executable; keep shots consecutive and duration-safe.

## Seedance 2.0

- Define stable subjects once and preserve event order, camera motivation, sound intent, and overall duration.
- Use a simple paragraph for simple concepts or an ordered multi-shot structure for complex concepts.
- State overall duration once; do not copy H3 field labels or per-shot timecode grammar.

## Output

Return one concept sentence, the filled slots, an anchor-coverage check, one MiniMax H3 prompt, one Seedance 2.0 prompt, and a short anti-copy validation note.

## Non-Negotiable

- A subject-only request is underspecified. Preserve that subject and complete the mechanism instead of returning a generic portrait or showcase.
- Do not omit, reorder, or weaken a required anchor.
- Do not reuse source people, brands, dialogue, exact storyboard, signature props, exact timings, or recognizable effect surfaces.

# 双系统碰撞｜同时证明两种规则 — 摘要

## 用途

先分别建立两个对立系统的独立规则，再让它们一次汇聚形成持久第三状态。

## 推荐输入格式

`系统A材质/规则 + 系统B材质/规则 + 分别建立 + 一次汇聚碰撞 + 双方共同形成的第三状态`

## 可直接改写的简短示例

> 实验台左侧是会结晶的液态玻璃，右侧是会脉动的磁性沙；分别证明各自规则后，它们只汇聚一次，形成同时透明且持续脉动的悬浮晶格。

## 必须保留的结构锚点

- 两个系统先独立成立
- 材质或运动规则明确不同
- 只发生一次关键汇聚
- 第三状态同时保留双方证据

## 使用方法

1. 保留用户给出的主体与目标。
2. 按推荐输入格式补齐场景、事件链、镜头职责和结果。
3. 同时改变表面名词、风格、光影、声效与物理实现，不做来源视频换名词复刻。
4. 分别编译 MiniMax H3 与 Seedance 2.0，并逐项核对结构锚点。

# 双系统碰撞｜同时证明两种规则 Template

## Mechanism

Establish two systems separately with distinct color, material physics, motion cadence and starting zones. Alternate equal proof beats while their spatial distance decreases, align them on one readable axis, permit exactly one convergence event, and end on a third shared result that neither system produced alone.

## Invariants

### inv-01

- Rule: Give each system an independent establishing proof.
- Purpose: Prevents color alone from carrying identity.
- Failure if removed: Immediate collision makes the systems interchangeable.

### inv-02

- Rule: Keep material physics and cadence distinct before convergence.
- Purpose: Makes alternation informative.
- Failure if removed: Shared motion grammar erases opposition.

### inv-03

- Rule: Reduce one visible spatial gap across matched views.
- Purpose: Creates measurable progress.
- Failure if removed: Random angles obscure whether convergence is approaching.

### inv-04

- Rule: Allow only one terminal meeting event.
- Purpose: Protects anticipation and causal clarity.
- Failure if removed: Repeated clashes dilute the payoff.

### inv-05

- Rule: Leave a persistent third-state consequence.
- Purpose: Proves both inputs affected the result.
- Failure if removed: A flash followed by reset provides no outcome evidence.


## Variable Slots

| Slot | Constraint |
|---|---|
| lead_subject | An original subject or system whose identity remains stable. |
| setting | A new setting with fixed spatial anchors. |
| escalation_variable | One visible variable that changes in countable causal stages. |
| performance_rule | A restrained behavior rule that makes the mechanism legible. |
| camera_grammar | A coherent information order that does not copy source shot boundaries. |
| payoff | One clean physical or graphic consequence. |
| sound_family | A new hierarchy of diegetic cues supporting state changes. |

## Required Human-Facing Anchors

- 两个系统先独立成立
- 材质或运动规则明确不同
- 只发生一次关键汇聚
- 第三状态同时保留双方证据

## Anti-Copy Boundary

- two female elemental warriors
- fire magic versus ice magic
- ruined stone arena at sunset
- weapons, petals and the source mid-air collision pose

## Transfer Tests

   - Preserved: inv-01, inv-02, inv-03, inv-04, inv-05
   - Changed: lead_subject, setting, escalation_variable, performance_rule, camera_grammar, payoff, sound_family
2. A weather visualization establishes a dry dust front and a humid membrane separately, converging once into a rotating condensation wall.
   - Preserved: inv-01, inv-02, inv-03, inv-04, inv-05
   - Changed: lead_subject, setting, escalation_variable, performance_rule, camera_grammar, payoff, sound_family

    约束：[连续性、物理逻辑、反复制与结尾状态]

Adapt shot count to the user's concept. Preserve the causal mechanism, not a fixed storyboard.
