# 触控换媒｜接触触发、状态推进与成品回归

Create a new execution from the reusable mechanism, not a surface reskin of any reference video.

## Workflow

1. Preserve the user's subject and objective, then fill every missing scene, trigger, event-chain, camera, sound, and payoff slot.
2. Treat these anchors as mandatory:

- Establish one bounded workspace, one primary object and one visible contact tool in reality.
- Toggle medium only at visible tool contact and preserve object registration across the boundary.
- Advance one irreversible build or preparation state after every toggle without resetting earlier progress.
- Return to photoreal reality with the completed object and original anchors visible.

3. Change source-specific people, setting, props, palette, dialogue, shot boundaries, sound family, and payoff surfaces together.
4. Compile MiniMax H3 and Seedance 2.0 independently; do not leak one model's field syntax into the other.
5. Silently verify anchor coverage, continuity, timing, physical causality, and anti-copy distance before returning the final prompts.

## MiniMax H3

- Use the current official H3 task grammar and language profile.
- Separate integrated visual action, overall soundscape, and non-diegetic music or explicit silence.
- Use timestamps only to make event order executable; keep shots consecutive and duration-safe.

## Seedance 2.0

- Define stable subjects once and preserve event order, camera motivation, sound intent, and overall duration.
- Use a simple paragraph for simple concepts or an ordered multi-shot structure for complex concepts.
- State overall duration once; do not copy H3 field labels or per-shot timecode grammar.

## Output

Return one concept sentence, the filled slots, an anchor-coverage check, one MiniMax H3 prompt, one Seedance 2.0 prompt, and a short anti-copy validation note.

## Non-Negotiable

- A subject-only request is underspecified. Preserve that subject and complete the mechanism instead of returning a generic portrait or showcase.
- Do not omit, reorder, or weaken a required anchor.
- Do not reuse source people, brands, dialogue, exact storyboard, signature props, exact timings, or recognizable effect surfaces.

# 触控换媒｜接触触发、状态推进与成品回归 Template

## Mechanism

Lock one bounded workspace, one primary object and one visible contact tool. Every time the tool touches the object or its immediate support, toggle the registered region between photoreal action and a materially distinct illustrated medium. Preserve object orientation, support geometry and surrounding anchors across each toggle, while advancing one irreversible construction or preparation state after every transition. End by returning to photoreal reality with the completed object and all accumulated evidence visible. The reusable mechanism is attributable contact, registered medium toggle, irreversible progress, anchor continuity and real finished payoff—not the source hand, blue stylus, bread, egg, pan, French toast, berries, syrup, black-yellow drawing style, exact camera, timing, creator identity or model labels.

## Invariants

### inv-01

- Rule: Establish one bounded workspace, one primary object and one visible contact tool in reality.
- Purpose: Defines the registered region and causal trigger.
- Failure if removed: An unseen trigger makes the medium switch arbitrary.

### inv-02

- Rule: Toggle medium only at visible tool contact and preserve object registration across the boundary.
- Purpose: Makes every transformation attributable and comparable.
- Failure if removed: Cuts between unrelated layouts lose contact causality.

### inv-03

- Rule: Alternate between photoreal and one clearly different illustrated medium at least twice.
- Purpose: Proves a repeatable two-way system rather than a single effect.
- Failure if removed: One-way conversion does not establish a toggle grammar.

### inv-04

- Rule: Advance one irreversible build or preparation state after every toggle without resetting earlier progress.
- Purpose: Turns medium change into narrative progress.
- Failure if removed: Cosmetic switching alone is a filter demo.

### inv-05

- Rule: Return to photoreal reality with the completed object and original anchors visible.
- Purpose: Closes both medium and progress arcs.
- Failure if removed: Ending in illustration leaves real completion unproven.


## Variable Slots

| Slot | Constraint |
|---|---|
| lead_subject | An original stable subject or pair with a readable role. |
| setting | A new setting with fixed spatial anchors and no source-specific surface. |
| escalation_variable | One causal variable that changes through visible stages. |
| performance_rule | A restrained acting or motion rule that keeps the mechanism legible. |
| camera_grammar | An information order that proves each state without copying source shot boundaries. |
| payoff | A clean final physical, informational or social consequence. |
| sound_family | An original hierarchy of diegetic cues; no unsupported source-audio claim. |

## Required Human-Facing Anchors

- Establish one bounded workspace, one primary object and one visible contact tool in reality.
- Toggle medium only at visible tool contact and preserve object registration across the boundary.
- Advance one irreversible build or preparation state after every toggle without resetting earlier progress.
- Return to photoreal reality with the completed object and original anchors visible.

## Anti-Copy Boundary

- the source hand, light-blue stylus and exact contact positions
- the source kitchen, plate, pan, bread, egg, French toast, berries, sugar and syrup
- the source black-and-yellow illustration style, line density and drawing marks
- the source camera positions, object orientation, transition timing and plating sequence
- the source creator identity, GPT Image 2 and Seedance 2.0 labels, platform overlay, watermark and branding

   - Changed: lead_subject, setting, escalation_variable, performance_rule, camera_grammar, payoff, sound_family

   - Preserved: inv-01, inv-02, inv-03, inv-04, inv-05
   - Changed: lead_subject, setting, escalation_variable, performance_rule, camera_grammar, payoff, sound_family
