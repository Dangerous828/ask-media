# 功能问答闭环｜人物疑问由设备状态完成证明

Create a new execution from the reusable mechanism, not a surface reskin of any reference video.

## Workflow

1. Read [references/summary.md](references/summary.md) for fit, input slots, and the concise starting example.
2. Read [references/template.md](references/template.md) completely before drafting.
3. Preserve the user's subject and objective, then fill every missing scene, trigger, event-chain, camera, sound, and payoff slot.
4. Treat these anchors as mandatory:

- Open with the questioner and the relevant operating device visible in one spatial relationship.
- Use a second adult and one separate status carrier as an independent response channel.
- Return to the opening device space after the response.
- Change one device state and one human response before the final hold.

5. Change source-specific people, setting, props, palette, dialogue, shot boundaries, sound family, and payoff surfaces together.
6. Compile MiniMax H3 and Seedance 2.0 independently; do not leak one model's field syntax into the other.
7. Silently verify anchor coverage, continuity, timing, physical causality, and anti-copy distance before returning the final prompts.

## MiniMax H3

- Use the current official H3 task grammar and language profile.
- Separate integrated visual action, overall soundscape, and non-diegetic music or explicit silence.
- Use timestamps only to make event order executable; keep shots consecutive and duration-safe.

## Seedance 2.0

- Define stable subjects once and preserve event order, camera motivation, sound intent, and overall duration.
- Use a simple paragraph for simple concepts or an ordered multi-shot structure for complex concepts.
- State overall duration once; do not copy H3 field labels or per-shot timecode grammar.

## Output

Return one concept sentence, the filled slots, an anchor-coverage check, one MiniMax H3 prompt, one Seedance 2.0 prompt, and a short anti-copy validation note.

## Non-Negotiable

- A subject-only request is underspecified. Preserve that subject and complete the mechanism instead of returning a generic portrait or showcase.
- Do not omit, reorder, or weaken a required anchor.
- Do not reuse source people, brands, dialogue, exact storyboard, signature props, exact timings, or recognizable effect surfaces.

# 功能问答闭环｜人物疑问由设备状态完成证明 Template

## Mechanism

Place one original questioner and one visibly operating device in the same opening frame so the functional uncertainty has a physical anchor. Cut once to a second adult who checks a separate status carrier and gives a visible response; do not rely on unreadable UI or prescribed dialogue. Return to the opening device space and change one machine state plus the questioner's posture or expression, so device evidence and human interpretation close the loop together. The reusable mechanism is question, remote status check, machine-state proof and return—not the source people, faces, clothes, home, computer hardware, phone, product, logo, dialogue, exact gestures, composition, creator identity or timing.

## Invariants

### inv-01

- Rule: Open with the questioner and the relevant operating device visible in one spatial relationship.
- Purpose: Gives the abstract function a concrete proof anchor before any answer.
- Failure if removed: A face-only question leaves later device evidence unbound.

### inv-02

- Rule: Use a second adult and one separate status carrier as an independent response channel.
- Purpose: Turns the answer into an observable relay rather than a title card.
- Failure if removed: Keeping every claim with the first person collapses question and proof into assertion.

### inv-03

- Rule: Avoid depending on small interface text or exact spoken words.
- Purpose: Keeps the mechanism supported by visible state and performance evidence.
- Failure if removed: Unreadable UI or untranscribed dialogue cannot carry the causal claim.

### inv-04

- Rule: Return to the opening device space after the response.
- Purpose: Reconnects the remote interpretation to the original physical system.
- Failure if removed: Ending on the phone makes the machine's result ambiguous.

### inv-05

- Rule: Change one device state and one human response before the final hold.
- Purpose: Provides both functional and social confirmation.
- Failure if removed: A static machine or unchanged questioner does not resolve the setup.


## Variable Slots

| Slot | Constraint |
|---|---|
| lead_subject | An original stable subject or pair with a readable role. |
| setting | A new setting with fixed spatial anchors and no source-specific surface. |
| escalation_variable | One causal variable that changes through visible stages. |
| performance_rule | A restrained acting or motion rule that keeps the mechanism legible. |
| camera_grammar | An information order that proves each state without copying source shot boundaries. |
| payoff | A clean final physical, informational or social consequence. |
| sound_family | An original hierarchy of diegetic cues; no unsupported source-audio claim. |

## Required Human-Facing Anchors

- Open with the questioner and the relevant operating device visible in one spatial relationship.
- Use a second adult and one separate status carrier as an independent response channel.
- Return to the opening device space after the response.
- Change one device state and one human response before the final hold.

## Anti-Copy Boundary

- the source adults, faces, bodies, clothing, expressions and exact gestures
- the source domestic rooms, balcony door, desktop computer, monitor, phone, couch and furniture
- the source product, deAPI and Earn Module concepts, logos, interface state and copy
- the source dialogue implication, camera positions, edit timing, color grade and performance rhythm
- the source creator identity, MiniMax H3 claim, platform overlay, watermark and branding

## Transfer Tests

   - Changed: lead_subject, setting, escalation_variable, performance_rule, camera_grammar, payoff, sound_family
2. A ceramics studio owner watches a sealed kiln with a blue hold lamp. A technician in another room checks a physical heat token, signals once, and the return shot shows the kiln lamp turning green while the owner lowers a guarded posture.
   - Preserved: inv-01, inv-02, inv-03, inv-04, inv-05
   - Changed: lead_subject, setting, escalation_variable, performance_rule, camera_grammar, payoff, sound_family
