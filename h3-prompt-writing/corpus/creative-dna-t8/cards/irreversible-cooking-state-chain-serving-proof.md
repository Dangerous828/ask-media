2. Read [references/template.md](references/template.md) completely before drafting.
3. Preserve the user's subject and objective, then fill every missing scene, trigger, event-chain, camera, sound, and payoff slot.
4. Treat these anchors as mandatory:

- Lock one clearly adult original cook, one base material, tray, kitchen and hand anchors.
- Apply exactly one irreversible operation per beat.
- Return the same tray after heat with plausible color, volume and texture change.
- End with the same serving and one restrained taste by the same adult.

5. Change source-specific people, setting, props, palette, dialogue, shot boundaries, sound family, and payoff surfaces together.
6. Compile MiniMax H3 and Seedance 2.0 independently; do not leak one model's field syntax into the other.
7. Silently verify anchor coverage, continuity, timing, physical causality, and anti-copy distance before returning the final prompts.

## MiniMax H3

- Use the current official H3 task grammar and language profile.
- Separate integrated visual action, overall soundscape, and non-diegetic music or explicit silence.
- Use timestamps only to make event order executable; keep shots consecutive and duration-safe.

## Seedance 2.0

- Define stable subjects once and preserve event order, camera motivation, sound intent, and overall duration.
- Use a simple paragraph for simple concepts or an ordered multi-shot structure for complex concepts.
- State overall duration once; do not copy H3 field labels or per-shot timecode grammar.

## Output

Return one concept sentence, the filled slots, an anchor-coverage check, one MiniMax H3 prompt, one Seedance 2.0 prompt, and a short anti-copy validation note.

## Non-Negotiable

- A subject-only request is underspecified. Preserve that subject and complete the mechanism instead of returning a generic portrait or showcase.
- Do not omit, reorder, or weaken a required anchor.
- Do not reuse source people, brands, dialogue, exact storyboard, signature props, exact timings, or recognizable effect surfaces.

# 烘焙状态链变体｜面团、铺料、入炉、成品与分享连续证明 — 摘要

## 用途

同一明确成年人物、晨光厨房、面团与烤盘持续锁定，每镜只推动一次不可逆食品状态变化；面团形状、酱料覆盖、配料分布与烤盘位置逐步累积，出炉后同一成品被端上并品尝。作为既有不可逆烹饪状态链的烘焙证据，不新增下拉项。

## 推荐输入格式

`一名明确成年原创操作者、固定空间、主材料组、主要容器与手部或工具锚点先建立 + 至少五个不可逆状态且每镜只执行一次清楚操作 + 上一状态的残留、形状、颜色、蒸汽或容器连续成为下一步输入 + 不得回到已消失的早期状态并保持数量合理 + 同一成品由同一成年人完成一次克制使用或品尝证明`

# 烘焙状态链变体｜面团、铺料、入炉、成品与分享连续证明 Template

## Mechanism

This is an evidence variant of the existing irreversible cooking state chain. Lock one original clearly adult cook, one kitchen, one dough or base, one tray and visible hand or tool anchors. Move through at least five irreversible food states, one operation per beat, while preserving outline, topping distribution, residue and container continuity. Oven or heat transitions must return the same tray and a plausibly changed version of the same item. End with the same serving and one restrained taste by the same adult. Do not copy source woman, kitchen, pizza, ingredients, recipe, lighting, camera or timing.

## Invariants

### inv-01

- Rule: Lock one clearly adult original cook, one base material, tray, kitchen and hand anchors.
- Purpose: Creates identity and material continuity.
- Failure if removed: Changing tray or hands makes the item unverifiable.

### inv-02

- Rule: Apply exactly one irreversible operation per beat.
- Purpose: Keeps state progression readable.
- Failure if removed: Hidden multi-step jumps weaken causality.

### inv-03

- Rule: Preserve outline, residue and topping or component distribution between states.
- Purpose: Proves the same item continues.
- Failure if removed: Rearranged components imply a replacement.

### inv-04

- Rule: Return the same tray after heat with plausible color, volume and texture change.
- Purpose: Makes cooking transformation credible.
- Failure if removed: A different tray or impossible state breaks material proof.

### inv-05

- Rule: End with the same serving and one restrained taste by the same adult.
- Purpose: Closes process with human proof.
- Failure if removed: An unrelated plated beauty shot loses continuity.

| Slot | Constraint |
