## 问题是怎么被发现的（不是靠 lead 盯，也不是靠闸门）

- **独立验收成员没有写词/生产史**：`review001` / `review206b` / `review3506r2` / `review003v3` / `review789` / `reviewfinal004` 都只裁决点名范围，明确"不碰已通过镜"。
- **看片方式写进报告**：`look_video` 全长采样 ≤1 s，可疑区间收细逐帧，关键帧/身份板逐张打开；音轨用 `silencedetect` + 0.2 s/0.5 s RMS 补强。报告带时间码、严重度（BLOCKER / MAJOR）、Finding、边界与未验项（如背对镜头口型记 UNVERIFIED）。
- **闸门只管结构，不管画面**：`h3-video-gate` 0 error 仍可能画面 FAIL；`ref_gate` 在上传前挡住未准入参考，属于流程拦截，不是生成质量问题。
- **回报不符也会被抓**：`review206` 回报了无关脚本，lead 判"回报与任务不符"并重新委派——这是正常的质量控制，不是事故。
- **裁决方式是隔离变量**：按段隔离、按画面/声音层隔离；一次只换一个实质变量（换参考绑定、改路线、只补音轨）；同一路线失败两次就停，不靠多抽卡碰运气。

## 当前引入点（2026-11-18 修订）

上文是历史会话观察，不代表只允许在分镜首次查卡。当前链路按 [语料机制与剪辑准备](../../../drama-skills/skills/short-drama/references/mechanism-preparation.md) 执行：

1. **文档准备／④ 导演**：按需求检索，一次读完整候选卡；核 template 的 Invariants（规则、目的、缺失后果）、变量槽与改编边界，不只读摘要。导演决定适配、采纳或改编，明确因果基线、递进与终局、注意/表演归属、不中断证明段、相对节奏及声画与实现责任；不能由模板补槽改剧情。
2. **③ 资产回补／⑤ 场记**：按机制需求补资产状态定义；场记将导演决定落入原六账的状态规则、动作阶段、可见证明和成对接续条件，白模核空间与可见性。资产需求后发现则回所属阶段更新，不新增阶段或独立机制账。
3. **⑥ 分镜／⑦⑧ 词**：沿原文条款→导演→CARD/SHOT→read/证明时间窗继承。分镜定具体切点与保护段，词译为可见动作和声音，英文模型骨架不得直接复制；纯后期效果只准备所需素材。
4. **⑨ 生产／⑩ 独立验收**：按现行授权生产，逐条实看。reviewer 对同一清单给真实时间码与证据；计划覆盖、结构闸门、文件存在不能代替 PASS。未验内容说明边界。
5. **⑪ 剪辑**：按真实可用带兑现保护段与声画交接，先核执行器支持，不能把效果目录当实现承诺。short-drama-edit 当前 render 不自动执行转场/自由混音；外部处理按既有边界记录并验收，不建平行工程。

必要条件未定先回 owner，相关镜头不宣称就绪；机制条件不自动成为剧本 N-ID。返工换机制时先改上游并同步受影响下游，不重做无关已通过镜头。规则是人工继承与审查约定，不宣称现有检查器已理解新增散文字段。

## 不要做

- 不要把 FAIL 叫"事故"或"翻车"；它是阶段链的正常输出。
- 不要 lead 自己看片兼裁决；写词/生产/验收三者分离。
- 不要拿闸门 exit 0、文件存在、生产方自述当验收结论。
- 不要绕过 `ref_gate`；被拦就走准入，再用同一 idem_key 重投。
- 不要一次改三个变量，也不要连抽两次同路线；隔离段与层，一次一个实质改动。
- 不要把卡的英文原文或案例来源素材复制进 H3 正文/成片。
