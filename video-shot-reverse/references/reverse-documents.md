# 逆推准备文档体系

> 逆推一条视频不是产出一张分镜表，而是为这条视频重建**一套准备文档**。
> 每份文档有稳定 ID、落盘路径、书写思路、贯穿轴与下游读法；结构向
> [六文档契约](../../drama-skills/skills/short-drama/references/document-contract.md) 看齐，
> 让逆推事实能被下游 owner 按同样的结构继承。逐镜字段与 QC 见
> [反推格式](reverse-format.md)。

## 为什么是一套

成熟的写法都以交付物定义流程：先写清最终产出有哪些文档、每份字段先定好，中间步骤都为交付它们；
所有中间成果落盘，下游读文件而不是靠记忆；主体与场景设定跨集累积。
逆推同样如此——从画面还原出的剧本、场记、导演意图与分镜，只有落成同一套结构，
才不会在下一轮被重新理解一遍。

## 九份文档

| ID | 文档 | 落盘路径（复刻项目） | 书写思路 | 贯穿轴 | 下游读法 |
|---|---|---|---|---|---|
| `RR-OVERVIEW` | 视频概览 | `项目开发/原片还原/RR-OVERVIEW.md` | 总时长、画幅、色彩、光照、风格、介质；全局层只写一次 | 源片 | 各文档引用，不改 |
| `RR-SCRIPT` | 源片剧本还原 | `项目开发/原片还原/RR-SCRIPT.md` | 按场次还原动作、台词（逐字）、画面文字、声音；OCR/ASR 为源事实，听不清写「疑似」 | 场次 + 时间码 | 场记、导演还原、分镜的源 |
| `RR-ASSETS` | 主体与场景设定 | `项目开发/原片还原/RR-ASSETS.md` | `<主体N>` `<场景N>` 稳定标签 + 视觉特征描述 + 首次出处镜；只给视觉特征稳定的建标签 | 标签 → 出处镜 | 提示词不变层、引用映射 |
| `RR-CONTINUITY` | 场记账 | `项目开发/原片还原/RR-CONTINUITY.md` | 一镜一卡：站位／朝向／机位／景别／轴线侧／光位／道具状态／时间关系；数值只从代表帧与切点读 | `CARD-` ↔ `SHOT-` | 分镜只引用账里的值 |
| `RR-DIRECT` | 导演还原 | `项目开发/原片还原/RR-DIRECT.md` | 每场戏剧行动、转折与承受、观众知情、观看方案；只写画面能证明的 | 场次 | 分镜职责与 reads |
| `RR-SHOTS` | 分镜表 | `项目开发/原片还原/RR-SHOTS.md` | 逐行一镜，边界按反推格式判定，含证据级与置信度 | `SHOT-` + `in/out` | 提示词、QC |
| `RR-PROMPTS` | 提示词 | `项目开发/原片还原/RR-PROMPTS.md` | 按目标方言翻译，三层槽位（不变层／氛围层／变化层） | 镜号 | 生成态才启用 |
| `RR-MAP` | 引用映射表 | `项目开发/原片还原/RR-MAP.md` | 标签 → 描述 → 出处镜 → 证据；把时间码与代表帧贯穿到剧本、场记、分镜 | 时间码／代表帧 | 全片核对 |
| `RR-QC` | QC 备注 | `项目开发/原片还原/RR-QC.md` | 12 条逐条结论（通过／已修正／不适用＋理由）+ 冲突待裁决 | 条号 | 交付前自检 |

`项目开发/原片还原/` 是 `creator-workflow.md` 允许的**可选分析工作区**，只在用户点名复刻／反推时建立；
九份 `RR-*` 是证据层的还原稿，不进 `剧集/<EP>/` 六文档主链。

## 三条书写思路

1. **文档契约先行**：先定每份文档的输出字段，再拆视频；字段没定好不开始逐镜。
2. **不变／变化分层**：角色场景层不变、氛围画质层一场不变、每镜画面内容层唯一变化；
   光线归氛围层，写进画面内容层会和动作描述抢权重。
3. **证据分级 + 帧轴贯穿**：每条事实带 `observed`／`inferred`／`unclear`；
   `RR-MAP` 把时间码与代表帧贯穿到剧本还原、场记账与分镜表，让「这一镜从哪一帧来」可核对。

## 回填到项目：SRC / RR / SHOT 对账

九份 `RR-*` 落在 `项目开发/原片还原/`，接通靠三条 ID 的对账，由 `RR-MAP` 负责：

| 层 | ID | 在哪 | 谁拥有 |
|---|---|---|---|
| 原片证据 | `SRC-<镜号>` | `项目开发/原片拆解.md` 每镜一节，带入出点秒数与代表帧路径 | [视频复刻模式](../../drama-skills/skills/short-drama/references/video-remake.md) |
| 逆推还原 | `RR-*` 镜号 | `项目开发/原片还原/` 九份文档共用 | `video-shot-reverse` |
| 创作主链 | `SHOT-...` / `CARD-...` | `剧集/<EP>/分镜.md`、`设定集/场记.md` | 各阶段 owner |

- 三者数量相等、集合相同；合并或拆分原片镜头要写理由。
- 每个 `SHOT-...` 的「来源」写对应 `SRC-...`；`CARD-...` 与 `SHOT-...` 仍按场记账一卡一镜对账。
- 下游 owner 按 [六文档契约](../../drama-skills/skills/short-drama/references/document-contract.md)
  的字段与 ID 把 RR 事实**编译**进 `剧集/<EP>/` 的六份文档；不复制 RR 文档、不另建一套创作真相。
- 代表帧路径 `输入/原片/frames/SRC-xx.jpg` 仍是画风基准与构图参考的源。

## 与正向六文档的对应

| 逆推 | 正向 | 差异 |
|---|---|---|
| `RR-OVERVIEW` + `RR-MAP` | 无独立文档；散在观看策略、画风基准、视觉设定 | 正向缺一份贯穿全片的源与引用索引 |
| `RR-SCRIPT` | `剧本.md` | 逆推以时间码与帧为源，正向以场景 ID 为轴 |
| `RR-ASSETS` | `视觉设定.md` | 同构；逆推多「出处镜」与证据级 |
| `RR-CONTINUITY` | `设定集/场记.md` | 同构：一卡一镜、账本为数值权威 |
| `RR-DIRECT` | `导演.md` | 逆推只写画面能证明的，正向写创作决定 |
| `RR-SHOTS` | `分镜.md` | 逆推带证据级与置信度，正向带观众 reads 与画面证明 |
| `RR-PROMPTS` | `图片提示词.md` + `视频提示词.md` | 同构，方言按目标通道换 |
| `RR-QC` | 无随稿交付段；QC 在脚本与独立审查报告 | 正向有意不落 QA 报告，保持 |

## 边界

不生成媒体、不剪辑、不把推断写成源事实、不把这一套文档当成创作真相——它是可核对的还原稿。
`RR-PROMPTS` 默认只写台账，送去生成是新的授权（见 `video-shot-reverse` 的分析态铁律）。
