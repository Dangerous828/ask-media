# video-shot-reverse — 视频逐镜反推

> **注意**：本技能把视频动作**拆成文字**。如果用户要的是“把参考视频直接喂给模型，让角色照着做（含参考音轨）”，那是另一条通道，读 `../h3-queue/references/video-motion-drive.md`，不要走本技能。

**扒片**是把眼睛看到的翻译成模型听得懂的。这套活最难的不是技术，是**克制**：看不清就说看不清，
没听到就说没听到，拿不准标「疑似」放进备注。翻过的车几乎都翻在「你以为你看见了」。

本技能把这件事标准化：**只读、逐镜、可核对、能存档**。逆推一条视频不是产出一张分镜表，
而是为这条视频重建**一套准备文档**——剧本、场记、导演、分镜、提示词都要还原出来，
才能被下游 owner 按同样的结构继承。

## 铁律：分析态与生成态分开

- **默认停在分析态**：提示词提取、反推、拆镜、加字幕表，全程只读。完成判据是产出
  [一套可存档的逆推准备文档](references/reverse-documents.md)，不是一张图或一段视频。
- 只有用户明确说「用这个提示词去生成」「做同款」「复刻」时，才把准备文档交给对应生成通道；
  这一步是新的授权，不因文档已经写好而自动发生。
- 拿不准按分析走，出完文档再问要不要生成。

## 何时用 / 不用

| 用 | 不用 |
|---|---|
| 把一条视频重建一套准备文档 | 只把链接转成文字稿 → `shortvideo-understand` |
| 反推每镜景别、运镜、光、动作、台词断点 | 拉片出切点与白模预演 → `video-previs` |
| 复刻／翻拍前把原片变成逐镜事实 | 从剧本正推写短剧分镜 → `short-drama-storyboard` |
| 成片复审按证据分级逐镜复核 | 剪已有素材 → `concat-video` / `short-drama-edit` |
| 提取可复制的 caption | 出图／出视频 → `h3-*` / `short-drama-produce` |

**分工**：`shortvideo-understand` 给文字稿与原片，`video-previs` 给切点、代表帧与白模，
本技能把这两样**逐镜还原成九份 `RR-*` 准备文档**；文档往下走生成时按目标模型方言翻译，
往回走项目时按 [视频复刻模式](../drama-skills/skills/short-drama/references/video-remake.md)
把九份文档落 `项目开发/原片还原/`、再按
[六文档契约](../drama-skills/skills/short-drama/references/document-contract.md) 回填进 `剧集/<EP>/`。
两侧不互相替代：`video-previs` 的白模只锁空间，不产出准备文档；本技能不渲染白模、不改机位数值。

## 流程

每一步都有完成判据，达不到就停在那一步，不带疑问往下写。

1. **定模式。** 判定本次是分析还是生成；生成请求先重建准备文档再拿去生成。
   完成判据：写入本次模式，且生成态有明确授权。
2. **锁视频源。** 上传的、素材库里的、画布节点上的都可用；多段按 `@视频1 @视频2` 编号。
   顺序不明先问，不自己猜。完成判据：每段视频有唯一编号与确定顺序。
3. **逐镜拆解成台账。** 按 [反推格式](references/reverse-format.md) 的逐镜 schema 取严格分镜 JSON：
   整体时长、全局风格、画幅色彩光照、逐镜边界，以及每镜的景别、角度、运镜、主体动作、表情、
   空间走位、转场、可见文字、置信度。返回的是大段场景概括时再追问一次，专门问切点、运镜变化、
   动作状态变化；**第二次只当补充证据，不当自动真理**，两次矛盾留到 QC 里解决。
   完成判据：每镜字段齐全、每个边界有判定依据、未观测项标「疑似」而非写成事实。
4. **判边界、建映射。** 按同一份格式里的边界判定表决定何时开新行；反复出现且视觉特征稳定的主体、
   场景建 `<主体1>` `<场景1>` 标签跨镜复用，只出现一次的用描述性短语。
   完成判据：没有因「过了几秒」拆的行，也没有把两个视觉上明显不同的镜合并。
5. **翻译成 caption（方言可插拔）。** 观测到的是原始数据，不能直接搬进提示词。按格式里的翻译层过一道：
   八要素、一镜一主导运镜、情绪翻成物理证据、音频与文字用固定符号。
   **格式骨架通用，caption 方言按目标通道换**：本仓主通道是 MiniMax H3，SD2 的符号与词表不进 H3 正文。
   完成判据：未观测要素一律没写进去；每镜只有一种主导运镜，次要趋势在备注。
6. **跑 QC。** 按格式里的 12 条逐条过，每条给结论。完成判据：12 条都有处理理由，
   时间码串列、裸露资产 ID、遮挡处脑补动作、形容词加码都已被检出或确认不存在。
7. **交付一套准备文档。** 逆推不是产出一张分镜表，而是为这条视频重建一套准备文档：
   视频概览／源片剧本还原／主体与场景设定／场记账／导演还原／分镜表／提示词／引用映射表／QC 备注。
   九份文档在复刻项目里落 `项目开发/原片还原/`；`RR-MAP` 负责 `SRC-...`／`RR-*` 镜号／`SHOT-...`
   三者数量相等、集合相同。清单、落盘路径与回填对账见
   [逆推准备文档体系](references/reverse-documents.md)；结构向
   [六文档契约](../drama-skills/skills/short-drama/references/document-contract.md) 看齐，
   让逆推事实能被下游 owner 按同样结构继承。
   完成判据：九份齐全、每条事实带证据级、引用映射表的时间码能贯穿到剧本还原与分镜表。

## 只在五种情况打断用户

没有可用视频；多个视频但顺序不明；要精确对白但没有音频源或转录稿；要精确身份／品牌／地点但工具给不出；
用户明确要求只要聊天输出。其余情况自己按格式往下做。

## 与正推写法的 merge

逆推准备文档与正向六文档互为镜像：

- 正推侧：[六文档契约](../drama-skills/skills/short-drama/references/document-contract.md)
  （每份文档的字段、ID、贯穿轴、下游读法、不变／变化三层），由 `short-drama` 持有；
- 逆推侧：[逆推准备文档体系](references/reverse-documents.md) 九份 `RR-*` 文档
  + 本技能的 [反推格式](references/reverse-format.md)；
- 字段级细节：[逐镜证据台账](../drama-skills/skills/short-drama/references/observation-ledger.md)
  （依据三级、记录值与设计值、冲突裁决、主导运镜、写作 QC 12 条）。

护栏、正向更严项与验收层顺序见 [消费场景](references/consumers.md)。
