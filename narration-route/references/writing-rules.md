> 转载改编自 [video-recap-skills](https://github.com/zenstory-ai/video-recap-skills) v0.6.2 `skills/video-script`
> （MIT License, Copyright (c) 2026 PiteChen）的 §4.4「声音与旁白分工」、§5.1「写作规则」、§5.2「解说结构」。
> 原文完整语境见上游仓库；本文件只保留对短剧旁白直接可用的部分，并补了短剧特有判断。

## 1. 先定 audio_owner，再写字

先回答"这个 beat 的声音归谁"，再动笔。旁白只允许承担这六类职责（`narration_job`）：

| job | 补的是什么 | 短剧里的例子 |
|---|---|---|
| `context` | 背景信息，画面看不出 | 「2005年，全中国有上亿个QQ号。」 |
| `causal_link` | 两个画面之间的因果 | 「他没有问，也没有查。」 |
| `foreshadow` | 之后会兑现的伏笔 | 「这句话，他记住了。」 |
| `interpretation` | 对已发生事实的解释或评价 | 「一个足以震惊整个互联网的结论，诞生了。」 |
| `transition` | 跨越时空的过渡 | 「第二天课间。」 |
| `none` | **不需要旁白** | 画面与原声已经说清楚了 |

**`none` 是合法且常用的答案。** 画面、原声或沉默已经足够时，不要默认铺旁白。

## 2. 写作规则（9 条，逐条对照）

1. **先有 narration_job，后有句子。** 没有明确任务就不写；旁白不是默认音轨。
2. **按连续思路写。** 旁白拥有一个 beat 时，用一或少量完整句子完成"前提 → 触发动作 → 变化/意义"，并在一次 TTS 中合成。句号服从口语思路和呼吸，不服从字幕换行；不要固定句数，也不要"一句一停"。
3. **7:3 不是配额。** 只在素材判断不足时作为避免"墙到墙旁白"的粗略首稿参考。实际比例服从 `audio_owner`；强对白、动作声或沉默可以完整拥有一个 beat。
4. **视听接力。** 旁白若引出原声，块尾要让观众想听；原声结束后的下一块要承接它造成的变化。
5. **按有效语速控量。** 用 `字数 ÷ 语速` 估算朗读秒数（中文播音腔约 4.2–4.6 字/秒），每块再加约 **0.45 秒 TTS 首尾静音**。2–3 秒的短窗口要比算出来的少写一两个字；**装不下时删减或拆分叙事任务，不用加速堆字**。
6. **不看图说话。** 旁白只增加上下文、因果、预期、证据支持的解释或跨越。**画面已经在演的，不要念一遍。**
7. **人物与证据优先。** 优先用已知角色名；关系、动机、潜台词和结果必须指向画面/对白/设定里的既有证据，不能把背景资料伪装成当前画面事实。
8. **写给耳朵听。** 用具体名词和动词，句子完整、口语可听；避免字幕腔、半句、空泛拔高和破折号。TTS 文本先保证听感连续，字幕再按阅读宽度拆分，不能反过来把朗读稿切碎。
9. **避免模板化纠偏。** "不是 A，而是 B"只在确实存在一个观众可能相信、而素材又要纠正的判断时使用。不要靠先否定再肯定制造假洞察；优先直接写人物的动作、因果和后果。

## 3. 解说结构（短剧适用部分）

- **钩子**：提出正文会真实兑现的问题或利害，不用无关留存话术。
- **主线**：围绕选定 POV 与主线推进，不在每个场景重新开篇。
- **递进**：后续 beat 必须提高风险、改变关系或提供新信息。
- **悬念缺口**：只预告之后真的会回收的后果。
- **收尾**：回答或有意转化开头问题，留下明确余味。
- **衔接**：旁白块与相邻原声属于同一个 beat——前者铺垫、后者呈现、下一块承接。

## 4. 时间窗核算表（写作时直接查）

| 时间窗 | 可写字数（含 0.45s 静音余量） |
|---|---|
| 2.0s | 6–7 字 |
| 3.0s | 10–11 字 |
| 4.0s | 14–16 字 |
| 5.0s | 19–21 字 |
| 6.0s | 23–25 字 |
| 8.0s | 31–34 字 |

超出就用规则 5 处理：删字、拆任务，或改用画面文字（不受发声窗口约束，但受排版空间约束，见 `layout.md`）。

## 5. 数据契约（若走 TTS）

沿用上游 `narration.json`，时间统一为**成片输出时间线的秒数**：

```json
[
  {
    "start": 10.6,
    "end": 16.2,
    "narration": "小时候的我一直不明白，为什么这里是个选择，而且只能选这两个。",
    "pause_after_ms": 250,
    "overlaps_speech": false,
    "emotion": "回忆"
  }
]
```

- `start` / `end`：该块在成片里的起止
- `pause_after_ms`：段后停顿，默认 250
- `overlaps_speech`：是否与原对白重叠；有台词同时说时 `true`，静音槽 `false`
- `emotion`：语气标签，喂给 TTS 做语气/语速指令

## 6. 短剧场景的额外判断

上游面向"视频解说成片"，短剧有两个不同点，写作时要额外注意：

1. **短剧已有完整对白与表演**，旁白的默认答案是 `none`；解说成片则可以墙到墙铺。判断"该不该加"时按短剧口径，更保守。
2. **短剧旁白通常是创作者的自传回望或作者评论**，天然适合第三人称说书人或第一人称回忆；两者不要混用，见 `perspective.md`。
