# 旁白落地形式

## 1. 三种形式

| 形式 | 观众感知 | 约束 | 适用 |
|---|---|---|---|
| **TTS 配音** | 听得到 | 受发声窗口硬约束、需混音、需单独授权外发 | 信息密度高、需要语气带情绪 |
| **画面文字** | 看得到 | 受排版空间约束、长文案难、可能读不完 | 短句点题、不想动音轨 |
| **两者并用** | 视听双通道 | 成本最高、时间轴必须严格对齐 | 关键句需要双重强化 |

**必须由创作者选定，代理不自作主张。** 默认倾向：
- 旁白短（≤12 字）且是点题性质 → 画面文字
- 旁白长、有语气转折、需要节奏 → TTS
- 创作者说"旁白"但没指定形式 → **先问**

## 2. TTS 配音

**执行**：短剧项目交 `short-drama-produce` 的 `tts` 模态生成（预览→确认→运行，音色取 `short-drama-assets` 声音方向），再由 `short-drama-edit` 以 `配音` 行装配；非短剧项目可用外部 `video-recap-skills/video-voiceover`（本机未安装），输入 `narration.json`（契约见 `writing-rules.md` §5）。

**时间窗硬约束**：
- 中文播音腔约 4.2–4.6 字/秒
- 每块加约 0.45 秒首尾静音
- 装不下就删字或拆任务

**不允许的做法**：
- ✗ 为塞下旁白而放慢画面（实测 0.65x 已明显动作滞涩，创作者否决）
- ✗ 加速 TTS 语速硬塞（超出 ±10% 听感变尖，且失真）
- ✗ 旁白压在台词上不降音量（两路中文同时说，观众听混）

**必须做的**：
- 先试听音色与语速
- 旁白与台词时间窗错开；若必须重叠，旁白压 -12dB 以下
- 混完后测整片响度，并单独确认旁白区间可辨

## 3. 画面文字

**执行**：本技能 `../scripts/overlay_text.py`；排版规则见 `layout.md`。

**优势**：不受发声窗口约束，一条长文案可以铺满整镜。

**硬约束**：
- 不压在人物面部、手部动作、关键道具上
- 不出画（竖排尤其容易，见 `layout.md`）
- 不与底部对白字幕撞位
- 单屏可读字数有限：竖排一列约 8–14 字（视字号），横排一行约 10–16 字

**长文案必须处理**，三种手段按优先级：
1. **按镜拆分**——一个镜头内分两段时间显示，各自 4 秒左右（推荐）
2. **分列**——竖排自动分成 2 列，宽度允许时
3. **缩字号**——最后手段，低于 40px 在竖屏手机上偏难读

## 4. 两者并用

只在关键句使用。两条铁律：
1. **时间轴严格一致**：文字起止必须落在配音发声区间内，不能文字先走或声音后到
2. **文字不复述配音全文**：文字放关键词或短句，配音说完整句

## 5. 形式与剪辑阶段的关系

| 形式 | 剪辑单怎么写 | render 能不能做 |
|---|---|---|
| TTS 配音 | `- 配音 N：<起> <路径>` | ✓ 内置支持（叠在原声上） |
| 画面文字 | 不进剪辑单的字幕行，走外部叠层 | ✗ 内置 render 只烧底部字幕；画面文字需 `overlay_text.py` 或 Remotion |
| 底部对白字幕 | `- 字幕：<逐字台词>` | ✓ 内置支持 |

**注意**：短剧项目的旁白文字走剪辑单的 `画面文字` 行，由 `short-drama-edit render`（Remotion）一次渲染进成片，保证剪辑单与交付文件一致、`verify` 测的就是交付件。本技能的 `overlay_text.py` 只用于非短剧素材；在短剧成片上二次叠字会产出剪辑单之外的新成片，不要用。

## 6. 自检

- [ ] 形式由创作者选定
- [ ] TTS：时间窗算过、音色试听过、旁白区间可辨
- [ ] 文字：抽帧确认不压主体、不出画、不与字幕撞位
- [ ] 两者并用：时间轴对齐、文字不重复配音全文
