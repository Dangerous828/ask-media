# Ask Media

## 先判这是不是短剧项目

判据是**盘上有没有 `剧集/<EP>/` 六文档**，不是片长：

- **有** → 走完整阶段链，十一阶段判据归 `drama-skills` 那 12 个 `short-drama-*`。
- **30 秒上下的独立短片、无项目目录** → 阶段链相同，但分镜用 `storyboard-30s`、场景账用 `short-film-scene-continuity`。
- **单张图、单段视频** → 不建项目，直接从第 7 或第 8 步进，跳过场记与分镜。

## 准备阶段的必需交接

进入相关分镜前，采用的每项机制条件须有完整 template 出处、导演承载镜头、场记状态/接续条件及素材责任；未定项回 owner，相关范围不宣称就绪。无需套卡的普通场写明取舍即可。剪辑组织方法与特效目录分开核实，前期读取知识不等于提前执行剪辑。

## 每一步的前置与硬闸

这几条最容易出错，按阶段查：

- **③ 资产 → ⑤ 场记**：必须先出场景/地点资产才能开场记，不必等人物定形。
- **③ 资产／项目档案 → ⑨ 生产**：画风基准必须带「认可依据」（谁、何时、认可了什么，附认可项／待补证维度）才算登记，缺这一行验收只能给 `PROVISIONAL`；认可依据来自创作者本人确认，agent 不代写。会话里点名了目标视频模型，就先落进 `production_profile`（`unset` 不算已选）——它决定原生时长、参考方式与正文语言，没落档案就往下写词，后面整链要返工。档案字段拆法见 `../drama-skills/skills/short-drama/references/production-form-profiles.md`，写入与接受步骤归 `short-drama`。
- **⑤ 场记 → ⑥ 分镜**：六本账未对齐，**不许写第一张分镜和第一条提示词**；缺账先补场记，不带着“机位和光位回头再说”往下写。一张 `CARD-` 强制对应一个 `SHOT-`。哪怕只有一个场景也要建最基础白模。
- **白模 → ⑥ ⑦ ⑧**：白模摆出来的**实摆值**（机位高、俯仰角、距离、焦距）与原来的计划值常常对不上。回写顺序：账本 → 分镜镜头语言行 → **分镜英文正文的机位句** → 已写的视频提示词 → 账本「未对齐项」记原因。**下游任一份没同步就不算做完**。先写分镜、事后才建白模、然后不回头改，是最常见的错位——那种情况下白模白做了。
- **⑥ 分镜 → ⑦ 图片词**：写分镜前确认 `设定集/场记.md` 存在且已对齐；下游只准引用账本里的值。
- **⑧ 视频词 → ⑨ 生产**：过 `h3-video-gate` 才算交稿；闸门只查结构，查不出画风错、接缝断、身份漂移。
- **⑨ 生产 → ⑩ 验收**：生产是“生成一条 → 验收一条 → 才决定下一条输入”的循环，不是一次跑完再统一审。被拒素材的派生产物随之作废。产物被打回时**先判症状归属再选回哪一步**：画风/身份回 ③⑦，机位与状态回 ⑤⑥，表演与接缝回 ⑧，别在 ⑨ 原地改参数重跑——同一症状重跑不修法。判型入口见 [阶段路由表](references/route-table.md) ⑧⑩ 两行。
- **执笔与投递（⑦⑧⑨，单张/单段同）**：提示词正文由**干净上下文的子代理**执笔，哪怕只写一张图、一段视频；改图／图编辑指令同属提示词，一镜一任务、代理不复用到下一镜。每一次投生产由一个**全新的子代理**执行，一次投递一个代理，h3q 队列与图编辑网关同样算。主会话只备交接材料、收回执、验收产物，不亲笔、不代投。判据见 [开发纪律](references/discipline.md) §七。
- **文档就绪 → 请求批准**：文档层面的准备做完后、向创作者请求批准下一步之前（含单张图、单段视频开工），先开**双轴审查**：规约轴、事实轴各由一个干净代理独立执行；两轴都查不出问题，才有资格开口请求批准。任一轴查出问题，修完全部重跑两轴，不许只补查改动点。判据见 [开发纪律](references/discipline.md) §七。
- **⑩ 验收执行者**：验收读片（逐帧审、首尾并排、measure/review 实测）由未参与本镜写词投递的**干净代理**执行，evidence 数字当轮实测、不继承声称值；主会话仍亲开产物核对关键 PASS。判据见 [开发纪律](references/discipline.md) §七。
- **⑪ 剪辑执行者**：粗剪／终剪由干净代理按剪辑单组装，逐缝过「切点前后帧并排、上一镜末态＝下一镜首态」再冷看全片报事实；缝的观感归创作者判。判据见 [开发纪律](references/discipline.md) §七。
- **删除执行者（全线）**：删文件／删目录／整镜整集下线由干净子代理按**删除单**执行——单上逐项列删什么、留什么、归档路径（能归档先归档）、下游引用谁改；删完回报实际删除与保留清单，批量删除以创作者明确点名为前提。判据见 [开发纪律](references/discipline.md) §七。
- **文档联动执行者**：一个决定波及两份以上文档的联动同步改（删镜／改点位／换时长波及剧本-场记-分镜-词-导演）由干净代理按**变更单**执行——单列每处改什么+依据原文、自足可照改；改完回报每份文件实际改动位置，不许顺手改。删除类联动先走删除单再走本条。判据见 [开发纪律](references/discipline.md) §七。

## 旁路：复刻别人的片子

`shortvideo-understand` / `video-shot-reverse` —— 不占链条位置，产出的原作事实回填到第 2 步起。分析态全程只读，不碰生成工具。

## 不进链的情况

**用户要角色“学动作 / 照着参考视频做 / 动作参考 / 翻跳”（视频动作驱动、含参考音轨）**：直接到 ⑨ 生产，读 `../h3-queue/references/video-motion-drive.md`，它不经 h3q 队列，与“拆成文字的 MOTION 复刻”是两回事。

对已有任务的队列查询、既有媒体审查和纯已有素材剪辑，不另起创作路由；实际生产仍遵守生产 owner 的授权规则。**复审视频要看/核对台词时**，用通用 ASR 工具出带时间轴文字稿（作者本机用 `transcribe <视频> [--format srt] [--lang zh]`——这是作者本机工具，入口 `~/.local/bin/transcribe` 已软链 `mlx_whisper`，未随本仓发布；通用替代：`mlx-whisper`、`whisper.cpp` 或任意本地离线 Whisper 实现）；需要画面动作信息时自行抽帧逐帧核对。这是只读审查，不碰生成工具。`concat-video` 只负责通用已有素材执行；发现需要补素材、改剧情/镜头职责/起终态时，回对应上游。短剧仍走 `short-drama-edit`，不建平行剪辑工程。

## 动手前必读一条

任何阶段出了产物（样张、draft、final、拼好的段）都要自己看过才许往下走。**视频一秒一帧，闸门过了不算看过。** 细则见 [开发纪律](references/discipline.md)。

## 需要逐行查参考的时候

已经知道自己在第几步、只要查“这步该读哪份参考”，读 [阶段路由表](references/route-table.md)。其余情况不用打开它。

语料和剪辑知识在文档准备时按需求引入：`creative-dna-cards` 检索完整模板 → ④ 导演采纳/改编并分派镜头 → ③ 资产按需回补状态 → ⑤ 场记落实状态与接续条件 → ⑥ 分镜定证明时间窗 → ⑦⑧ 词执行 → ⑨⑩ 真实产物核证据 → ⑪ 剪辑采用。已有专项入口也须继承本次相关条件；不是末端兜底，不增加阶段。完整分工、未定项与执行器限制见 [语料机制与剪辑准备](../drama-skills/skills/short-drama/references/mechanism-preparation.md)，检索见 [机制卡索引](../h3-prompt-writing/corpus/creative-dna-t8/INDEX.md)。ask-media 只选路交接，不代选机制或写创作正文。
