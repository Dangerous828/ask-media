# 段间接缝：手法、通道可用性、可复制句式与核对

两段独立生成的视频放在一起，观众看到的不连续有四种：**身份变了、空间变了、动作相位断了、情绪相位断了**（画面三连却仍被读成硬切，是表演在切点跳档）。
前三种都不该留给剪辑去"修"，因为剪辑只能选点，补不出没拍到的中间状态；第四种连容器与手法都修不了，只能回正文修表演曲线（判法见 §0.1 第 0 步）。

本文件是接缝手法的唯一权威源。别的文档只保留入口与结论一句话，
不复制手法清单——同一件事写在四处，四处会各自漂移。入口见 [`../SKILL.md`](../SKILL.md)。

## 零、最先读这一张表（其余章节都是它的展开）

本文件大部分篇幅是 32 种手法的句式清单。实际决定成败的不是清单，而是下面这张表。
**如果你只有两分钟，只读这一节。** 后面所有章节都服从这里的结论。

### 0.1 拆段决策：按顺序判，命中就停

| 步 | 判断 | 做法 | 依据 |
|---|---|---|---|
| 0 | 创作者反馈"还是硬切"，先判型再动手，按顺序查三个：①**画面缝**——机位/光影/身份/人物大小在切点跳档；②**镜内相位断**——画面要素没跳，但某角色的入场/落位过程被压缩（以中途姿态凭空出现、动作缺过渡拍）；③**情绪缝**——①②逐帧都对，只有表演在切点跳档（如"委屈含泪→瞬间张嘴大哭"） | ① → 按本表 1–6 选接法；② → 不是接缝问题，回正文拆逐拍入场/过渡拍，每拍给时间码（判据见 `../../../../h3-prompt-writing/references/failure-modes.md`"画外角色入场用一拍概括"条）；③ → 回正文修表演铺垫：上一窗末帧先铺垫情绪（含泪/眼眶湿），下一窗开场直接写到位的强表情，别在窗内做渐进微表情（会被读成另一种表情；判据见 `../../../../h3-prompt-writing/references/failure-modes.md`"Q版渐进微表情/否定句压表情"两行）。**重做容器、换接法、叠化对②③都无效** | EP004 006+007 三轮迭代三个根因（2026-11-19/20）：多窗把画面缝钉死后，"抱起来那一下"=妈妈入场被压缩（②，v2 拆逐拍入场修掉）；随后"瞬间开哭"=情绪跳档（③，v3 铺垫+强信号修掉）——同一条片两个硬切、两个不同根因 |
| 1 | 这些动作能不能装进一次生成（≤15s）？ | **能 → 可装进一个容器，用 `[Shot N]` 切**。仍核切点与连续性 | 减少跨任务接口，不保证无漂移 |
| 2 | 装不下一次单镜，但**同机位同场景、接缝必须无缝**（动作接力/连续对话/光影不能跳） | **多窗容器 `workflow=multishot`**：潜空间接力把上一窗末段直接钉进下一窗，接缝不是两段拼接。**选路细则与通道参数以 `../../../../h3-queue/SKILL.md` §2.14 为准**（默认能拆就拆单镜；scene_video 场景锚、静默窗、容量代价都在那里，本文件不复制） | 实测接缝几乎逐帧一致（EP004 006+007，2026-11-19）；换场景硬塞会翻机位，见 §0.2 |
| 2b | 两段各自出片（各自要挂身份/地理图），**同一空间**（§0.4 四项判据全成立），机位或站位有变，装不进同一容器 | **转场卡**：A 的真实末帧 + B 的真实首帧 → FL2VA 单段生成中间段 C，成片 A + C + B（做法见 #18 用法 B；判据与投递约束见 §0.4）。A、B 各自保留 full-reference，C 只靠两帧，**必须走默认分支、不能带 `--workflow pdd_lu`** | 两端像素锁定（#17 只锁一端）；代价：多一整段（≥107f/4.458s）片长与一次生成。中段实测只保身份与空间，不保表情/说话人/动作路径（§0.4 证据状态） |
| 3 | 装不下多窗（跨场景/要换机位/本段不需要无缝），且**不重挂身份/地理图** | **用上一段真实末帧做 `first_frame` 接力** | 实测帧差 **3.38** |
| 4 | 装不下，且**本段必须重挂身份/地理图** | **改机位重出，让两段各自成立**；不要设计"接着上一段"的连续动作 | 接力与 `reference_image` 互斥；靠正文承接是 **41.87** |
| 5 | 两段之间本来就有时间跳跃 / 换地点（§0.4 任一条不成立也归这里） | **硬切、跳切、省略，且接缝处必须在剪辑单登记一个剪辑手段**：默认声音桥（J-cut / L-cut）；有叙事动机时可用黑场或白场；叠化的适用范围见 `short-drama-edit` 的 cut-craft。不写「裸硬切」，也不加字幕/贴纸/特效遮缝（§八） | 本来就断开；换场景的接缝靠声音与节奏承接，画面上补不出缺失状态 |
| 6 | 需要一个过渡动作 | **光线变化**（✅ 实测）或 **插入镜**（✅ 实测） | 不依赖前段状态 |

### 0.2 实测结论速查（十组真实渲染，本地 h3q，draft 512×896）

| 手法 | 结果 | 数字 |
|---|---|---|
| 容器内 `[Shot N]` 切 | ✅ 可用 | 同一次采样 |
| `flf_chain` 接力（真实末帧做首帧） | ✅ 可用 | 帧差 3.38 |
| 接力 + 双镜容器组合 | ✅ 可叠加 | 首帧接上 + 内部切点生效 |
| 光线变化（关灯） | ✅ 可用 | 亮度 65→39.5 并稳定 |
| 插入镜（换主体） | ✅ 可用 | 脸不在画内、手入画 |
| 失焦 #22 | ✅ 可用 | 边缘能量 4.21→2.12，末帧只剩光斑 |
| 甩镜 #21 | ❌ 失败 | 只模糊背景，人物完全清晰 |
| 动作对拍（两段独立生成） | ❌ 失败 | 41.87，后段从参考图姿势重演 |
| #1 背接（环绕到肩背遮满） | ❌ 失败 | 三组全败；8s 只到约 90° |
| 多角度参考图救遮挡 | ❌ 无效 | 只让"靠近/压暗"生效，脸仍正对 |
| multishot 潜空间接力（同机位同场景两窗 + scene_video 场景锚） | ✅ 可用 | 接缝 8.4–9.2s 五帧几乎逐帧一致，光影/机位/人物大小连续（2026-11-19 EP004 006+007，两窗 226f@1024×576 约 12 分钟；通道参数以 h3-queue §2.14 为准） |
| 画外角色入场压缩（`from off screen` 一拍概括入场+落位） | 词层坑 | 角色以中途姿态凭空出现、无入场过渡帧，读成镜内瞬移/硬切；逐拍入场修法见 `../../../../h3-prompt-writing/references/failure-modes.md`"画外角色入场用一拍概括"行（2026-11-19 EP004 006007 v1→v2） |
| 情绪缝（画面全连续、表演跳档） | 词侧修 | 不归手法管：上一窗末帧铺垫情绪 + 下一窗开场强信号表情才成立；窗内渐进微表情会被读成另一种表情（2026-11-20 EP004 v3 同片实证，表情词判据见 `../../../../h3-prompt-writing/references/failure-modes.md`） |

**一句话**：**在两段之间，"接着上一段"只有两条可靠做法——把上一段的真实末帧交出去（单镜接力），
或把两窗放进同一个 multishot 容器走潜空间接力。其余靠文字、靠遮挡、靠对拍，全部实测失败。**
（情绪跳档另算：它不走手法，走正文表演曲线，见 §0.1 第 0 步。）

### 0.3 三个最容易犯的错

1. **以为写了"镜头环绕到背后"它就会环绕**——参考图的姿势会压过正文，实测三组都退回了正面看镜头。
2. **以为两段正文写同一拍就能对上**——后段不知道上一段演到哪，会从参考图姿势重演（41.87）。
3. **以为秒数可以随便写**——执行端只认 `--frames`，24fps 下 4–15 秒里**只有 8 秒**正好落 `17k+5`（§6.3.2）。

### 0.4 转场卡：什么时候用，凭什么判

**概念**：A、B 两段先各自按完整参考组出片；再取 A 的**真实末帧**做 `first_frame`、B 的**真实首帧**做 `last_frame`，走 FL2VA 单段生成中间段 C（转场卡）。成片 A + C + B，剪辑时 C 的首帧与 A 末帧重合、末帧与 B 首帧重合，各去掉重复的一帧。
与 #17 的区别：#17 只锁起点，B 要放弃参考组；转场卡把「放弃参考组」的代价只压在 C 一段上，A 与 B 保持 full-reference，两条接缝都由真实帧锁死。

**四项判据（场记卡取值，全部成立才用转场卡）**

| 项 | 取值来源 | 成立条件 |
|---|---|---|
| 同一场景 | 场记空间账的场景 ID；相邻功能区按 §6.4.1b | 同 ID，或同场景相邻功能区且人物走动路径在 C 内可见 |
| 同一光位 | 光位账 | 光向与色温一致（暖/冷不翻） |
| 同一集合 | 调度卡的在场、持物；道具账 | 两帧在场人物与持物集合相同，或差异能在 C 内由可见动作解释（谁入画、谁放下什么） |
| 一段连续运动能走完 | A 末帧 → B 首帧的机位与站位位移 | 位移能被一个连续动作或一次连续运镜解释，且不越轴（§六点五）。要两次以上动作才走完，拆成两张转场卡或回改分镜 |

**判据之外的三个限制**

1. **C 的身份只靠两帧**，两帧里必须是已验收的同一个人（#18 已列）。
2. **C 内不放台词与对白口型**：C 的音频是独立生成的，两端都不连；接缝处按 §4.5 #20 做声音桥。
3. **C 是新增片长**：最短 107f / 4.458s（§6.4.1c）。剩余预算不足就不用，改走 #13 硬切加声音桥。

**投递硬约束（2026-11-22 实测，走 h3q）**

转场卡**走默认分支**（h3q 不带 `--workflow`，落到 `h3_render_ref.py` 的 i2va/fl2va 图）。`pdd_lu` 是 pdd 的草稿档，它的渲染器没有 `--first-frame` / `--last-frame`，做不了首尾帧；三个生产入口（MCP `h3_generate_video`、项目 adapter、`transcard.py`）已按输入自动分流，带首帧就不落到 `pdd_lu`。**落地命令与验收口径见 `../../../../h3-queue/references/transcard.md`**，别再手搓提交参数。

两帧按渲染器的参数语义传 **ComfyUI `input/` 里的裸文件名**（`--first-frame` 的帮助原文是 "filename in ComfyUI input/"）。T1 的 job params 写的是 Windows 绝对路径，但那一次根本没走到读这个键的渲染器，所以「绝对路径能不能用」这一轮没有证据——别拿它当先例。

经 h3q 提交时 `sol_profile` 缺省落 `off`（默认分支显式传 `--sol-profile`，不经渲染器自己的 scheduled 默认值）。T2 实测 `sol_profile=off`、4.458s/107f、wall **156s**、峰值显存 14.85 GiB。

**分流顺序（导演在观看方案里写，场记在接缝判型里记）**

| 步 | 条件 | 手法 |
|---|---|---|
| ① | 同机位同场景，装得进同一 multishot 容器 | multishot（§0.1 步 2） |
| ② | ① 不成立，但四项判据全成立 | 转场卡（§0.1 步 2b） |
| ③ | ② 不成立，B 不需要身份/地理图 | #17 首帧接力 |
| ④ | 换场景、换光位、集合对不上，或位移一段走不完 | 硬切 + 剪辑手段（§0.1 步 5）。回改分镜是另一条路（#32），按成本选 |

**证据状态**（2026-11-22 本地实测，EP002 / SHOT-03）

- **两端像素锁定成立**：C 首帧 vs 指定首帧 MAD **3.86**，C 末帧 vs 指定末帧 **3.66**。两端都锁得住。
- **中段只保身份与空间，不保路径**：把同一镜头的真实中间段当 ground truth 逐帧比（原片 f120→f226 vs C 的 107 帧），MAD 首末 3.9/3.7、中位 **23.9**、全片 22–27 之间**平坦地高**，不单调从 A 走向 B，而是中间就切到一个新状态。并排看脸：身份、发型、服装、巷子、光位都对，**表情与说话人不对**——原片是 S1 笑着说话、S2 静听，C 里 S1 转头朝镜头、S2 在张嘴。
- **C 的音轨独立且不连两端**：转写 C 得到与词稿一致的两句（「你别太挑了，一个人多冷清」「冷不冷，看跟谁走」），说明 `<d>` 台词能正常生成；但这两句在 C 内自成一段，与 A、B 的口型/音色无关，所以限制 2 仍然成立。
- **结论**：转场卡按「两端接死 + 中段身份/空间守住」这一档使用是**可用**的；指望中间那段还原原片的表情与说话人分配**不成立**，要那两样就把 A→B 的动作本身拆进一次生成（multishot 或单镜加长）。首轮用一对真实 A/B 出一张，按 §七 并排看四项再定是否常规化——这一轮不必再重复，判据已经被上面这条钉住。

## 二、成本分层：先说清楚要不要重出

写方案时每一步都标注它属于哪一层。分不清层次会导致"以为改文档就行"，实际必须重出一段。

| 层 | 含义 | 代表手法 | 代价 |
|---|---|---|---|
| **L-A 写词层** | 下一段还没生成。改两段的正文即可，素材不动 | 遮挡、动作承接、硬切/省略/插入、时间过渡、情绪对比 | 零次生成 |
| **L-B 剪辑层** | 两段都已出片，不改正文 | 硬切、省略、插入镜（用已有素材剪）、声音桥 | 零次生成，只改时间线 |
| **L-C 重出一段** | 必须重新生成其中一段 | 改机位重出、给前段补遮挡动作、换起始帧 | 每次 1 段生成 |
| **L-D 改分镜** | 并镜或拆镜，上游账本跟着改 | 改分镜 | 上游文档 + 全部受影响段重出 |

**必须写进接缝契约**：每条接缝标注 L-A / L-B / L-C / L-D，以及"这一层为什么够"。
只写手法名不写层次，等于没说什么时候动手。

| # | 手法 | 本通道 | 怎么落地（用哪条通道能力） |

## 四、逐个手法：可复制句式与失败迹象

> **这一节是句式参考手册，不是选择依据。** 选择依据在 §0.1，实测结论在 §0.2。
> 本节 32 条里，**真跑过渲染并成功的有四条：接力（#17）、光线变化（#23）、插入镜（#16）、失焦（#22）**；
> #13/#14/#15 是剪辑层手法，不依赖生成能否执行；
> **其余 15 条从未验证**，其中 #1 背接、#9/#10 动作对拍、#21 甩镜已被实测证伪。
> 它们的句式能过闸门，但不等于模型执行得出来。
>
> **按这里的清单挑手法是错的**：清单按"这是什么手法"组织，不按"这个通道能不能做到"组织。

句式全部取自 `h3-prompt-writing` 的方言规则，并按本机 `h3_gate.py` 实测通过
（`--refs 4 --frames 175`，ref 六段）；带 `[Shot N]` 的变体另加 `--storyboard` 已对账。
实测日期 2026-11-05，闸门为 `$h3-video-gate` 的 `../../../../h3-video-gate/scripts/h3_gate.py`。

### 4.0 三个必须遵守的写法约束

**① 遮挡转场里不写 `cut` 词。** `the camera cuts to` / `the shot transitions to` 是硬切指令。
遮挡只写 `the camera travels on`。真要硬切时反过来必须写切镜动词。

**② 优先写具体可见状态。** `the room melting into smooth amber bokeh` 直接描述失焦；必要的 `no readable detail` 可以保留，G36只提醒核对语义。不要把采样器没有独立负向分支解释成正文否定必然失效。

**③ 遮挡程度要写够。** `passes in front of the camera` 只遮一角，接缝会露出来。
要 `fills the whole picture` / `swallows the frame` / `fills the right two thirds of frame by <时刻>`。

### 4.1 遮挡类（L-A 写词层；**#1 背接实测证伪，其余未测，见 §一 与 §6.4.1**）

共同点：**切点落在画面被完全遮住的那一帧**。那一帧没有可比较的信息，两段的身份与空间漂移同时被藏起来。

结构固定为三段：**遮挡物是什么 → 从哪来、盖到什么程度、什么时候盖满 → 露出什么**。
前三要素在一句里写全，露出放在下一段的首句。

#### 1. 背接（tail-away）

镜头绕到人物背后，背影占满画面。

```text
From 00:06.300 the camera begins a slow arc around her right shoulder toward her back;
by 00:06.800 her shoulder and the wine-red silk of her cardigan fill the right two thirds of frame,
and by 00:07.100 the whole frame is covered by the dark fabric of her back, her hair and the soft fall of the cardigan.
```

后段首句（在它自己的正文里）：

```text
It opens buried in the dark fabric of her back, the wine-red silk filling the whole picture at 00:00.000;
the camera travels on and the fabric slides away to frame right, clearing at 00:00.500 to reveal the empty diner behind her.
```

**失败迹象**：遮挡发生在段中而不是段末（观众等）；背影没有盖满（留出背景可比较）；
后段没有从"被遮住"起幅，而是直接给全景（等于硬切）。

#### 2. 顺接（head-on）

人物朝镜头走来，身体占满画面。

```text
From 00:06.200 she pushes the plate away and stands up toward the lens,
her torso widening until her chest and both shoulders fill the whole frame by 00:07.000.
```

**失败迹象**：人物走到画面边缘停住（没有盖满）；走位方向不是朝向镜头。

#### 3. 前景擦除（foreground wipe）

第三个人物或物体横过镜头，不需要主角配合。

```text
At 00:06.000 a waiter in a black apron crosses the close foreground left to right,
his torso sweeping across the lens and swallowing the whole picture by 00:06.400,
and the camera travels on through that sweep as he clears frame right at 00:06.900.
```

**失败迹象**：遮挡物写成抽象词（`a blur` / `a wipe`）→ 模型给失焦色块，不像实物；
没有给方向 → 遮挡物随机停留；没有写"镜头没停" → 拍成静止画面被挡住又露出，像黑场。

#### 4. 门 / 帘 / 窗的开关

```text
At 00:06.100 the kitchen curtain beside her swings through the frame from frame left in one heavy pass,
filling the picture by 00:06.400 and sliding away to frame right to reveal the same table at 00:06.900.
```

**失败迹象**：写"门关上"但没写它挡住镜头（关在画面深处不构成遮挡）。

#### 5. 贴身特写遮挡

推到极近的材质占满画面。

```text
From 00:06.100 the camera pushes in until only the woven texture of the wine-red silk strap
fills the entire frame, every thread and crease sharp, the room gone from the picture by 00:06.700.
```

**失败迹象**：推到一半停下（仍然能看到背景轮廓）。

#### 6. 手挡镜头

```text
At 00:06.150 her free left hand rises off the table and opens toward the lens,
palm and fingers filling the whole picture by 00:06.550, the warm light glowing through the skin of her fingers.
```

**失败迹象**：手只挡住画面一角；手是另一只（左右手与持物冲突）。

#### 7. 穿过遮挡物（through-pass）—— ⚠️ 本通道有条件

**能做的**：镜头穿过**本段画面里已经存在的**开口——前景椅背的缝、门框、人群之间的空隙、
前景的帘子。这些都在同一次生成里，模型知道那个开口在哪。

```text
From 00:06.000 the camera glides forward through the gap in the wooden chair back in the foreground,
the chair spindles sweeping past on both sides of the lens and filling the picture by 00:06.500,
the room beyond rushing back into view at 00:07.000.
```

**不能做的**："穿过去之后是一个新空间"。这需要尾帧或参考视频告诉模型穿过去该看到什么；
本地通道两样都没有，模型会自己编一个新房间——这正是本文件要避免的事故。

**结论**：through-pass 只用于**同空间内换视角**。要换空间，改用遮挡类 + 后段自己的空间参考图
（后段本来就绑着地理图，从遮挡里起幅更安全）。

**失败迹象**：穿过去之后的光位、陈设、道具和本段前半不一致 → 模型换了空间，撤掉这个手法。

#### 8. 贴面滑过

```text
From 00:06.000 the camera slides along the table surface,
the pale wood grain filling the lower two thirds of frame and then the whole picture by 00:06.600.
```

**失败迹象**：平面没有真的占满（仍能看到人物或背景）。

### 4.2 动作承接类（L-A 写词层）

#### 9. Match on action（动作同帧换视角）

在动作的同一相位换视角。在**同一次生成内**（容器里的 `[Shot N]`）最不易被察觉。

**但两段独立生成时它不成立**：实测帧差 41.87，后段会从参考图姿势重演、丢掉前段末的推进（§6.4.1 第五组）。
两段之间要接动作，**只能用真实末帧接力**（§4.4.17，实测 3.38）。

要求：两段的动作方向、速度、身体部位状态必须一致。把动作拆到"第几拍"，两段对到同一拍。

前段末：

```text
at 00:04.200 her right wrist is still rising through chest height, the loaded fork level with her collarbone.
```

后段首（另一次生成，或同一容器的 `[Shot 2]`）：

```text
[Shot 1] Her right wrist is already rising through chest height at 00:00.000, the loaded fork level with her collarbone,
and it continues upward to her mouth by 00:01.200.
```

同一容器内换视角：

```text
[Shot 2] At 00:04.200, the camera cuts to a tighter angle from her left as her wrist keeps rising through chest height.
```

**失败迹象**：两段的动作阶段差半拍（前段已到嘴，后段还在胸前）；
前段写的是"正在抬手"，后段写的是"手已在嘴边"。改法是把两段的时间点对齐到同一拍，
不是加过渡。

#### 10. 动作中途切（cut on action）

不等动作做完就切，让动作跨段完成。观众注意力在动作上，不在接缝上。与第 9 条的差别：
第 9 条要求两侧的**相位完全相同**，第 10 条允许动作在前段做到一半、在后段做完——
但**只用在同一次生成内的 `[Shot N]`**，两次独立生成之间用它会露馅（后段不知道前段做到哪）。

```text
前段末：at 00:04.200 her wrist has risen to chest height and the fork is still travelling upward.
后段首（同容器）：[Shot 2] At 00:04.200, the shot cuts to a tighter angle as her wrist keeps rising to her mouth by 00:05.100.
```

**失败迹象**：用两次独立生成做这个手法，后段从"手已在嘴边"起演 → 中间那段动作丢失，
观众看到跳帧。改法：装进同一个容器，或退回第 9 条把两段对到同一相位。

#### 11. 视线引导（eyeline match）

前段末她看向画外某点，后段首给出那个目标。

```text
前段末：at 00:05.800 her eyes lock off-screen left, her chin still level.
后段首：[Shot 1] The same gaze direction holds at 00:00.000: her eyes are fixed off-screen left on the man leaning at the window.
```

**失败迹象**：视线方向相反（前段看左，后段的目标在右）——这是越轴，观众会读成两个人。

#### 12. 反应切（reaction cut）

前段末给听者的反应，后段接说话人或新信息。

```text
前段末：at 00:05.900 his jaw tightens and his thumb presses once against the chair back.
后段首：[Shot 1] From his jaw tightening, the same tightness still in his mouth as he starts to speak.
```

**失败迹象**：反应情绪与后段说话内容矛盾（前段震惊，后段轻松）。

### 4.3 硬切与省略（**本来就该切的时候**，L-A / L-B）

**这几种不算缺陷，不要为了无缝而避免它们。** 给它们写"过渡"反而会削弱节奏。

#### 13. 硬切

时间或地点本来就有跳变时，硬切是对的。同一次生成内用 `[Shot N]`：

```text
[Shot 2] At 00:04.200, the camera cuts to the empty banquette from the far side of the room.
```

#### 14. 跳切

同机位、同主体、跳过一段时间。

```text
[Shot 2] At 00:04.200, the camera cuts back to the same seat and the same fixed framing;
her posture has shifted and the cream crater is deeper.
```

#### 15. 省略

直接跳过过程，观众自己补。剪辑层最容易做，也可以写成两段：

```text
后段首：[Shot 1] The plate is clean at 00:00.000 and the fork lies flat on it.
```

#### 16. 插入镜（insert / cutaway）

切到物件或细节再切回来。观众看不到那两段之间发生了什么。

**成本要说清**：装进相邻段的容器里，它是**零额外时长**的内部切点（最省）；
单独生成一个插入段，它要花**至少 107f / 4.458s**（见 §6.4.1c），在小预算里很贵。
先确认它落在哪一层，再谈用不用。

```text
[Shot 2] At 00:04.200, the camera cuts to the short three-tined wooden-handled fork
resting on the white plate, a last smear of cream on the middle tine.
[Shot 3] At 00:05.400, the camera cuts back to her from the same three-quarter view.
```

**失败迹象**：插入镜没有真的"隔开"两段（插得太短，观众没来得及忘掉前一个空间）；插入的内容与前后无关。

### 4.4 真实帧接力：首帧与首尾帧

#### 17. 首帧接力（用上一段真实末帧做下一段首帧）—— ⚠️ 有条件，代价高

**能做的**：把 `first_frame` 设成上一段的真实末帧，让下一段从那个可见状态继续。
这是"只锁起点"的做法；需要连终点一起锁时用第 18 条的 FL2VA（代价相同：都要放弃 full-reference）。

**代价（必须一起写进方案）**：

**这里有两种不同的做法，不要混为一谈**（`minimax-h3.md`「连续段」讲的是第二种）：

| 做法 | 怎么走 | 拿到什么 | 丢掉什么 |
|---|---|---|---|
| **A. 真·首帧接力** | `first_frame`（+ 可选 `last_frame`），**不带任何 `reference_image`** | 动作从真实末帧精确继续 | 身份图、地理图全丢 |
| **B. 末帧当构图参考** | 仍走 `reference_image` 全组，把上一段一帧**追加**为一张 `用途：构图` 的参考 | 身份/地理都还在 | 只是多一个构图提示，**不保证动作连续** |

下面第 1 条讲的是 A；`minimax-h3` 允许的 B 是另一条路，代价与收益都不同。
选 A 是因为"动作必须精确接上"，选 B 是因为"空间要延续但动作只要求大致连贯"。

1. **A 做法会整段放弃 full-reference**。H3 的首/尾帧输入与参考输入互斥，本地 adapter 也会拒绝混用
   （`first_frame` + `reference_image` 同时出现直接报错）。走了 `first_frame`，这一段就没有身份图、
   地理图、道具图——后面几段一旦有角色走动、道具变化，身份和空间会开始漂。
2. **继承上一段的画质损失与漂移**。上一段如果是 draft 档（竖屏 512×896，四步），下一段也会软。
3. **只用真实末帧，不用计划帧**。分镜的关键帧提示词、`PLAN-` 挂图都不是末帧；
   拿它们冒充会让后段从一个"没发生过的状态"起演。

判断是否值得：

| 条件 | 结论 |
|---|---|
| 两段必须共享同一段连续动作，且动作跨不过半拍 | 用 |
| 上一段已通过画风验收、并被批准复用其帧 | 用 |
| 上一段未验收，或两段之间本来有时间跳跃 | 不用。时间跳跃时硬切本来就对；动作要连续但没验收 → 先验收再接力 |
| 下一段还需要身份图/地理图才能站住 | **并回容器**（一次生成里换不了参考组）；装不下时改机位重出，让两段各自成立 |
| ~~走 full-reference + 遮挡~~ | **不作为出路**：#1 背接实测证伪（§6.4.1），其余遮挡手法未测、不能当作已知可行的退路 |

用法：

```text
REF-<本镜>-START（顺序：1）· 剧集/<EP>/制作成果/frames/TAIL-MOTION-<上一段>.png《上一段真实末帧》（用途：起始帧；控制：开场姿态、构图、光位；不得控制：本镜动作进度、终点表情）
```

正文按 `first_frame` 的三段结构写，从该帧状态起演，不另造镜外转换。

**失败迹象**：下一段首帧与上一段末帧差得像换了机位（说明 `first_frame` 没真正生效，
或 adapter 落到了别的模式）；身份开始漂（说明丢了身份图，这个手法在这一段不成立）。

#### 18. 首尾帧配对（FL2VA）—— ⚠️ 有条件可用

`first_frame` + `last_frame` 两张一组，模型在两者之间插值，终点精确可控。这是把两段接起来的
首尾帧为两端提供约束；中间路径、遮挡、身份与接触仍可能出错，须实看，不从两端已锁定推断中段合格。

```text
bindings:
  - role: first_frame   # 上一段真实末帧，或本镜起始关键帧
  - role: last_frame    # 本镜终点帧：她已经转身、他已经伸手
```

两条硬约束：

1. **尾帧不能单独出现**——没有首帧就无处插值，适配器直接拒绝。
2. **与 `reference_image` 互斥**——同一次请求里既要求"精确到达这一帧"又要求"从这些图取身份"，
   服务端只能二选一，适配器拒绝混合。

**代价**：走 FL2VA 就没有身份图与地理图。人物一致性必须靠**你自己已经验收过的首尾两帧**保证，
不是靠角色板。所以它适合"两帧都已经由你确认过"的场景，不适合"靠参考图约束"的场景。

**值不值得**：

| 条件 | 结论 |
|---|---|
| 这一镜的终点必须精确到达（转身完成、手落到某处） | 用 |
| 两帧都是已验收的同一个人、同一空间 | 用 |
| 这一镜还需要身份板/地理板才站得住 | 不用，走 `reference` 全参考组 + 正文写终点 |
| 尾帧只是"大概长这样"的计划帧 | 不用，插值会把计划帧的不准当成目标 |

**用法 B：转场卡**（A、B 已出片，生成它们之间的 C）：`first_frame` = A 的真实末帧（`seam_check.py --extract --frame last` 取），`last_frame` = B 的真实首帧（`--frame first`）。两帧都必须取自最终要交付的那两个文件，按**裸文件名**放进 ComfyUI `input/`。提示词写一个 `[Shot 1]`，只写 A 末态到 B 首态之间那一段连续运动，不重写两端已有的状态。

投递**必须走默认分支**（h3q 不带 `--workflow`）：`--workflow pdd_lu` 用的是 `pdd_render_ref.py`，它没有首尾帧参数、也静默丢弃这两个键，产物会变成纯文生视频且照报 `exit_code 0`。实测对比与判据见 §0.4。

**失败迹象**：末帧到达但中段漂移（说明两帧之间跨得太大，需要拆成三次生成）；
人物在中段变了脸（说明首尾两帧本身不是同一个人，先修图）。

#### 19. 参考视频 —— ❌ 本通道不可用

通道档案没有 `reference_video`。云端 H3 才能把上一段的运动与镜头行为当参考传给下一段。

替代：两段正文把动作拆到同一拍（§4.2），或用 `[Shot N]` 装进同一次生成（§5）。

### 4.5 时间过渡类（表达"过了多久"）

#### 20. 声音桥（sound bridge / J-cut / L-cut）—— L-B 剪辑层

画面切了声音不断，或下一段的声音先入。**感知最低的过渡之一**。

本地每段独立生成声音，跨段音色会漂，所以桥接**必须在剪辑层做**，不能指望两段生成时就对得上。

做法：前段末留一段与后段起点同质的底声（房间嗡鸣、冰箱压缩机、雨声），
后段首 0.3–0.8s 保留同样的底声，剪辑时在两段之间叠 0.3–0.5s 的底声交叉，
让观众听到的是同一条房间而不是两条。

写词时的义务：**两段的 `overall_soundscape` 用同一句底声描述**，不要一段写"安静"、一段写"嗡鸣"。

```text
前段 overall_soundscape: ...the low steady hum of the two lit pendant lamps above the table...
后段 overall_soundscape: The same low steady hum of the pendant lamps carries at 00:00.000...
```

**关键事实**：两段独立生成出来的底声**不是同一条音轨**——它们来自两次采样，房间混响、电噪频谱、
相位都不同。所以"叠 0.3–0.5s 交叉"只能让切换点不刺耳，**不能让两段听起来像同一间房**。

`seam_check.py` 能量化切点两侧的电平差（`audio_seam.delta_db`）与开场爆音（`audio_onset`），这些能自动核对；
但它测不出"是否像同一间房"（混响、音色、空间感的一致性）——这一层仍只能靠**听**，并且要写下听到什么：

| 听什么 | 合格的听感 | 不合格的听感 |
|---|---|---|
| 底声连续性 | 切点前后是同一条房间的嗡鸣 | 切点处"换了一个房间"（混响长短变了） |
| 电平 | 两段响度接近 | 切点处突然变响或变轻 |
| 对白尾音 | 完整 | 被切断 |
| 跨越的动作声 | 在切点两侧各出现一次且位置合理 | 提前出现（声景驱动画面）或缺失 |

**做法**：戴耳机从切点前 2 秒听到后 2 秒，闭着眼睛听一遍。听不出切换 = 声音接上了。
听得出 = 按上表三条路处理。**这一项必须亲耳听，不能用任何指标代替。**

要真的像同一间房，只有三条路，按成本排：

1. **统一铺一层贯穿全片的房间底噪**（L-B，最省）：做一条与场景匹配的底噪循环（冰箱压缩机 + 荧光灯
   镇流器 + 远处街道），贯穿整集垫在最下层，把两段各自的底声压到它下面。这是本片这类连续单场的正解。
2. **从同一段生成里取样**（L-B）：取最长那一镜的底声做全片基准，其他段把自带的底声降下去、补这段。
3. **整段重做声音**（L-C）：分离人声，底声全部重建。成本最高，只在声音本身不合格时做。

**所以写词时的义务是"让两段的底声能被同一条基准盖住"**：都用常见、稳定、低起伏的底声类型
（压缩机、荧光灯、雨、通风），不要一段写"餐厅里有人低声交谈"、另一段写"极静只有钟表声"——
那种底声无法用一条基准统一，桥接就变成两次不同的房间。

**本通道的一条硬限制（容易踩）**：`h3-prompt-writing` 写明"声景是第二动作轨"——绑定了动作的声景
会**反过来驱动画面把那个动作演出来**。所以把"他的脚步声/开门声"写进**前段末的 soundscape**，
模型很可能让他在前段就入画。

**结论：J-cut 在本通道只能落剪辑层，不得写进前段提示词。**
前段 soundscape 只写**本段在场的**声源；要"下段声音先入"，在剪辑时把后段音轨提前 0.3–0.5s，
不要靠前段正文去预告。

**失败迹象**：底声类型不同（一段有冰箱、一段没有）；交叉后仍能听出"换了个空间"（混响长短变了）；
对白尾音被切掉；**前一镜里出现了下一镜才该出现的人或动作**（声景驱动画面的典型症状）。

#### 21. 甩镜（whip pan）

快速横摇，运动模糊糊掉画面。

```text
At 00:06.300 the camera whips right in one fast horizontal pan,
the diner smearing into long horizontal streaks of warm amber and cool cyan,
and the pan decelerates onto the empty banquette at 00:06.900.
```

**失败迹象**：只写"快速摇"没写模糊（模型给出清晰的摇）；摇完没有落点（停在一个随机角度）。

#### 22. 失焦过渡（defocus / rack focus）

```text
At 00:06.200 the focus slides off her face and the frame turns into soft warm discs of pendant light,
the room melting into smooth amber bokeh, and by 00:06.800 the focus pulls back onto her eyes.
```

**失败迹象**：写成 `with no readable detail` 这类否定句（见 §4.0 ②）；
虚化后仍能看出背景轮廓（虚得不够，接缝露出来）。

#### 23. 光线变化（light change / flicker）

```text
At 00:06.100 the pendant lamp above the table flickers once and drops to a deep ember,
the whole room collapsing into one warm pool, then the filament catches and the light floods back at 00:06.600.
```

**失败迹象**：光变幅度不够（只是暗一点，画面仍可比较）；变色温而不是变亮度（两段的白平衡接不上）。

#### 24. 全白 / 过曝（washout）

```text
At 00:06.200 a passing headlight strikes the window glass behind her and the whole frame blooms to pure white for three frames,
then settles back to the warm interior at 00:06.700.
```

**失败迹象**：只过曝到灰白（仍有细节）。要有明确的触发源，否则模型不给全白。

#### 25. 全黑（fade to black）

```text
At 00:06.100 the whole frame fades smoothly to pure black by 00:06.600 and the shot ends in black.
```

**代价（写方案时必须一起写）**：等于承认接不上，还割断动作，节奏会掉。只在真正的段落分隔时用。
**本地通道额外代价**：下一段如果从黑起，模型会用一个"凭空出现"的构图起幅，等于放弃首帧参考。

**失败迹象**：黑场之后节奏明显塌下去 → 说明这一刀不是段落分隔，改用遮挡。

### 4.6 对比与匹配类（撞击、图形、声音）

#### 26. 撞击切（smash cut）

从极静切到极动，或反过来。用反差替代连贯。

```text
[Shot 2] At 00:04.200, the camera cuts to a tight overhead of the ruined cake, the fork standing in it.
```

#### 27. 图形匹配（graphic match）

两段构图、形状、线条或颜色区域相似。**必须在两边正文都写那个形状**，只在一边写的锚点不成立。

```text
前段末：at 00:05.600 the round rim of the white plate holds the centre of frame, the arc unbroken.
后段首：[Shot 1] The round rim of the pendant shade fills the upper frame, the same arc against the dark ceiling at 00:00.000.
```

**失败迹象**：后段没有出现那个形状（只有前段写了）；形状出现了但位置差很远（观众对不上）。

#### 28. 声音匹配（sound match）—— L-B 剪辑层

两段有相似的音（瓷器碰响、金属摩擦），用声音接。写词义务与 §4.6.20 相同：两段的
`overall_soundscape` 用**同一个声源名词**，剪辑层把两个声源对齐到切点两侧 0.2s 内。

```text
前段 overall_soundscape: ...At 00:05.500 the ceramic click of the fork settling on the plate, short and dry...
后段 overall_soundscape: A second dry ceramic click at 00:00.400 on the same plate...
```

**失败迹象**：两段的声源名词不同（一段 `ceramic click`、一段 `a sharp clink`），剪辑时对不上，
观众听到两个不同的东西。

### 4.7 叙事遮挡类（最后手段，成本最高）

#### 29. 插入一个交代镜

补一个短镜把两段隔开。**成本最低的叙事手段**（比改分镜便宜），但仍要重出一次（L-C）。
插入段自己也要有起点、唯一动作和终点，按正常一段写；它不是"空白过渡"。

```text
[Shot 1] A vertical 9:16 photoreal live-action insert of the till drawer hanging open in the dark bar,
its pale interior catching one warm edge from the pendant lamps; the drawer stays still for the whole shot.
```

**失败迹象**：插入段与前后两段没有任何共享的可见事实（同一张桌子、同一盏灯、同一个人身上的东西）——
那样它不是"隔开"，是"插播"。

#### 30. 让角色遮挡动作

```text
From 00:06.000 she turns her whole upper body away from the lens toward the window,
her back and hair filling the frame by 00:06.700.
```

与 #1 背接的区别：背接是**镜头**绕过去，这个是**角色**转过去。角色转身可以由本段的角色参考图控制，
比镜头运动更容易被模型执行。

#### 31. 改机位重出（L-C）

上一段或下一段换机位重出，让构图差异变成"有意的切镜"而不是"接不上"。

**判断依据**：两段的空间已经不一致、且两者都无法用遮挡藏住时。重出前先把新机位写进分镜和场记
（换机位是 `CONT-` 版本变更，不是生成时的临时选择），不在生成时临时改。

重出时改的是运镜句和构图锚点，**不是身份与地理参考**：同一套参考图仍然绑着，
变的只是这一镜的取景。

```text
From 00:00.000 the camera holds a locked-off wide from the far side of the room, the whole table and the window bay in frame;
the subject stays at frame centre as she lifts the fork.
```

**失败迹象**：重出后仍然接不上（说明问题不在机位，而在空间本身已经漂了）；
改了机位但没改场记（下一步读账的 agent 会按旧机位重写回去）。

#### 32. 改分镜（L-D）

把两镜合成一个连续段，或拆成三个镜。成本最高，最后才用。合镜还受 15 秒上限约束。

**三选一的判断依据**（选不出就用第一行）：

| 现象 | 改法 |
|---|---|
| 两镜之间没有必须看见的中间状态 | 合镜（写进同一个 `[Shot N]` 容器或同一个连续段） |
| 两镜之间有必须看见的状态，但跨度太小装不进一段 | 拆成三镜，中间那镜承载那个状态 |
| 接缝问题出在动作相位而非空间 | 先回 §4.2 对拍；对不上才拆 |

改完必须同步刷新三处：分镜的 `SHOT-...`、场记里受影响调度卡的 `CONT-` 版本、以及所有下游
`MOTION-...` 的成员与时长。只改一处会让账本失去权威，下一轮 agent 读到的还是旧事实。

## 五、多镜容器内的切点：和段间是同一套手法，但不共享"接缝风险"

一段内部有多个 `[Shot N]` 时，切点**发生在同一次生成里**：共享同一条音轨、同一套参考图与潜空间，
减少了跨任务接口，但身份、空间与动作相位仍可能出错，需按真实画面核对：

| 项 | 段间（两次生成） | 容器内（同一次生成） |
|---|---|---|
| 身份漂移 | 有，必须处理 | 仍需核对，不由同次采样保证 |
| 空间漂移 | 有，必须处理 | 仍需按锚点和朝向核对 |
| 动作相位连续 | 靠实际末/首状态与路径核对 | 共享生成上下文，仍须实看 |
| 音轨 | 两段独立，需剪辑桥接 | 共享一条，`<scenetrans>` 声明跨切继续 |
| 切点时刻精度 | 由剪辑决定 | 模型会偏（无关键帧的切偏 0.5–1s） |
| 需要的接缝手法 | 遮挡、动作承接、硬切等 | **只需要叙事动机**：被什么挡住、视线落到哪、哪个声音先进来 |

**所以容器内切点用 §4.4 的硬切写法，不需要遮挡**。写遮挡反而浪费时长。

```text
[Shot 1] ... At 00:03.950 her free left hand rises off the table edge and crosses the lens from frame left,
her palm and fingers filling the whole picture by 00:04.200.
[Shot 2] At 00:04.200, the shot cuts to a wider angle from the room side as her palm slides out of the lens to frame right,
clearing to reveal the same table, the same plate and her hand lowering back to the table edge at 00:04.500.
```

这段话在容器里是合法的（G33 已按 `--storyboard` 对账通过）：**遮挡在这里只是给切点一个动机**，
不代表同次生成天然没有漂移；仍以实际切点两侧的角色、空间和动作判定。

**这不与"遮挡类实测证伪"矛盾**：证伪的是"靠遮挡盖住两段独立生成之间的断点"；
容器内的遮挡不承担藏断点的任务，只是让切点有个画面理由。两件事不同，
但**容器内也不需要它**——有动机的硬切就够，写遮挡只会多花时间。

**"段"的定义，本文档统一如下**（不先定这个，后面所有"每一对相邻段"都会有两种读法）：

- **生成段**＝一次提交给执行端的生成（一个容器就是一段，不论内部有几个 `[Shot]`）；
- **镜头**＝容器内的一个 `[Shot k]`。

于是核对分两类，义务不同：

| 核对对象 | 要不要跑 `seam_check.py` | 做什么 |
|---|---|---|
| **段间**（两次生成之间） | 要 | 有漂移风险，按 §九 的时点 A/B 全流程走 |
| **容器内**（同一段里的 `[Shot k]` 之间） | 不要求机械套用段间命令 | 核叙事动机、切点位置、`At` 时间，并实看身份、空间与动作相位；疑点可用同样的并排取证 |

容器内切点两侧也可能换人、换布局或重复动作；共享一次采样不能替代核对。区分设计允许的换景/反打与未申报的视点变化，案例见 EP002空间证明（`../../../../h3-prompt-writing/corpus/ep002-parking-contracts.md`）。

容器内切点的三条约束（来自 `minimax-h3.md` 多镜容器）：

1. 每个切点写明叙事动机，写不出动机的切点并回上一镜；
2. 无关键帧的切放在天然遮挡或运镜过渡处，不要放在需要精确卡点的动作中间（实测偏 0.5–1s）；
3. 容器时长 = 成员时长之和，不超过 15 秒；`[Shot k]` 的 `At` 时刻等于前面各镜秒数累计（G33 对账）。

**只有容器总帧数要落 `17k+5`，成员的帧数不用。** 这条必须写死，否则会推出一个死结：
若要求每个成员都是 `17k+5`，则 n 个成员之和 ≡ 5n (mod 17)，要它等于 17K+5 就需要
n ≡ 1 (mod 17)——**两个及以上成员的容器永远凑不出合法的总长**，多镜容器根本不能存在。

所以成员帧数只由"这一镜的表演需要多长"决定，容器总帧数由执行端时长决定；
`At` 时刻取成员的**秒数**累计，与成员帧数是否整除网格无关。

**"容器时长等于成员时长之和"要读成"成员秒数之和"**，不是"成员帧数之和"。
两句同时成立的方式是：成员各自有自己的秒数 → 相加得容器秒数 → 容器秒数按 §6.3.2 吸附成合法帧数。
吸附多出来的零点几秒落在**最后一个成员**的尾巴上（或均匀摊），不影响 `At` 时刻（它按秒算）。

## 六、节奏与声音：过渡的时间成本要登记

过渡**不是免费的**。它吃掉的是本段的可表演时长，写方案时要算进去。

### 6.1 时间账

下表是**起步量级、不是精确值**（同 §6.1.1 的口径）——用途是在写词前发现「这段装不下」，不是事后校验。

| 手法 | 吃掉多少 | 从哪里扣 |
|---|---|---|
| 遮挡类（1–8） | 段末最后 **0.4–0.7s** 画面无信息 | 从本段动作预算里扣，不从结尾硬加 |
| **背接/环绕达成遮挡** | 见下方时间下限 | 环绕本身要占时间，不能只算最后 0.5s |
| 后段从遮挡起幅 | 后段开头 **0.3–0.8s** 规划时先扣出来（实测为准） | 后段动作在这之后再开始 |
| 甩镜（21） | **0.4–0.6s** 纯模糊 | 从运镜预算里扣 |
| 失焦（22） | **0.5–0.8s** 来回 | 同上 |
| 光线变化（23） | **0.3–0.5s**（瞬时）／**1.5–3.0s**（渐变） | 同上。实测 3.0s 关灯成功：**突变只要 0.3s，但要给观众看清"变暗了"需要 1.5–3s** |
| 全白（24） | **0.1–0.2s**（3–5 帧） | 从曝光预算里扣 |
| 全黑（25） | **0.5–1.0s** 加上下一段重启 | 最贵，只在段落分隔 |
| 声音桥（20） | 不占画面时长，占**声轨** 0.3–0.5s | 剪辑层 |
| 硬切 / 跳切 / 省略（13–15） | **0** | —— |

**环绕类的时间下限（实测）**：`0.4–0.7s` 只是"遮挡发生"那一下的时长，**不含镜头走到那个位置的时间**。
2026-11-05 实测：8 秒（192f）从正面中近景开始环绕，4 秒才到侧面、6 秒仍在侧面，
**到段末都没能转到背后**。可读的结论只有两条：**90° 约需 4–6 秒**；**8 秒内没完成 180°**。
保守取值：**180° 至少 10 秒以上，实测 8 秒不够**。

所以**不要指望在一次生成里完成"正面 → 背接"**：至少要 10 秒纯运镜，实际更可能不够。
换句话说——**背接在本地通道上不仅"难成立"，是"装不进一次生成"**。
（早先这里写"5–7 秒"与实测不符：实测 90° 就要 4–6 秒，180° 远超 5–7 秒。）

所以用背接/环绕时，本段时长要按 `环绕时间 + 遮挡时间 + 动作时间` 算，
不是只加 0.5 秒。段长装不下就改用不依赖环绕的手法（#23 光线变化、#22 失焦、#16 插入镜）。

**硬规则**：一段 6 秒的镜头，写一个 0.6s 遮挡，实际可表演时长只剩 5.4s。
写方案时必须显式算一遍：`本段时长 − 过渡占用 = 可表演时长`，并检查对白与动作能否装进可表演时长。
装不下就换手法（遮挡换硬切、甩镜换光线变化），或者**删掉可省的节拍**；
**不要把动作演快**——压动作会赶词。两者区别：删节拍是剪故事，压动作是毁表演。

对照：`h3-prompt-writing` 的对白预算是「台词字数 ÷ 4.1 字/秒 + 表演动作占用」。

### 6.1.1 表演动作占用怎么估（无台词时唯一依据）

零台词的戏没有字数可算，只能按动作本身估。以下是**起步量级**，不是精确值——
它的用途是让你在写提示词之前发现"这段装不下"，不是事后校验。

| 动作 | 老实演完需要 | 说明 |
|---|---|---|
| 一次呼吸、一次眨眼 | 0.3–0.5s | 单独成拍时才算 |
| 抬手到嘴边、放下手 | 各 0.6–0.9s | 有持物时取上限 |
| 咬一口、咀嚼一次 | 0.5–0.8s | 咀嚼可以只拍前两下 |
| 转头（30–45°） | 0.5–0.7s | 带情绪停顿时再加 0.3s |
| 抬头看、低头 | 0.4–0.6s | —— |
| 起身站直 / 坐下 | 1.0–1.5s | 带重心转移 |
| 走三步 | 1.0–1.4s | 1.5–2m 距离 |
| 走过 3–4m 并停下 | 2.0–3.0s | 含起步与停稳 |
| 开门（推杆式） | 0.8–1.2s | 含门叶摆动到位 |
| 跨过门槛、落脚 | 0.6–0.9s | 含重心交代 |
| 把物件放下 | 0.7–1.0s | 含手指离开 |
| 一次明显的停顿 / 僵住 | 0.6–1.2s | 规划时先扣出来，别被动作挤掉 |
| 翻面（锅铲翻一个蛋） | 0.8–1.2s | 含下铲、翻转、落回 |
| 把食物铲进盘子 | 1.2–1.8s | 含刮、移、倒 |
| 端盘走 2–3m 并放下 | 2.5–3.5s | 含起步、走、弯腰、松手 |
| 转身 90° | 0.8–1.2s | 带重心转移 |
| 坐下（到坐稳） | 1.5–2.2s | 含拉椅、落座、调整 |
| 拿起餐具 | 0.5–0.8s | 手指合拢到离桌 |
| 视线从一处移到另一处 | 0.4–0.7s | 幅度小时取下限 |
| 展开一张纸／信封 | 1.0–1.6s | 含抖开与理平 |
| 折纸（两三折） | 1.2–2.0s | 每折 0.4–0.7s |
| 把东西塞进包里 | 1.0–1.6s | 含开包口、塞入、压一下 |
| 推开汽车门并下车 | 2.0–3.0s | 含解锁、推门、抬腿、站定、关门 |
| 有内容的注视（看窗外） | **1.5–3.0s** | 太短观众来不及读；这是叙事停顿，不是空白 |

**估算方法**：把这一镜要发生的动作逐条列出，加上停顿，得到一个总数；
再与 `可表演时长` 比。超出就换手法或改分镜，不要压动作。

**专门提醒"停顿"**：反应、僵住、决定前的静止是这类片子的价值所在，而它最容易被动作预算挤掉。
写方案时把停顿当作一条**必须占时**的动作先扣出来，剩下的才分给动作。

**一个常见误判**：让角色在另一段动作进行时"保持不动"，看着像省了预算，实际会让观众觉得
"她怎么不动"。这类"被动的静止"要么写成**有内容的停顿**（写清她在看什么、在想什么），
要么给一个微小的可见动作（呼吸、手指收紧、视线移动）。
过渡占用是**第三项**，之前没算进去。

### 6.2 声音账

| 手法 | 声音怎么处理 | 写在哪 |
|---|---|---|
| 遮挡类 | 遮挡物自己的声音先入或延后（脚步、布料、门轴） | 前段 `overall_soundscape` 末句 + 后段首句 |
| 甩镜 | 环境声在甩动中"变远"再"变近"，不切断 | 前段末写环境声持续；后段首写同一环境声 |
| 失焦 | 声音不虚；画面虚、声音实是常态 | 两段底声一致 |
| 全黑 | 声音可以延续到黑之后（比画面长 0.3s） | 前段末句 + 剪辑层 |
| 声音桥 | 两段共用同一句底声描述 | 两段 `overall_soundscape` 首句 |
| 硬切 | 声音一起硬切，可以有 1 帧静音 | 不需要写 |

**跨段对白绝不断开**：一句台词不要跨两次生成。本地每段重新生成人声，跨段会换音色。

**写词义务**：给一条接缝指定声音手法时，两段的 `overall_soundscape` 都要写到它，不能只写一边。
`h3_gate.py` 只检查对白格式（G13/G14/G16/G18），不检查底声是否两侧一致——这条靠自看。

## 六点四、两个会毁掉整段的前提

### 6.3.1 画布规格：768×1344 不是精确 9:16，这是硬约束不是笔误

必须写清，否则跨 draft/final 比指标时会对不上：

- `768 × 1344` 的宽高比是 **0.5714**，而 9:16 是 **0.5625**，差约 1.6%；
- 真正的 9:16 在宽 768 时需要高 **1365.3**，不是 32 的倍数；
- 执行端要求宽高都是 **32 的倍数**，所以在 768 宽这一档里**不存在精确的 9:16**。

因此 `768×1344` 是"32 倍数约束下最接近 9:16 的竖屏画布"，是**约定**，不是需要修正的错误。
工程上要守住的是：**同一集的所有段用同一个画布**，不要一段 768×1344、一段 896×1344——
那样 `seam_check.py` 量出来的 `structure_mad` 会混入重采样误差，跨段不可比。

**draft 档是目标尺寸的 2/3（吸附 32）**：`768×1344` → `512×896`，同样是 0.5714，比例一致。
所以 draft 上量的指标可以**定性地**用于判断接缝性质（接上 / 换了空间），但**不要拿 draft 的绝对数值
去和 final 的绝对值比**：分辨率不同，`structure_mad` 的量级会变。要比就同档比。

---

### 6.3.1a 零台词、动作不够填满目标时长时怎么办

零台词的戏没有字数可算（对白预算的 `字数 ÷ 4.1` 用不上），只能靠动作。常见困境：
**动作只够 17 秒，目标 26 秒**。四条出路，按优先：

| 出路 | 怎么做 | 观感 |
|---|---|---|
| **1. 加有内容的停顿** | 把"看、等、犹豫"写成明确节拍（看什么、看多久、看到什么变化） | **最好**：短剧的张力就在这些停顿里 |
| **2. 加环境动作** | 蒸汽升起、窗外车灯扫过、锅里的油响、光照变化 | 好，且不占人物表演预算 |
| **3. 减少镜数、拉长单镜** | 同样的动作装进更少的段，单段更长 | 可行，但要看表演撑不撑得住 |
| **4. 缩短目标时长** | 向创作者说明动作只够 N 秒 | 最后手段，要创作者同意 |

**不要做的**：为了填满时长把动作放慢、加无意义的来回走动、或让人物"保持不动"。
后者看起来省事，实际会让观众觉得"她怎么不动"——**被动的静止必须写成有内容的停顿**：
写清她在看什么、在想什么、脸上有什么细微变化。

**判据**：如果一段里连续 2 秒以上既没有动作变化、也没有环境变化、也没有新的信息，
观众就会开始走神。**这 2 秒要么给它内容，要么剪掉。**

---

### 6.3.1b 目标总时长几乎不可能精确达到——先说清怎么取舍

甲方给的是"26 秒"，而每一段都要落 `17k+5`，所以总长是**若干合法段长之和**，不是任意数。
实测可达性：

| 目标 | 2 段最接近 | 误差 | 3 段最接近 | 误差 |
|---|---|---|---|---|
| 20s | 486f = 20.250s | +0.250 | —— | —— |
| 22s | 520f = 21.667s | **−0.333** | 525f = 21.875s | −0.125 |
| 24s | 571f = 23.792s | −0.208 | —— | —— |
| 26s | 622f = 25.917s | −0.083 | 627f = 26.125s | +0.125 |
| 28s | 673f = 28.042s | +0.042 | —— | —— |
| 30s | 690f = 28.750s | **−1.250** | 712f = 29.667s | −0.333 |

**注意 30 秒这一行**：两段最长只能到 28.75s（`345+345`，每段上限 15.083s），
差 1.25 秒**不是误差而是装不下**——30 秒的目标至少要三段。

**结论与写法**：

1. **不要承诺"精确 26 秒"**。方案里写"目标 26 秒，实际 25.917 秒（622f，两段）"，
   并说明误差来自帧网格——这是硬约束，不是失误。
2. **优先贴近目标，其次少拆一刀**。26 秒两段 25.917（误差 0.08）比三段 26.125（误差 0.13）更准，
   但三段多一刀接缝。**默认选少一刀**：宁可总长差 0.13 秒，也不要多一处可能断裂的接缝。
3. **误差方向优先取长**，但**这条让位于第 2 条**。当"更贴近目标"与"更少段数"冲突时，**选更少段数**。
   只有段数相同时才用"取长"打破平局。
4. 交付前把实际总长、段数、段长、误差一次性列出来，让创作者看到差在哪。

### 6.3.2 秒 → 17k+5 帧：24fps 对照表（每次提交都要用）

执行端只认 `--frames`，而方案是按秒写的。`17k+5` 与 24fps 的整数秒**几乎处处对不齐**：

`24n ≡ 5 (mod 17)` 只有 `n ≡ 8 (mod 17)` 有解——**在 4–15 秒区间里，只有 8 秒正好落格**。
其余整数秒全部要吸附。**吸附方向固定朝上**（向下会截掉尾动作，向上只多几帧）。

| 想写 | 24fps 原始 | 必须提交 | 实际时长 |
|---|---|---|---|
| 4s | 96f | **107f** | 4.458s |
| 5s | 120f | **124f** | 5.167s |
| 6s | 144f | **158f** | 6.583s |
| 7s | 168f | **175f** | 7.292s |
| **8s** | 192f | **192f** | 8.000s（唯一正好落格） |
| 9s | 216f | **226f** | 9.417s |
| 10s | 240f | **243f** | 10.125s |
| 11s | 264f | **277f** | 11.542s |
| 12s | 288f | **294f** | 12.250s |
| 13s | 312f | **328f** | 13.667s |
| 14s | 336f | **345f** | 14.375s |
| 15s | 360f | **362f** | 15.083s（上限） |

**写法约定**：

- 方案里的「时长」写**真实秒数**（小数，如 `7.292s`），不要写 `7s`——`7s` 会被执行端吸成 `7.292s`，
  方案与实际差 0.292s，时间账就是假的；
- 提交参数只写 `--frames`（整数），不写 `--seconds`；
- 容器总帧数按上表吸附；**成员帧数不必落格**（见 §5）；
- 时间账要用**吸附后的真实秒数**算，不要用你写的整数秒。7s 想装 7s 的动作，实际只有 7.292s 可用，
  但如果你按 7s 设计，最后 0.292s 会多出无内容的尾巴。

### 6.4.1 容器内新增人物：他的参考图会污染前面的镜

一条容器里装多个 `[Shot]` 时，参考图整段共享。既有案例观察到后段人物提前出现，不能据此推断所有否定失效或每个容器必然提前入画。

**按本镜评估**：

- 新人物首次登场与前段同容器时，核对入画时机及观众知情；有提前出现风险或实测失败时，可把容器边界移到登场前，不以在场集合不同自动禁用容器。
- **但一个容器只有一组参考图，不能逐镜挂不同的图**——所以"前面的镜不挂他的图"在同一个容器里做不到。
  真正的做法只有两条：**拆容器**（边界画在他出现之前），或者**接受他可能提前出现**并在正文里
  把前面几镜写成"他不在场也可以成立"的构图（例如她独占的中近景，画内根本没有能站人的空间）。
- 出场本身写成**可见的进入过程**（脚跨过门槛、影子先入画、门开的角度变化），不要只靠"他站在那里"。

判断依据：把容器内每一镜的"在场人物"列出来，**只要有一镜的在场集合与其他不同，就要考虑拆容器**。

**道具同理，而且更容易翻车**：一条容器里挂了他手里那把刀的道具图，前面几镜里那把刀也可能出现，
甚至出现在它"还没被拿出来"之前——**道具图和人物身份图一样是整段共享的正向条件**。

- 道具**第一次出现的那一镜**之前，不要把它和前面几镜装进同一容器；
- 已经收起/放进包里的道具，在续接的下一段仍可能**回魂**，因为上一帧里有它：
  **消失要写成可见动作**（放进包里、手离开画面），不要靠"不再提它"；
- 需要精确控制出现/消失时点，就不要用容器，拆段并用接力。

**身份板本身的三条要求**（不满足的话，上面两条都救不了）：

| 要求 | 为什么 | 违反的后果 |
|---|---|---|
| **单人**，画面里只有这一个角色 | 身份板是给模型"这个人长什么样"的，多出一个人就多一个正向条件 | 别人物被拉进不该出现的镜 |
| **背景中性**（纯色棚拍或纯灰） | 板上的布景会被当成地理信息继承 | 板上有楼梯 → 那个楼梯会出现在所有挂这张板的镜里，等于多一张地理图 |
| **中性站姿**（正面直立、手臂自然下垂），不要写"正在做某事" | H3 无否定通道：参考画面里的姿态会被当作**持续状态** | 板是"站着看手机"，成片里他会一直站着看手机 |

第三条最容易被忽略：**身份板只承担"长相"，不承担"他在做什么"**。动作必须写在每一镜的正文里，
不要指望板上那张图。已经做好的板如果带了动作或带布景，宁可重做一张干净的，也不要在提示词里
写"忽略背景"——否定句在 H3 里无效。

**实测证据（2026-11-05，本地 h3q draft，512×896，三组）**

第一组：正面三视图身份板 + 明确写满"镜头环绕到背后、肩背占满画面"的正文。

| 段 | 正文要求的边界帧 | 实际 |
|---|---|---|
| A 末帧（8s/192f） | 肩背/深色织物占满画面 | 她**正面**站着、脸清楚受光、背景是灰墙 |

所以这个组合里身份只能靠那一帧，容器内也不能另挂角色板。

| 段 | 要求 | 实际 |
|---|---|---|
| L 22f（0.92s） | 全画面拖成横向条纹 | ❌ **只模糊了背景**：人物（脸、裙子、手）**完全清晰**，只有背景出现横向拖影 |

**这是甩镜的典型失败形态，也是最好认的判据**：真正的甩镜里**主体也该被拖开**；
如果只有背景糊、人还清楚，那不是甩镜，是"背景径向模糊"滤镜，接缝一点没被遮住。

**结论（三条，都有实测支撑）**：

1. **参考图的姿势会压过正文的动作描述。** 换了侧视图之后，模型照样把画面摆回"能看见脸"的角度——
   而且把参考图里那个"身后有人"的构图也继承了（C 组末帧多出一个人）。规范写得再清楚也压不过它。
2. **环绕到背接需要的时间比文档写的长得多。** `0.4–0.7s` 只是遮挡发生那一下，
   走到那个位置另需约 16 秒（按 8 秒完成约 90° 推算），远超单次 15 秒上限。

所以：

- 遮挡类/环绕类手法，**不要用"正面三视图"那张板当唯一参考**——它是"站定看镜头"的强条件；
- 需要背面/侧背时，挂一张**背面或侧背的板**，或在项目里另做一张该角度的视图；
- 正文写"镜头环绕到背后"之前，先确认参考组里没有"正面站定"的图在与它对抗。

### 6.4.1b 同场有两个功能区时，地理图怎么挂

一场戏里常有两个功能区（灶台 + 窗边桌、门口 + 吧台、床 + 窗）。**一个容器只有一组参考图**，
所以不能"前几镜挂灶台图、后几镜挂桌面图"。三种做法，按优先：

| 做法 | 怎么做 | 代价 |
|---|---|---|
| **1. 拆成两个单元** | 灶台动作一个容器、桌面动作另一个容器，各自挂对应的地理图 | 多一处段间接缝，必须用传送带（接力）或硬切处理 |
| **2. 合成一张"空间关系图"** | 画一张能同时看到两个功能区的图（俯视或轴测），整段挂这一张 | 图内必须有可核对的相对方位（灶台在左、桌在右、门在后方），否则模型自己编 |
| **3. 只用一张主图 + 正文写另一区** | 挂主要活动区那张，另一区只靠正文描述 | **风险最高**：没挂图的区域模型自由发挥，容易和后续镜头对不上 |

**判断依据**：两个功能区之间**人物是否走动**。走动 → 必须有空间关系图（做法 2），否则走位对不上；
不走动（切镜到另一区）→ 做法 1 更稳。

**不要做的**：把两张功能区图一起挂上去当"两个参考"。模型会当成两个空间，拼出中间不存在的过渡区
（两张地理图会被当成两个空间）。

### 6.4.1c 单独成段的一个手法要花多少预算

任何"单独成一段"的手法（插入镜、反应切、纯空镜）都受同一条约束：
**一段最短就是 `107f / 4.458s`**（`17k+5` 的下限，4 秒档）。

所以：

| 做法 | 成本 | 什么时候划算 |
|---|---|---|
| 单独成段 | 至少 **107f（4.458s）** 占掉总时长 | 这一镜本身有独立叙事价值（信息镜头、反应镜头） |
| 装进相邻段的容器 | **0 额外时长**（内部切点不占总长） | 只是换视角看同一场戏 |

**判据**：先算"总目标时长 − 已排段长 = 剩余"。剩余 < 107f 就**不能**再单独插一段，
只能并进容器或删掉。实测第六组的插入镜成功，但它占了整整 107f——在 26 秒的预算里
那就是约六分之一，但一段 12 秒的戏里它就占近四成，必须先算再决定。

### 6.4.2 遮挡物够不到镜头时，遮挡类不成立

§4.1 的八条遮挡手法有一个共同前提：**遮挡物必须在镜头前方 0.3–0.5 米内经过**，能盖满画面。
这不是风格问题，是物理问题：

- 门在你 3 米外被推开 → 它扇不动镜头，遮不住任何东西；
- 只有一个人在场、他离镜头也远 → 没有前景可以擦过；
- 空镜、远景、大场面 → 没有近处实体。

**这类场景不要硬写遮挡**（写了模型会试图把那个物体拉到镜头前，造成比例失真或瞬移）。
改用这几类，它们不要求近处实体：

| 可用 | 为什么不需要近处物体 |
|---|---|
| **#11 视线引导** | 靠前段末的视线与后段首的目标呼应 |
| **#23 光线变化** | 吊灯闪一下、车灯扫过——光源变化本身就是遮挡 |
| **#22 失焦** | 焦点拉虚，画面只剩光斑，也不需要近处实体 |
| **#16 插入镜** | 切到物件细节再切回，用镜头本身隔开两段 |

**判断顺序**：先看"有没有一个能走到镜头前的实体"。没有 → 直接跳到上表，不要浪费时间设计遮挡。

## 六点五、轴线：同场换机位不换空间的那条线

前面所有手法都在解决"怎么把两刀接上"，但有一类断裂**再好的过渡也救不了**：**越轴**。
观众看到的不是"切了一刀"，而是"这两个人怎么换位置了"或"这是不是另一间房"。
本节补的正是这个判据——它也是"设计好的换机位"与"换了空间"唯一可靠的分界线。

### 6.5.1 先定轴

一场戏在开拍前必须有一条**固定轴**，写在《场记.md》的调度卡里（`轴线侧` 字段）。轴由**主要关系**决定：

| 场景类型 | 轴是什么 |
|---|---|
| 两人对话 | 两人视线的连线 |
| 一人对固定物（吧台、柜、门、窗） | 人物躯干朝向与那个物的连线 |
| 一人独自活动 | 人物的躯干朝向 + 主光源方向共同固定的一侧 |

**写下来的形式**：`轴线：她的躯干朝画面右，玻璃门恒在背景左侧，所有机位在走道一侧`
——一句话里同时有"人物朝哪""固定物在哪""机位站哪边"。三者缺一，换机位时就无法判断是否越轴。

### 6.5.2 同场换机位的三条硬约束

换机位只要同时满足这三条，观众读成"还在同一间屋"，哪怕画面差 40+ 也是设计的：

1. **轴线侧不变**：所有机位留在轴的同一侧。跨到另一侧就是越轴，除非中间有建立镜或可见的位移过程。
2. **固定锚点在画面里的相对方位不变**：玻璃门始终在背景左侧、吊灯始终在左上、台面黑线始终横贯下部。
   位置可以移动，**左右/上下的先后次序不能翻**。
3. **30° 规则**：同主体换角度至少 30°，否则读成跳切（而不是换机位）。

### 6.5.3 越轴的四种补救

已经越了轴、又不愿重出时，按成本从低到高：

1. **加建立镜**（L-A 写词）：在两镜之间插一个能看清空间关系的全景，再回到另一侧；
2. **让位移可见**：让镜头或人物在段内走过轴线，观众看到"绕过去了"（这就是 §4.1 背接的另一种用法）；
3. **用中性镜头过渡**：切一个正对轴的镜头（人物正对或正背镜头），它不属于任何一侧；
4. **重出**（L-D）：改机位到正确一侧。

### 6.5.4 越轴在核对表里长什么样

§7.4 的四行里，越轴的典型表现是：

- **"同一空间"那行对不上**：不是墙变了，而是**同一件固定物的左右位置翻了**（门从画面左跑到右、
  窗从背景左跑到背景右）。这种"翻面"比换房间更常见，也更容易被误判成"合理换机位"。
- **人物朝向自相矛盾**：她上一镜朝画面右，这一镜朝画面左，但中间没有任何转身动作。

**判据**：打开并排图，先看那几件固定锚点的左右次序。**次序翻了就是越轴，不是换机位。**

## 七、核对：命令、指标、判断表

### 7.1 为什么不能只靠"并排看一眼"

本仓库实测（`example-project`，6 镜竖屏，本地 h3q）：agent 逐段看得很仔细，每段内部都合格，
但从没把前段末帧与后段首帧并排比过。实测这三对接缝：

| 接缝 | structure_mad | edge_agreement | 段内单帧最大跳变 | 跳变倍率 | 并排看之后 |
|---|---|---|---|---|---|
| 001→002 | 1.72 | +0.927 | 1.40 | 1.2× | 接上 |
| 002→003 | 40.36 | −0.024 | 1.29 | 31.3× | **设计好的换机位**，不是事故 |
| 003→004 | 45.37 | −0.014 | 1.43 | 31.7× | **真断裂**，须回改 |

**这张表本身不能告诉你哪一刀是对的。** 同一部片的分镜里，SHOT-002 要求"中近景、正面、胸口正对镜头"，
SHOT-003 要求"她右后方过肩、俯视 15°"——这两镜本来就是**两个完全不同的机位**，
画面差 40 是设计的必然结果，不是漂移。而 003→004 同样是 45，却是一次真实的断裂：
把 003 末帧与 004 首帧并排看，背景从暖色暗室内变成窗外的青蓝夜景、他在画面里的位置与高度整个换了。

**这就是这一节存在的理由**：同一个数字既可能是"合理的换机位"，也可能是"换了地方/换了人"。
指标只能把注意力引过去，判断只能由并排图 + §7.4 判断表做。

更关键的一条：**绝对帧差不能当判据**。004 段自己内部首帧→末帧就漂了 47.5，
和 003→004 的接缝（45.4）同量级——一段持续推镜的镜头，自己内部就能走出接缝级别的数字。
任何"超过 X 就是硬切"的阈值都会把正常推镜判成硬切，或者把真硬切放过。

所以核对分两步：**先量（用单帧阶跃作分母），再按判断表看**。

### 7.2 命令

```bash
cd <项目>

# 一条命令出全部证据：真实末帧、真实首帧、并排图、区域热图、指标 JSON
python3 <本技能目录>/scripts/seam_check.py \
  --before 剧集/EP001/制作成果/video/MOTION-EP001-002-draft.mp4 \
  --after  剧集/EP001/制作成果/video/MOTION-EP001-003-draft.mp4 \
  --out    审查/seam --label 002-to-003

# 只想取真实末帧（例如给下一段做 first_frame）
python3 <本技能目录>/scripts/seam_check.py \
  --extract 剧集/EP001/制作成果/video/MOTION-EP001-002-draft.mp4 \
  --frame last --to 剧集/EP001/制作成果/frames/TAIL-MOTION-002.png
```

产物：

| 文件 | 用途 |
|---|---|
| `<label>-side-by-side.jpg` | 并排图，判断"同一个人/同一空间"只能靠它 |
| `<label>-grid.jpg` | 3×4 热图叠在后段首帧上，标出差异落在哪一格 |
| `<label>-before-end.png` / `<label>-after-start.png` | 真实取出的两帧，可单独打开 |
| `<label>-seam.json` | 全部指标 + 取帧来源；写进接缝契约时引这个文件 |

取帧实现（脚本已做，手做时要照抄）：

```bash
# 真实末帧：按帧号取，不用 -sseof
ffmpeg -v error -i <video> -vf "select=eq(n\,174)" -fps_mode passthrough -frames:v 1 -y tail.png
# 真实首帧
ffmpeg -v error -i <video> -vf "select=eq(n\,0)" -fps_mode passthrough -frames:v 1 -y head.png
```

**`-sseof` 的坑**：`-sseof -1 -i <v> -frames:v 1` 取到的是末 1 秒窗口里的**第一帧**，不是最后一帧。
要留下最后一帧必须配 `-update 1`（每帧覆盖同一路径）。脚本在拿不到 `nb_frames` 时才走这条路，
并在 JSON 里写清用了哪种方法。

### 7.3 指标含义（脚本已算，判断由人做）

| 指标 | 含义 | 怎么用 |
|---|---|---|
| `mean_abs_diff` | 384 宽全幅平均像素差（0–255） | 只看量级，不单独作判据 |
| `structure_mad` | 降到 12px 宽后的平均差，**丢掉纹理、留下布局与大色块** | 判"是不是同一个空间"的主指标 |
| `edge_agreement` | 边缘方向一致度：+1 同向，0 无关，−1 反向 | 判"同一个空间/同一机位轴"；两段独立生成换了房间时会掉到 0 附近 |
| `histogram_distance` | 三通道色调分布距离，0 = 相同 | 分布差大而 edge 对得上 → 布光或调色变了，不是换地方 |
| `regions[]` | 3×4 格各自的平均差 | 定位差异在哪（"第 3 行第 2 格"就是桌面） |
| `within_shot_envelope` | 前后两段**各自段内**的相邻帧差（中位数、p95、`structure_mad_max_step`） | 给量级参照；`max_step` 是跳变倍率的分母 |
| `edge_agreement_min`（在 envelope 里） | 该段段内最小的边缘一致度 | 低于这个值说明接缝比段内任何一帧都更"不像" |
| `seam_step_ratio` | 脚本已算好的倍率及其分母 | 直接抄进接缝契约；1–2 倍正常，高两个数量级先看图 |

**用法不是比阈值，是比量级**：

```text
接缝 structure_mad ÷ max(前段段内【单帧最大跳变】, 后段段内【单帧最大跳变】) = 跳变倍率
```

**分母必须是单帧最大跳变，不是段内首末漂移。** 这一条是实测踩出来的，不是偏好：

| 分母取法 | 001→002 | 002→003 | 003→004 | 结论 |
|---|---|---|---|---|
| 单帧最大跳变（正确） | 1.2× | 31.3× | 31.7× | 一刀接上、另两刀须看图分开 |
| 段内首末漂移（错误） | 0.3× | 2.5× | **0.9×** | 第三刀被判成"比段内还小"，直接放行 |

原因很直接：**接缝本身就是一个单帧阶跃**，它该和"这一段的相邻两帧最多能差多少"比，不该和
"这一段从头到尾漂了多少"比。004 段是一段持续推镜，首帧到末帧漂了 47.5——用它当分母，
40 以上的真接缝会被除成 1 倍以下，等于把所有大漂移镜头里的接缝都放过。

本仓库实测标定（同一批素材，24fps，768×1344，12px struct 口径）。前三行是
`seam_check.py` 在这三对接缝上的实际输出（`structure_mad` / `edge_agreement` / `seam_step_ratio`），
可直接复现；后三行是同一批素材的段内对照，用来说明这个倍率为什么必须拿单帧阶跃当分母：

| 关系 | structure_mad | edge_agreement | 跳变倍率（分母） |
|---|---|---|---|
| 真接缝、同一空间（001→002） | 1.72 | +0.927 | **1.2×**（1.40） |
| 真接缝、换了整个空间（002→003） | 40.36 | −0.024 | **31.3×**（1.29） |
| 真接缝、换了整个空间（003→004） | 45.37 | −0.014 | **31.7×**（1.43） |
| 段内对照：001 段首 vs 末（同一空间，同一机位） | 5.52 | +0.779 | —— |
| 段内对照：003 段首 vs 末（同一空间，机位已移动） | 16.01 | +0.428 | —— |
| 段内对照：004 段首 vs 末（同一空间，持续推镜） | **47.53** | **+0.014** | —— |

最后三行是**关键**：同一段镜头内部就能出现 struct 47.5、edge 0.01 的值。所以单看
"struct 44 / edge 0"**不能**判成接缝失败——它和"004 段内部"完全同量级。必须同时确认这三件事：

1. 这两帧真的是前后两段的边界帧，不是段内两帧（脚本从视频取的，不是人手挑的，这一条天然成立）；
2. 接缝的单帧阶跃远大于两段各自的单帧最大跳变（倍率数），而不是大于它们的整体漂移；
3. **打开并排图，看得见换了什么**（§7.4 判断表）。

三条同时成立才是接不上。缺第 3 条时，数字只能告诉你"去看这一格"。

**为什么倍率不能当阈值**：本仓库只标定了 3 刀（1.2× 接上、31× 换空间），样本量不足以给一条
"超过 N 就是硬切"的线。倍率的作用是**把注意力引到该看的地方**，判断仍然由并排图做。
写方案时不要给创作者一个"通过阈值"，那会把判断类问题变成机械闸门——本项目明确不做这件事。

对每一对接缝，在《视频提示词.md》的「接缝契约」表里补一列，写下三件事：

```text
| 切点 | 前镜末状态 | 后镜起状态 | 连接方式 | 成本层 | 新增信息 | 不切的后果 | 核对 |
| 001→002 | ... | ... | 硬切 | L-A | ... | ... | seam-check 001-to-002：struct 1.72 / edge +0.927 / 倍率 1.2。并排看：她左耳银圈位置一致、马尾高度一致、毛衣领口罗纹宽度一致；吊灯在左上同一位置、酒架纵线数一致；他不在画内 → 接上 |
| 003→004 | ... | ... | 改机位重出 | L-C | ... | ... | seam-check 003-to-004：struct 45.37 / edge −0.014 / 倍率 31.7。并排看：背景由暖色室内墙变成窗外青蓝夜景、窗框消失；他在画内的水平位置从右三分之一移到中央、机位高度由眼平变俯视；她的锁骨白痕在 004 首帧不见 → 接不上，须回改 |
```

**只有真的打开并排图看过才能写"并排看：…"**。没看过的写「未看」，不得用脚本输出、指标数字、
文件存在或 contact sheet 冒充。

### 7.6 什么时候必须停下来重做

| 看到什么 | 处理 |
|---|---|
| 四项里有一项明显对不上，且这一刀不是有意的时间/地点跳跃 | 不许往下生成。按 §1 分类选手法回改；改不了就重出一段（L-C） |
| 四项里有一项对得上、其余三项对不上 | 几乎一定是换了空间，不是造型问题。先查两段绑的地理图是否同一张 |
| 两段的段内 envelope 已经覆盖这个差值，且并排图看不出四项有变 | 是镜头运动造成的，不是接缝问题，放行并记下"段内运动大" |
| 同一接缝连续两次修补仍不成立 | 停止局部打补丁，整段或整份分镜重写（改分镜，L-D） |
| 前段末帧与后段首帧差得很少，但动作接不上 | 这是动作相位问题，不是画面问题。回 §4.2 对拍，不看指标 |

## 八、明确不许用的

| 手法 | 为什么不行 |
|---|---|
| 叠化 / 溶解（有人物帧时） | 人物与前景半透明重影（双重曝光）。实测：只有**全屏无细节色块帧**上的叠化才不留鬼影 |
| 无动机的全黑 | 等于承认接不上，还割断动作，节奏会掉 |
| 补帧 / 光流插值 | 会生成不存在的中间状态，脸和手最容易崩 |
| 靠剪辑选点"修"接缝 | 选点只能去掉多余部分，补不出缺失状态 |
| 加字幕 / 贴纸 / 特效遮住接缝 | 观众知道你在遮，反而更注意那里 |
| 把"接缝留给剪辑"当方案 | 剪辑还没开始，所以现在就是硬切——这是本项目事故的原话 |
| 把上一段尾帧塞进 `reference_image` 冒充续接 | 只带来上一段的画质损失和漂移，带不来动作与声音连续。要接力就走 `first_frame`（§4.4.17），并接受失去 full-reference |

## 九、交稿前的接缝核对（照做）

核对分两个时点，**不要把它们合成一步**——合成之后就变成"要等后段生成完才能判断前段该不该生成"，
顺序是死的：

**时点 A · 生成下一段之前（只有前段产物，没有后段）**

这部分只能看前段，不能跑 §7.2 的双段命令（后段文件还不存在）。逐项确认：

1. 前段的末帧是否落在你设计的状态上（遮挡是否真的盖满、动作是否停在对的相位、
   终点是否到了正文写的位置）；
2. 前段的末帧里，那几件**共享锚点**是否都可见、都还在原位（吊灯、台面黑线、门框、
   某件道具）——它们要在后段首帧里被复述，前段没拍到就无处可复述；
3. 前段的过渡动作是否留出了 0.3–0.5 秒余量，后段开头是否有 0.3–0.8 秒的接续空间。

任一条不成立，**先修前段**，不要指望后段去圆。

**时点 B · 后段生成之后（两段都有产物）**

1. 跑 §7.2 的命令，拿到并排图与指标；
2. 打开并排图，按 §7.4 四行逐项看，写下看到的具体特征；
3. 打开热图，确认差异最大的区域与第 2 步的观察相符；
4. 回答：**这一刀是合理切镜，还是接不上？**
   - 合理切镜 = 换机位或换时间点，观众预期会跳，且跳得有意义；
   - 接不上 = 观众会以为换了个地方或换了个人；
5. 接不上时按 §1 重新分类、按 §3 确认通道能做什么、按 §4 选一种手法回改；
6. 回改后重跑第 1 步，把两次的 `seam.json` 都留着——修好了才有意义；
7. 把结论写进接缝契约表（§7.5）。
8. 结论是"接不上"时，**后段不得进入下一步**（下一段生成、剪辑、交付都不行）；
   时点 A 的三条只防"前段就错了"，救不了两段拼起来才暴露的问题。

一镜一镜单独看永远发现不了这件事：**每段内部都可以是合格的，接起来才是废的。**

### 9.1 谁来判断，谁签字

**判断由"看过这两帧的人"做，不由脚本做。** 脚本只产证据（末帧、首帧、并排图、热图、指标）。
这条不是谦辞，是分工：

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| `seam_check.py` | 取真实边界帧、拼并排图与热图、量指标 | 不说"接上了"，不给通过/失败 |
| 写词的 agent | 按 §7.4 逐项看并写下具体特征；写方案时算时间账 | 不能用"看起来可以"代替逐项观察；没看过就写未看 |
| `short-drama-review` | 独立复核画风和剧情；对"这一刀能不能进剪辑"出结论 | 不代替写词者做接缝设计 |
| 创作者 | 对**成片观感**有最终判断权；可以推翻以上任何结论 | —— |

**签字的含义**：在接缝契约表里写下"并排看：<具体特征>"那一行的人，对"这一刀成立"负责。
所以那一行必须是**可核对的具体观察**（银圈位置、马尾高度、门框左右次序），不是"一致""可以"。
写不出具体特征就说明没真看，等于没签。

**独立复核怎么触发**：一处接缝被判"接不上"并回改之后，改完的那一版要找**没参与写词的人**
复核一次。理由和 `short-drama-review` 要求换 reviewer 一样——自己改、自己判，会把"我改对了"
当成事实。

**创作者不需要看技术项**。给创作者看的是并排图 + 一句人话结论（"这一刀接得上/接不上，因为……"），
不是指标表。指标是给干活的人定位用的。

## 十、量化判据（2026-11-07 新增，实测标定）

肉眼看并排图会漏判——2026-11-07 EP002 项目文档把一处接缝记为 `mean_abs_diff=4.69 / 成立`，
实测实际交付的两条片子是 **MAD 63.45 / 结构相关 −0.034**，差一个数量级且结论相反。
**所以接缝必须量化，且必须测最终要交付的那两个文件。**

```bash
ffmpeg -sseof -0.05 -i A.mp4 -frames:v 1 -update 1 a-last.png
ffmpeg -i B.mp4 -frames:v 1 -update 1 b-first.png
python3 -c "
from PIL import Image; import numpy as np
a=np.asarray(Image.open('a-last.png').convert('RGB'),dtype=np.float32)
b=np.asarray(Image.open('b-first.png').convert('RGB'),dtype=np.float32)
print('MAD=%.2f' % np.abs(a-b).mean())
print('corr=%.4f' % np.corrcoef(a.mean(2).ravel(), b.mean(2).ravel())[0,1])
"
```

**判据（结构相关 corr，仅手动取证专用——`seam_check.py` 不计算 corr，下表来自手动 ffmpeg+PIL 比对）**：

| corr | 判定 | 处理 |
|---|---|---|
| ≥ 0.85 | 真接上了 | 可直接剪，遮挡非必需 |
| 0.5–0.85 | 有偏移 | 必须加遮挡或声音桥 |
| < 0.5 | **两个镜头** | 重出或当硬切；文档里不许记"成立" |

**同 seed 重跑是确定性的（2026-11-08 标定）**：同 seed、同 prompt、同参考图跨天重跑，
取同刻帧比对 **MAD = 0.00（逐像素完全相同）**。所以本通道里任何 MAD > 0 的差异都是
变量造成的因果差异，不是运行抖动——做 A/B **不需要靠重复采样来分离噪声**。

反过来这也划出一条红线：**改动输入口径（例如参考图上传编码）等于换一次生成**，
不是"同一张更清楚"。实测把板卡从 768/JPEG q80 换成原生 PNG，同 seed 下 MAD 到 19.65／25.26，
12 秒帧上衬衫颜色、仪表盘细节、后视镜都变了。已验收素材会整批对不上，
所以这类改动要按"换一次生成"的代价评估，不能按画质微调评估。

**EP002 七处接缝实测分布**（2026-11-07，全部为最终交付文件）：

| 接缝 | corr | 判定 |
|---|---|---|
| C1 001→002 | −0.034 | ❌ 两个镜头（机位反向） |
| C3 003→004 | 0.995 | ✅ |
| C6 006→007 | 0.996 | ✅ |
| C8 008→009 | 0.010 | ❌ 两个镜头 |
| C9 009→010 | 0.989 | ✅ |
| C11 011→012 | 0.994 | ✅ |
| C13 013→014 | 0.519 | ⚠️ 需桥接 |

结论：**真实末帧接力本身是有效的**（4/7 达到 0.99），失效的两处都是机位/空间换了，
不是"首尾帧接力这个方法不行"。所以优先修机位，不要因为两处失败就放弃手法。

**为什么机位反向不可修复**：机位换到人物另一侧时，人物朝向、方向盘/价格牌/门框的屏幕位置
整体镜像，corr 会掉到 0 附近。叠化只是把两张镜像图叠成重影，遮挡挡不住"背景全变了"这个事实。
唯一出路是改机位重出，或按硬切处理并让观众接受"换了个角度"。
