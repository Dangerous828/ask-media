# 视频复刻模式：原片是可审基准

用户给出一条已有短视频，要求“复刻”“照着做一版”“翻拍成 AI 版”时，原片不再只是学习机制的参考作品，
而是**本项目的验收基准**：镜头节奏、景别、画风、人物关系和关键道具都要能和它逐镜对照。
这与 `short-drama-develop` 的「创作参考作品的安全摄取」（`../../short-drama-develop/references/creative-reference-intake.md`）
“学机制不照搬”是两种不同授权。只有用户明确说要复刻、并确认对原片拥有使用权或只做内部练习时才进入
本模式；否则仍按参考摄取处理。

## 1. 原片拆解（第一阶段，先于剧本）

原片放进 `输入/原片/`。用现成工具把它变成可读证据，写进 `项目开发/原片拆解.md`：

- 链接或文件的文字稿、时间轴台词：`shortvideo-understand`（B 站/抖音链接）；
- 切点、逐镜抽帧、台词 OCR 与 ASR：`video-previs` 的拉片步骤。

`原片拆解.md` 每镜一节 `## SRC-<镜号> · <一句话内容>`，写：入出点秒数、景别与机位、谁在画面里、
谁说了哪句台词（逐字）、关键道具与状态、运镜，以及一张该镜代表帧的项目相对路径
（`输入/原片/frames/SRC-xx.jpg`，原样解码，不裁不调）。最后汇总总时长、镜数、平均镜长和整体画风观察
（介质、光色、材质、景深；无法确认的写“不确定”）。

### 1.1 逆推准备文档回填（接通六文档契约）

`原片拆解.md` 是**证据层**，不是准备文档的全部。用 `$video-shot-reverse` 为原片重建九份
`RR-*` 准备文档，落在 `项目开发/原片还原/`（可选分析工作区，不进 `剧集/<EP>/`）：
清单、落盘路径与回填对账见
逆推准备文档体系（详见 `../../../../video-shot-reverse/references/reverse-documents.md`），
文档级结构见 [六文档契约](document-contract.md)。

`RR-MAP` 负责三条 ID 的对账：`SRC-<镜号>`（本文件每镜一节）／`RR-*` 镜号／`SHOT-...`（正式分镜）
数量相等、集合相同；每个 `SHOT-...` 的「来源」写对应 `SRC-...`，合并或拆分原片镜头要写理由
（沿用 `## 2 下游怎样继承`）。`CARD-...` 与 `SHOT-...` 仍按场记账一卡一镜对账。

下游 owner 按 [六文档契约](document-contract.md) 的字段与 ID 把 RR 事实**编译**进
`剧集/<EP>/` 的六份文档，不把 RR 文档复制进创作主链：RR 是可核对的还原稿，不是第二套创作真相。
代表帧路径 `输入/原片/frames/SRC-xx.jpg` 仍是画风基准与构图参考的源。

## 2. 下游怎样继承

- **develop / write**：剧本的场次与台词顺序从 `RR-SCRIPT`（源片剧本还原）与 `SRC-...` 来；
  改动要写明“改了哪一镜、为什么”。`1.1` 节的九份文档是证据层，下游按六文档契约编译，不另起一套正推。
- **assets**：《视觉设定.md》「## 画风基准」优先登记原片代表帧（复刻目标就是原片画风）；创作者
  选择换画风时，改登记已接受的 Look 测试帧，并在拆解里注明“画风不复刻”。
- **direct / storyboard**：每个 `SHOT-...` 在来源字段写对应的 `SRC-...`；合并或拆分原片镜头要写理由。
  原片里观众能看清的东西就是“叙事必需”的候选，其余布局默认“允许偏差”（导演 DIR-08）。
- **video-prompts**：原片代表帧可以作为 `构图` 参考绑定，但它不是身份参考，人物身份仍用资产板。

## 3. 审查增加“对照原片”这一层

`short-drama-review` 审 `production_outputs` 时，复刻项目在画风层（REV-15）之后加一层逐镜对照：
把生成镜的抽帧和对应 `SRC-...` 代表帧并排，核对景别、人物在画位置、关键道具是否出现、节奏是否接近。
与原片相似是本模式的验收维度；但道具位置这类“允许偏差”项不对齐不构成返工理由。

## 4. 不做的事

不下载用户没给的视频，不把原片音轨直接混进成片（除非用户明确授权），不把原片里的水印、平台 UI 或
字幕当作画内文字复刻。
