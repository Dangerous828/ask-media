# 接手创作文档的修复与复核

接手其他 agent 或历史会话留下的分镜、资产与提示词，遇到批量格式错误、上游矛盾或生成结果不符时使用。格式定位见套件 `docs/ep002-document-pitfalls.md`；字段定义仍以各阶段当前模板和执行接口为准。

## 先定位事实，再修改

1. 读取当前剧本、创作者明确决策、场记账及受影响阶段的技能。按镜列出冲突：来源原文、当前写法、下游消费者、拟采取的修复。场记本身也要核对，不能因为已有文件就宣布定稿。
2. 区分重复格式错与内容错。字段括号、标题后缀等可作局部批量修复；起点、机位、道具状态、参考用途互相矛盾时，先解开依赖，再重写受影响部分。错误数量、涉及文件数量都不是自动整集重做的阈值。
3. 重做范围服从用户授权。保留可追溯副本和运行记录；用户要求不再参考的废稿不进入写作上下文。文档改变不自动证明已有素材合格或全部失效，按镜核对它与当前事实的关系。

## 不用假内容消除报错

- 引用不存在的 `IMG-...` 时，写真正可用的提示词，或如实写无。不能创建只有“见分镜”“不在此重复”的可复制空壳。
- `composition` 是所选构图瞬间，`start` 是 0 秒状态。证明计划需要记录 start，不等于必须出首帧图；确需生产 start 时，补独立起始帧正文并验证解析结果。不能只换 role 标签。
- 七项镜头语言留在每个关键帧小节的说明层，模型正文表达可见画面。解析器把小节字段误报为镜级重复时，定位解析范围并记录实现缺陷，不能把中文元数据塞入英文可复制正文来过检查。
- 空房间图只能提供地理或光态，不能给房间里新增的人物提供身份来源。缺身份参考时按当前技能允许的文字身份方案如实声明；不支持则留缺口，不能虚构 `in <Picture N>` 的像素依据。
- 创作者认可要能指到原话、时间或正式决策记录。文件存在、文件名、交接摘要、agent 自己写的“认可依据”都不能补造用户确认。未核实的认可保持未核实。
- 不能因缺 rejected 前驱而直接删 revision。先核对素材路径、字节、来源条目与运行历史；确需新任务时记录原因，保留前次运行和拒绝证据。

## 参考与连续性按真实内容决定

本地 H3 的 first_frame 与 reference_image 输入互斥；这是通道限制，不代表任意尾帧都足以传承身份。先检查真实帧的人物、手位、道具、屏幕、机位和光态，再决定续接方式。

宽景末帧与手部近景起点不同，就不能强行首帧接力；已经亮出金额的旧尾帧，不能用于金额尚未揭示的起点；布袋不能冒充塑料袋。应按镜头职责采用独立参考起链、重新取得合格帧或回改上游切点。禁止偷偷增加镜内切镜、把旧尾帧冒充新版本结果，或用正文要求模型抹掉首帧已有事实。

SHOT 与 MOTION 的参考声明必须一致，但同步方向由阶段所有权决定：先修正分镜的参考与边界，再让视频提示词继承；视频阶段发现问题时回修上游，不能默认以下游为准覆盖分镜。

连续性锁使用项目提示词语言的最小稳定短语，只在适用画面里携带。不能为了子串命中让尚未进场或已出画的道具提前出现。画内中文以剧本及已接受文字义务为来源，使用明确载体或精确 visible_text 配置；不把所有被报出的中文无条件加入白名单。

## 分批写作与合并

先固定已核实的上游和当前格式，分批只改变工作量，不改变事实。共用交接内容包括场景、起止状态、对白、机位、参考用途和待解冲突；不把未经核实的项目判断写成强制契约传播给所有子 agent。

合并者必须读实际产物与不确定项，逐个闭合相邻镜的持物、屏幕、人员、光态与切点。不能将子 agent 的“自查通过”直接抄成整集 QC，也不能机械给每镜配置同样三帧、同样两张参考图或固定尾部静止。

## 分层验证与报告

1. **结构与引用**：运行创作文档检查器、启用的导演契约检查；逐字对照对白、画内文字和场景/CARD 引用。检查器因缺文件提前退出时，不能声称其余文档已检查通过。
2. **执行契约**：按当前通道检查模式组合、引用顺序、帧网格、实际时长及 H3 正文结构；带真实配置与输入数量跑闸门。正式投产前验证代表性的 source_entry/KF 解析，但不因此触发生成。模板与代码冲突时单独报告，不能削弱检查器换取绿灯。
3. **语义回读**：先不看检查输出，按成稿回答“观众看见什么、从哪里看、先后知道什么、物件怎么到下一状态”。修正上游冲突后同步依赖，并重跑受影响检查。
4. **媒体复核**：格式通过不等于画面通过。实际查看工具返回的画面；如已显示图片，可直接检查，未拿到可见图像时再打开。工具的“没发现问题”通常只涵盖编码、黑屏或音量，不能证明剧情、价格、机位或表演正确。抽帧不是完整播放；音量统计不是听过对白。报告注明实际覆盖与未验证部分。

同一 reviewer 名称既不能证明独立，也不能证明不独立；核查执行来源与复核内容。复用时核对当前素材字节及对应验收的用途、剧情层和用户确认范围。

交付分别说明已完成的文档、已验证的规则、仍未闭合的内容或媒体问题。保留测试失败及原因；不写“以后不会再犯”的保证。生产确认按当前任务的实际授权范围执行，已经获得的有效确认无需重复索取；输入或目标有实质变化时说明变化后再按生产流程处理。

## 融汇两版：先裁定冲突，再拼章节

两版文档各有优点时，不按章节直接拼接。逐条走这四步，每一步都要留下判定理由：

1. **建差异清单**：按镜、按段列出「旧版写法 / 新版写法 / 下游消费者 / 差异性质」。差异分三类——措辞、可见事实、治理结构。只有后两类需要裁定。
2. **逐条裁定并写理由**：不得只写「取新版」。理由要能回答「为什么不取另一版」，通常落在三处：与上游账本（视觉设定、场记、剧本）是否一致、能不能装进时长预算、下游段的起点能不能接上。
3. **同步所有引用点**：改了某镜终点，必须同步它的切点契约表、接缝契约表、交付分组里对该镜末状态的描述。三张表各写一遍同一条事实时，只改一处就会互相矛盾。
4. **重算被裁定项的时间账**：换了末状态就要按动作时长表重估「这段还剩几秒能不能装下」。装不下时换手法，不压动作。

治理章节（节奏设计、切点契约、生成单元表、连续性账、未对齐项、交付分组、接缝契约、实测记录）是**生产期要用的账**，不是文档装饰。新版把它们删掉、只留正文时，正文写得再细也接不上——没有首帧来源就不知道该跟谁比，没有接缝契约就不知道比什么。融汇时这类章节默认保留，除非能证明已由别处权威承担。

「未对齐项」不能照抄。逐条标「已关闭 / 部分关闭 / 未关闭」，关闭的要写明依据（原话、日期、裁定结果）。新发现的问题补进去——尤其是**当前实际素材与文档对不上的那些**（例如某段素材引用的参考图已被改为不可复用）。这一节的价值在于它不撒谎。

## 差异清单里必须查的几类

合并两个版本之前，先确认这些容易漏的：

- **同一镜的终点**：两版经常给出相反收束（松手 vs 握轮、出画 vs 留在画面）。这类差异会直接传到下一段起点。
- **画内文字的可读要求**：某镜从「不要求辨读」改成「逐字写入」，或反之，是可见事实变化。
- **构图左右**：人物、道具、仪表在画面左右互换，下游所有参考锁都要跟着改。
- **帧 role**：`start` 与 `composition` 混用时，先看证明计划里是怎么登记的；登记了 `start` 不等于这一镜出过首帧图。
- **画内文字承载物**：同一笔金额写在「收款屏」还是「手持扫码枪小屏」，是不同道具状态。

## 回写经验时只写可复用的判据

一次修复里发现的坑，回写进参考文档时挑能跨项目复用的：判定方法、检查顺序、冲突类型。具体项目的数值、镜头号、文件名不进参考文档——它们属于项目记录，写进来下个项目读不懂，还会过期。
