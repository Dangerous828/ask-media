# 语料机制与剪辑准备

本文件持有机制参考在准备阶段的采纳、分工与继承约定。十一阶段顺序、六创作文档和一部戏一本《场记.md》保持不变；不新增机制账、准备报告或平行交接文件。普通场次可以简写；仅对当前采用的机制展开条件。单项任务只读取相关场次和镜头，不为补齐流水线伪造上游。

## 检索与采纳

文档准备时，按当前叙事、表演、因果证明、运动或剪辑问题调用 `creative-dna-cards` 检索，一次完整读一张候选卡的 SKILL.md、summary.md、template.md。目录和摘要用于选卡，正式采纳必须核对完整 Invariants 的 Rule、Purpose、Failure if removed，以及 Variable Slots、Anti-Copy Boundary、Transfer Tests；摘要与人类可读锚点可能省略条件，不能代替正文。遇到结构不同的模板，按其真实 planning/lock/audit 内容读取，不强套同一章节名。

导演在《导演.md》现有「参考边界／观看方案」中写明：来源卡及具体条款、本场适配理由、采用或改编的条件、改变条件的理由、承载镜头。无合适机制可写「未采用：理由」，不用为每场凑卡。保留当前决定，视频词阶段按已选条件执行，不默认重新选卡。

机制条件使用「卡名#inv-编号」等原文定位；无编号时用章节与条款原句定位。它们是本次采用机制的设计条件，不自动成为剧本叙事必需 N-ID。需要改变剧情、台词、核心动作或结局时回写作 owner，不能照外部模板“补槽”擅自改戏。偏离关键不变量时明确为改编，重新说明如何成立，不声称完整采用原机制。外部案例本地未测，不写成已验证配方；英文模型骨架不直接当本地提示词，案例条件不升级为全局禁令。

## 各阶段拥有的决定

| owner / 位置 | 准备与交接责任 |
|---|---|
| 资产 /《视觉设定.md》 | 从剧本拆实体；消费已提出的机制需求，按需定义过程、破损、变形状态或后期所需独立元素的可见锚点与生效范围。姿势、瞬时手位、机位不升级资产；身份锚点与状态变化分开。导演后发现缺口，先回资产更新，再继续场记，不改变阶段顺序。白模及脚本拼贴不能成为生成参考图。 |
| 导演 /《导演.md》 | 决定机制适配、初始基线、触发、因果链、递进变量、峰值、恢复与终局；安排注意力和表演归属，说明必须不中断的完整证明段、相对停留和强弱。决定声音的预告／触发／证明／承接作用，选择动作匹配、视线承接、反应切、平行剪辑、J/L cut、声音桥或不切等所需方法。说明由表演、摄影、生成或后期兑现、需要什么素材、不可行时保住作用的替代表达。具体镜长和时间窗留给分镜；机位与光位数值归场记。 |
| 场记 /《场记.md》六账 | 把导演决定落实为可引用状态、数值和接续条件，方法见下一节；不重新排戏或任改镜头计划。核实资产与白模能承载证明责任。 |
| 分镜 /《分镜.md》 | 按已对齐的卡和导演条件安排具体切点、reads 时间窗、证明帧与素材余量。把每个采用条款映射到现有 SHOT、CARD、read／画面证明，明确由单镜或连续多镜共同承载。保护不中断证明段和终局停留；不能以生成任务边界替代剪辑决定。 |
| 图片词／视频词 | 图片词落实已有状态变体与指定瞬间，不能把终态提前到首帧；视频词把对应证明时间窗译成可见动作、状态链和声音。保持场记值及参考职责，机制来源说明留在正文外；纯后期效果不要求模型预烘焙，生成负责其必要素材。缺条件先回对应 owner，不临场补戏。 |
| 生产／独立验收 | 生产按当前版本执行；验收读取同一采纳条款和承载镜头，观察证明过程、状态方向、注意目标、完整表演、声音和接缝，逐项记录真实时间码、证据及未验范围。文档审查只判计划覆盖，不能冒充媒体 PASS；结构闸门不代替实看。 |
| 剪辑 /《剪辑单.md》 | 前期可以借用剪辑知识和能力核实，不提前装配。素材存在且通过验收后才选真实入出点；按导演保护段、证明责任、声画交接取舍。偏离上游意图时记录缺口并回 owner，不能用特效遮住遗漏的事件。 |

## 场记如何放进原来的六本账

- **空间／光位账**：记录观察方向、屏幕左右、运动方向、注意目标可见区、遮挡路径与恢复可见条件。涉及接触因果时，确认所选角度能看清接触面和结果；光态需匹配时落成唯一值。
- **调度卡**：在现有镜内起止与主体／摄影机字段下，按需写动作的准备、接触、发力、反应、恢复阶段；指出本镜交出与下一镜接住的阶段。完整证明段写明保护范围；物理状态未变也可发生知情变化，不为凑动作发明新事件。
- **道具／状态记录**：在原道具行或主体状态中标明保持项、变化方向（只增／只减）、可逆／不可逆、允许重置的触发与范围；引用《视觉设定.md》状态名称。材料覆盖不能无理由倒退，损伤、湿润、情绪残余等按本场机制记录，不把叙事知情误当物理数值。
- **时间线账**：时间连续／间隔与状态连续分开。省略时间不等于允许重置状态；可跳过重复过程，但不能省掉本次机制成立所必需的接触或因果证明。
- **相邻镜条件**：在时间线账内集中写一次「接续条件：CARD-A → CARD-B」，两卡引用同一条。按需要记录动作阶段、视线／屏幕方向、构图／尺度、运动方向与速度关系、遮挡、光态、声音入出及允许偏差。连续不切段不因生成分段而新增机位卡；确需改变镜头边界，先回导演／场记修订。
- **素材与白模**：同一接续条目按需列真实运动的头尾余量、干净背景、完整反应、无对白环境声或可分离声画素材。具体时长预算由分镜确定，生产后按真实可用带复核。clone 定格只补帧，不算真实运动余量。白模核对空间、视线、遮挡和证明可见性；它不能证明画风、表演或声音已成功。

这些内容写在现有字段、备注和时间线账中；不强加新表列或 N-ID，不重复维护两套机位／状态值。当前检查器不自动识别这些散文条件，须人工逐项回读。

## 下游就绪与修订

在进入相关分镜前，采用的每个必要条件应能回答「谁负责、哪镜承载、需要什么状态／素材、怎样观察证明」。未定或冲突写进既有「未对齐项／QC 备注」，点名责任 owner；可以继续不受影响的范围，相关镜头不能被宣称就绪。确实不适用时写理由，不以空白代替决定。

追溯链是：原文条款 → 导演采纳／改编 → 资产状态及 CARD 接续条件 → SHOT／read／证明时间窗 → 提示词实现或后期责任 → 真实媒体证据。状态与接续条件只在所属上游维护，下游引用；需要修订时先改 owner，再同步受影响卡、镜头、词及素材状态，不笼统废弃无关的已接受产物。旧项目按本次受影响范围补齐，不回填虚假历史。

## 实现能力边界

剪辑组织方法与执行器的转场效果目录分别核实。内置切型或效果数量不代表当前项目渲染路线全部支持；不要求“用满效果”，硬切和有意静止都可以是决定。

短剧交付仍由 `short-drama-edit` 维护剪辑单并执行正式 render；其当前 render 不自动执行转场，也不执行「声音」行的自由混音方案。所需外部预处理按该技能现有边界记录来源、处理、实际采用区间及派生媒体验收，再通过正式交付链核对最终文件；能力尚未落实时标未定，不假装填了字段就会渲染。通用已有素材处理走 `concat-video`，不借准备知识调用它建立平行短剧工程。

本次约定是创作与人工审查规则，不增加解析器、渲染器或自动闸门的能力；字段齐全、脚本通过和外部案例成功都不等于当前素材可用。
