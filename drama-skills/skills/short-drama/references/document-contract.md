# 六文档契约

> 单一真相源：每份创作文档的 owner、输入、输出字段、稳定 ID、贯穿轴与下游读法。
> [creator-workflow.md](creator-workflow.md) 定义链的顺序，本文件定义**每份文档长什么样**。
> 写第一份文档之前先读它；字段先定好，再让各 owner 按契约输出。

## 机制条件的贯穿

准备、采纳、分工和下游就绪按 [语料机制与剪辑准备](mechanism-preparation.md)。导演输入可含按需求检索的完整模板；其条款与剧本 N-ID 分开，沿用原 SHOT 计划分配承载。场记输入同时含导演决定，六账落实状态方向与成对接续条件；视觉设定按需补状态变体。分镜以 reads/画面证明展开时间窗，词和生产继承，审查核真实证据，剪辑按保护段与接续条件取舍。字段留在现有 Markdown 中，不新增平行真相、必填表列或机器校验承诺。

## 不变／变化三层

每条可复制正文按三层槽位组织，这是跨镜一致性的结构手段：

| 层 | 写什么 | 变化范围 |
|---|---|---|
| **不变层** | 身份、造型、地理、连续性锁的锁面；每次原样复制，不简写 | 全集不变 |
| **氛围层** | 风格核心、视觉基调、色彩影调、画质、光位；**光线归这一层** | 一场戏内不变，换场景才调整 |
| **变化层** | 本镜主体动作、接触、反应、唯一镜头运动 | 每镜唯一变化的部分 |

光线写进变化层会和动作描述抢权重。分层契约由 `creator-documents.md` 的可复制正文规则执行。

## 与逆推准备文档的对应

逆推侧为一条已有视频重建的九份文档见
逆推准备文档体系（`../../../../video-shot-reverse/references/reverse-documents.md`）。
两套体系互为镜像：正向以场景 ID 为轴，逆推以时间码与代表帧为轴；
`场记.md` ↔ `RR-CONTINUITY`、`分镜.md` ↔ `RR-SHOTS`、`视觉设定.md` ↔ `RR-ASSETS` 同构。
逆推事实要被下游 owner 继承时，按本契约的字段与 ID 回填，不另建一套真相。

## 全片贯穿索引

逆推侧的 `RR-OVERVIEW` + `RR-MAP` 在正向链里没有独立文档，也不新增一份——
`creator-workflow.md` 明确单集主链不另落索引。贯穿由三处既有结构共同承担：

| 贯穿什么 | 在哪 | 稳定形式 |
|---|---|---|
| 场景与剧情源 | `剧本.md` | `EP<编号>-SC<编号>`，分镜「来源」逐镜引用 |
| 视觉一致性与生效范围 | `视觉设定.md` | `LOCK-...` 的「镜头：全集／SHOT 列表」 |
| 逐镜数值与空间 | `设定集/场记.md` | `CARD-...` ↔ `SHOT-...` 一卡一镜、`CONT-V###` 版本 |

复刻项目里另由 `RR-MAP` 把 `SRC-<镜号>`（原片证据）、`RR-*` 镜号与 `SHOT-...` 三者对齐；
它落在 `项目开发/原片还原/`，是可选分析工作区，不进 `剧集/<EP>/` 主链。

## 边界

- 本文件是文档契约，不新增创作真相；`creator-workflow.md` 关于「单集主链不另落 JSON/JSONL、索引、指纹、
  覆盖表、QA 报告、审核表」的既有取舍保持不变。
- 结构检查与批次状态仍留在本轮上下文；QC 结论由各 owner 在成稿内自检，独立审查归 `short-drama-review`。
- 依据三级、记录值与设计值、冲突裁决、主导运镜、写作 QC 12 条的字段语义见
  [逐镜证据台账](observation-ledger.md)；本文件只定文档级结构。
