# 六文档契约

> 单一真相源：每份创作文档的 owner、输入、输出字段、稳定 ID、贯穿轴与下游读法。
> [creator-workflow.md](creator-workflow.md) 定义链的顺序，本文件定义**每份文档长什么样**。
> 写第一份文档之前先读它；字段先定好，再让各 owner 按契约输出。

## 投产字段与格式硬约束

六份文档里下列写法由脚本或生产闸门读取；散文式描述不能替代可定位字段。

- **画风基准**必须单独写成二级标题 `## 画风基准`，不要嵌成 `### 画风基准`：`look_check.py` 按 `startswith("## 画风基准")` 找基准，三级标题它看不见，会一直报「没有可用画风基准」；而 `creator_markdown_check.py` 不查这一节的级别，三级写法在那里是绿灯——所以错到画风验收那一步才暴露。基准节内必须同时有可机读的基准行 `- LOOK-…：<项目相对路径>《<中文名>》` 与 `- 认可依据：创作者 <日期> …`；只写「制作形态／时代锚点」这类散文不够，`look_check.py measure` 会说没有可用基准，`production_tool prepare` 会以 `reference acceptance failed: ... no creator-accepted look baseline` 拦住所有镜（纯文生视频也一样，画风准入是整集前置条件）。写法与审批链归 `short-drama-review/references/stage-contract.md` 的「画风审批的三步」。
- **人物／造型／地点／道具条目**的标题必须是 `## <人物|造型|地点|道具> · <名称>`（`##` 级，`·` 分隔）；写成 `### 人物 · 她` 或别的形状会报「条目标题必须写成 …」，下游视觉依据也解析不到。
- **导演条目**每场一个，标题写成 `## <SC-ID> 内 · <地点> · <时间>`（必须带 `内/外` 或 `·`）；写成 `## <SC-ID> 导演` 解析不到、会报「没有场景导演条目」。每场 `- 戏剧行动：`、`- 转折与承受：`、`- 观众知情：`、`- 观看方案：`、`- 空间与声音：` 五个字段必填，写空、写「无」、写「待补」或「同上」都会报「缺少<字段>」；`观看终点`、`参考边界` 是约定字段，检查器不核，但下游读它们决定怎么拍。
- **镜头计划**每场一个 `### 镜头计划`，表格列固定为 `| Shot | 来源与职责 | 入场状态 | 主要变化 | 离场状态与交接 |`（5 列）。第 6 列有两种互斥用法，二选一：
  - **承载列**：一旦 `空间与声音` 里写了带 ID 的 `叙事必需：N1=<事实>`，每行都必须有这一列，填 `N1`/`N2`（该镜兑现了哪条必需）或 `无`（不兑现）。每条 N-ID 至少被一镜承载，否则报「没有任何镜头承载」。没有 N-ID 时不得出现这一列。
  - **状态账本**：`[在场:甲,乙; 持有:甲=道具; 知情:观众=事实]`，键只认在场/持有/知情，三段用 `;` 分隔且不能有空片段，`持有` 项写 `<人物>=<道具>`，`知情` 目前只支持 `观众=<事实>`；用了就必须入场与离场两侧成对写，只写一侧无法做延续 diff。
  表里的 Shot ID 必须属于本场，且每镜都要在本场计划里出现。
- **观众 reads** 表头固定为 `| Read | 时间窗 | 观众理解什么 | 注意怎么到达 | 停留/承接 |`（5 列），**首格必须逐字写 `Read`**（检查器按这个字跳过表头行，写小写 `read` 会被当数据行）；行首是 `R1`、`R2`… 顺序排列，时间窗写成 `0.0–2.0s`，各窗无缺口无重叠地接续，并完整覆盖本镜时长。
- **输入参考图身份**：镜头里有可见人物时，`输入参考图` 必须包含至少一条 `用途：身份` 的 REF；唯一例外是**首帧接力**（只有一条 REF 且用途为 `起始帧`，身份由上一段已验收的末帧继承）。只挂首帧／尾帧而另有多条参考时不算例外。
- **MOTION 名**有三种等价写法，按镜归属认同一镜：`MOTION-<shot_id>`（`MOTION-SHOT-EP001-07`）、`MOTION-<清单 id>`（`MOTION-S7`）、`MOTION-<去掉 SHOT- 前缀的 shot_id>`（`MOTION-EP001-07`）。写哪一种都能对上；不要以为只有一种，也**不要把同一镜的三种写法当三个镜**。
- **接缝说明**的 `join` 用枚举 `continuous`/`hard_cut`/`interval`/`j_cut`/`l_cut`；`reason` 用 `none`/`scene_change`/`time_jump`/`action_bridge`/`sound_bridge`/`identity_bridge`/`coverage_cut`。同一场里的硬切不能写 `none`（`SEAM021` 报错）：刻意分镜覆盖写 `coverage_cut`，时间跳跃写 `time_jump`。「同场同光位」本身不构成切镜理由——能连续走完的动作默认连续。接缝条目 `inter` 的 `from`/`to`、`inner` 的 `shot` 填清单 `shots[].id`（短 ID，如 `S1`），**不是 `shot_id`**（`SHOT-EP901-001`）——填成 `shot_id` 会被判「不是已存在的 shot」。

## 机制条件的贯穿

准备、采纳、分工和下游就绪按 [语料机制与剪辑准备](mechanism-preparation.md)。导演输入可含按需求检索的完整模板；其条款与剧本 N-ID 分开，沿用原 SHOT 计划分配承载。场记输入同时含导演决定，六账落实状态方向与成对接续条件；视觉设定按需补状态变体。分镜以 reads/画面证明展开时间窗，词和生产继承，审查核真实证据，剪辑按保护段与接续条件取舍。字段留在现有 Markdown 中，不新增平行真相、必填表列或机器校验承诺。

## 不变／变化三层

每条可复制正文按三层槽位组织，这是跨镜一致性的结构手段：

| 层 | 写什么 | 变化范围 |
|---|---|---|
| **不变层** | 身份、造型、地理、连续性锁的锁面；每次原样复制，不简写 | 全集不变 |
| **氛围层** | 风格核心、视觉基调、色彩影调、画质、光位；**光线归这一层** | 一场戏内不变，换场景才调整 |
| **变化层** | 本镜主体动作、接触、反应、唯一镜头运动 | 每镜唯一变化的部分 |

光线写进变化层会和动作描述抢权重。分层契约由 `creator-documents.md` 的可复制正文规则执行。

## 与逆推准备文档的对应

逆推侧为一条已有视频重建的九份文档见
逆推准备文档体系（`../../../../video-shot-reverse/references/reverse-documents.md`）。
两套体系互为镜像：正向以场景 ID 为轴，逆推以时间码与代表帧为轴；
`场记.md` ↔ `RR-CONTINUITY`、`分镜.md` ↔ `RR-SHOTS`、`视觉设定.md` ↔ `RR-ASSETS` 同构。
逆推事实要被下游 owner 继承时，按本契约的字段与 ID 回填，不另建一套真相。

## 全片贯穿索引

逆推侧的 `RR-OVERVIEW` + `RR-MAP` 在正向链里没有独立文档，也不新增一份——
`creator-workflow.md` 明确单集主链不另落索引。贯穿由三处既有结构共同承担：

| 贯穿什么 | 在哪 | 稳定形式 |
|---|---|---|
| 场景与剧情源 | `剧本.md` | `EP<编号>-SC<编号>`，分镜「来源」逐镜引用 |
| 视觉一致性与生效范围 | `视觉设定.md` | `LOCK-...` 的「镜头：全集／SHOT 列表」 |
| 逐镜数值与空间 | `设定集/场记.md` | `CARD-...` ↔ `SHOT-...` 一卡一镜、`CONT-V###` 版本 |

复刻项目里另由 `RR-MAP` 把 `SRC-<镜号>`（原片证据）、`RR-*` 镜号与 `SHOT-...` 三者对齐；
它落在 `项目开发/原片还原/`，是可选分析工作区，不进 `剧集/<EP>/` 主链。

## 边界

- 本文件是文档契约，不新增创作真相；`creator-workflow.md` 关于「单集主链不另落 JSON/JSONL、索引、指纹、
  覆盖表、QA 报告、审核表、交接胶囊或恢复状态」的既有取舍保持不变。
- 结构检查与批次状态仍留在本轮上下文；QC 结论由各 owner 在成稿内自检，独立审查归 `short-drama-review`。
- 依据三级、记录值与设计值、冲突裁决、主导运镜、写作 QC 12 条的字段语义见
  [逐镜证据台账](observation-ledger.md)；本文件只定文档级结构。
