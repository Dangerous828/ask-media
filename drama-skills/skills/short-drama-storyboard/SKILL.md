# 短剧分镜与冻结关键帧

把《导演.md》的观看方案与视觉事实转成有镜头职责、观众 reads、空间连续性和画面证明的 `剧集/<EP>/分镜.md`。
每镜使用二级标题 `## SHOT-...`，含 `### 观众 reads` 与 `### 画面证明计划`；
同镜下用 `### 冻结关键帧提示词` 写本镜**核心参考画面**的正文（标题是历史名称，内容不是起点帧），需要时写 `### 关键姿势提示词` 和
`### 收尾关键帧提示词`。完整骨架见 [分镜模板](assets/storyboard-template.md)。
依据三级／记录值／稳定实体索引／写作 QC 的单一真相源是
逐镜证据台账（`../short-drama/references/observation-ledger.md`）；模板里的新增字段都从它读。
本技能持有分镜文件与各帧的 role/时刻/事实；单帧正文按 `$doc-still-prompt` 方法写入当前 SHOT/KF 条目。
调用方法后继续完成本阶段，不另建平行提示词、第二身份库或全部四段审计模板。


## 确定性检查（跑并贴输出，不作放行依据）

判断类问题只靠自看。以下三类必须跑脚本并把输出贴进交付说明，因为漏看一次不会报错：

1. **台词逐字比对**：四字以上引文与《剧本.md》比对，改写台词会浪费一次付费生成。
2. **来源场景 ID 与场记卡拉引用**：每镜「来源」的场景 ID 必须在剧本里存在，剧本每个场景都有镜头承载或登记「未拍场次」；每镜的 `- 场记：CARD-...` 必须在 `设定集/场记.md` 里存在，一卡对一镜——卡不存在、卡无人引用、一卡被两镜引用、一镜引用两卡都要报出来。漏一个 ID 在长文档里看不出来，但它会让账本失去权威。
3. **H3 提交前的格式与算术**：帧数 `17k+5`、`--refs N` 与上传张数一致、六段/三段顺序、时间码、容器时长等于成员时长之和。

warn 逐条说明处理理由；退出码不作为能否继续的依据。会硬拦截的是：参考图准入（`ref_gate`）、真正提交付费生成，以及生产选帧——`SHOT-...#KF-...` 必须解析到《分镜.md》`画面证明计划` 里唯一的 role，`用途：起始帧` ⇔ `first_frame`、`用途：结束帧` ⇔ `last_frame` 必须成对。
## 文字回读与媒体边界

交付分镜时回读当前文档、必要来源与实际可复制正文，确认每镜职责、reads、起止状态和各帧证明责任一致。
已提供图片且本次核对依赖其像素时，实际打开相关原图；没有媒体时完成文字核对，明确画面未验证。
只有真正看过的内容才能写“已核对”，脚本退出码或文件存在不代表画面合格。生成物的媒体验收规则由
`$short-drama-review` 持有，本技能不为文字完成而触发生产或重复定义视频采样配额。

## 语料与剪辑准备的继承

继承导演已采纳的完整模板条件及场记接续记录，逐项落实到 SHOT/CARD、reads 时间窗和画面证明；保护不中断表演、基线、递进及终局停留。未定条件回对应 owner，相关镜头不宣称就绪；本阶段不默认重新选机制。完整分工与就绪判据见 语料机制与剪辑准备（`short-drama` 技能 `../short-drama/references/mechanism-preparation.md`）。新增散文条件由人工回读，现有检查器不自动核验。

## Quick Start

```text
用 $short-drama-storyboard 完成 EP001 的正式分镜和每镜冻结关键帧
```

## 入口

启用 `director-v1` 时先读当前 `剧集/<EP>/导演.md`，按 [导演交接](references/director-handoff.md)
逐场继承行动、观看和空间决定；未启用时保留直接从剧本进入的旧路径，不伪造《导演.md》。
新初始化项目已默认启用。资产图片提示词与分镜是兄弟分支，不互相等待。

**先读 `设定集/场记.md`，确认所有 CONT-* 连续性条目已填实。玺占位符不得隐性继承到分镜锚点——必须显式标注「连续性待补」。** 场景空间、光位和既有调度卡是已接受事实的来源；分镜先据完整事件决定必要镜头，
再让逐镜卡与选定镜头对应。当前镜已有机位、高度、轴线侧、景别、站位、持物与时间关系时直接继承；
缺卡或确需改变时，按 `$short-drama` 的场记方法补/修对应卡，记录依据和影响，再回填本镜，不循环转交整份任务。
缺少关键空间事实时说明具体缺口，保留可完成部分，不凭空发明或为齐表改变调度。
每镜写 `- 场记：CARD-...`，一镜对应一张卡；只对当前范围的镜头/卡核对一对一，未进入本集的卡不因无人引用报错。
拆并镜或换机位时同步其卡与版本，场景级空间账仍是一部戏一本，不随每镜重建。

先排每场的完整事件与连续表演，再决定必要剪辑点；镜内 reads、剪辑镜头和生成任务分别规划。明确采用 H3 或用户反馈拆太散／拼接生硬时，调用可选技能 `video-studio` 读取 `../../../video-studio/references/craft/sequence-planning.md`；技能未安装或参考不可读时按本段原则继续。镜数不从句号、动作动词或提交次数推出。

创作者可读说明跟随项目语言；冻结关键帧的可复制正文跟随
`short-drama.json#/format/prompt_language`。没有 `short-drama.json` 时正文默认使用 `en`。
分配镜头时长前读取
`short-drama.json#/creator_authority/production_profile/choices/native_duration_seconds`，同时读同一处的
`supported_generation_modes`：不含 `first_last_frame` 时不写 `结束帧` 槽位和收尾关键帧（终点只靠正文与剪辑采用区间），
不含 `text` 时不提供“改走文生视频”这一选项（本地 h3q 档案即如此）。已声明目标模型但
没有原生时长时先补这一个选择；目标模型也未声明时照常按叙事节奏设计，不猜供应商限制。
同时读取 `short-drama.json#/creator_authority/rhythm_profile`：`status` 为 `accepted` 时，镜长按
[镜长从哪来](references/shot-craft.md#镜长从哪来-sht-28) 由声音事件与 `target_avg_shot_seconds` 推出，
全集近景类镜头占比不低于 `close_shot_share_min`；档案缺失或未接受时不核对这些数值。

冻结关键帧写完之前，谁会出现在这一格画面里还没有定下来。所以三条依据都在关键帧之后回填，
读的是成稿画面，不是镜头意图。

用户没有手工点名参考图，不等于选择文生视频。冻结关键帧后先根据本镜可见人物、地点、关键道具与
起始构图判断一致性需求，再检查项目中已有的真实图片。只有当前可读、内容与用途可核对的图片才能自动绑定；
文件名像某个角色但内容未核对时，仍视为未准备好。`制作成果/` 下的生成物（含从生成视频抽出的帧）还要有
审查技能以 `--use reference` 批准、且剧情层通过的验收记录（`审查/look/<项目相对路径>.look.json`），否则不可绑定，生产环节也会拒绝。
不要为了让参考图“摆好”布局而拼贴、贴图、矢量重画或局部修改图片：这类人造参考会污染画风；
布局做不到时按导演 DIR-08 降为允许偏差或改机位。

项目里一张都没有时，创作者有三条路（档案不支持文生时只剩前两条），一次说清楚再让他选，不要只给「先生成参考图」和
「改成文生视频」两个：把手上已有的图片放进项目再绑成 `REF-...`；在自己的工具里出图、本轮先用
`PLAN-...` 写出挂图计划；或者明确改走文生视频。用本套件的生产技能出图只是第一条路的一种做法，
需要项目外的 adapter 与凭据，不是唯一入口。

开始分镜前读 `剧集/<EP>/剧本.md` 的当前内容。创作者说「剧本已确认采用」指的是那个文件，
不是对话里更早的草稿；两者不一致时以文件为准，并把差异说出来。

## 工作流

1. 读取已接受的目标模型原生时长区间，再确认每个场景动作、对白、声音、画面文字和转折由哪些镜头承载。
2. 继承导演方案中的知情时机、观众立场、表演和空间决定。剧本或 Brief 用“前半段 / 后半段 /
   前三分之一 / 最后 N 秒”等相对时间限定首次出现、释放或禁止时，先用已接受集长换成明确时间边界。
3. 每镜先写来源、职责、起点、唯一动作与终点，再写 `### 观众 reads`：每条 read 写观众要理解什么、
   注意怎样到达、需要怎样的停留与承接。时间窗从 0 连续覆盖镜长，原因与反应不争抢同一窗口；
   镜长由完整声音事件、动作与这些 reads 反推，不按剧本字数或固定秒数折算。
4. 锁定人物朝向、位置、视线、持物、出入口、屏幕方向和必要状态；摄影机的注意目标必须在该机位
   实际可见。每个含人物的镜头写一条 `机位锁`，每个可见人物各写一条
   `人物构图：<姓名>｜身体：<朝向>｜头部：<朝向或不可见>｜视线目标：<唯一实体或不可见>`。
   先确定人物注视的具体对象，再选择能看清这段关系的相机侧；对象在画外时，不把相机放在该对象的反方向。
   对视线的描述不能代替身体朝向；需要同时看见反应与动作时先检查同框和遮挡。普通叙事不把镜头当视线目标；
   只有直视观众确为剧情动作时，才写 `视线目标：镜头（有意直视：<叙事理由>）`。
5. 写 `### 画面证明计划`：区分 `composition / start / pose_proof / end`，各写对应 read、镜内时刻、证明责任和生产/审查用途。每行的时刻必须落在它引用的 read 的时间窗内（`director_check.py` 会拦）：`start` 在 0.0s，引用覆盖 0 秒的 read；画的是后段状态（他已经俯身到她耳边）就是 `composition`，写它真实的时刻，不借 `start` 的名义放进视频输入。
   `start` 记录0s起态，不自动要求生成首帧；`end` 只在镜末；`pose_proof` 记录镜内姿势且默认不作首帧。
   核心参考画面默认 `composition`，选择本镜最能说明构图与内容的已接受瞬间，不要求等于0s。
   有关键姿势时另写 `### 关键姿势提示词` 及对应 `#### KF-...`；确需尾帧时写 `### 收尾关键帧提示词`。
   每个提示词小节在可复制引用块/围栏外写一条字段：
   `- 镜头语言：<景别>｜<水平角度（轴线侧/无轴线）>｜<机位高度>｜<焦段意图>｜<构图：主体位置/必要层次/留白>｜<焦点：清晰范围>｜<帧相位：所选瞬间>`。
   七项字段与本镜调度/场记同源，不新增人物位置、朝向、动作或道具状态。正文表达其可见取景和所选瞬间，
   role、时刻、相位标签、后续运镜与排除项留说明层；不把中文字段塞进英文正文或为七项重复描写。
   规则见 [关键帧镜头语言](references/keyframe-camera-language.md)。停车、侧缝或同机位证明不成立时，读 空间证明案例（`../../../h3-prompt-writing/corpus/ep002-parking-contracts.md`），逐项对照read、证明对象、该机位可见范围和真实帧，不由视频阶段自行换机位。
6. 关键帧成稿后，从成稿正文读出本格需要保持身份、造型或地理的人物、地点和道具，再填满三条依据：
   - **视觉依据**：逐项引用《视觉设定.md》的既有条目；
   - **图片提示词项**：有合适 `IMG-...` 就引用，没有写「无」；
   - **输入参考图**：在用户提供的输入、`剧集/<EP>/制作成果/` 和文档已指向媒体中核对真实图片后写
     `REF-...`、创作者挂图计划 `PLAN-...`、`无（待补参考图：……）` 或部分缺口，或创作者明确选择的文生视频。待补不是文生视频授权。
   三条依据读同一格画面，不能把关键姿势或终点的人物/道具状态混入首帧。
7. 逐镜独立回读：不看设计过程，能否从成稿还原导演目的、观众 reads、起止状态和每帧证明责任？
   整集请求完成整集，末端一次报告覆盖、节奏和真实未决选择。

## 镜头要求

- **机位、高度、轴线侧、光位与站位取自《场记.md》，不在分镜里重新发明。** 场记账是这些数值的唯一来源；
  分镜负责把它们落到本镜的职责、reads 和画面证明上。确实需要改（换机位、换轴线侧、换光）时，
  先改账本里这一镜的行并换 `CONT-` 版本号，再改分镜；账本与分镜不一致时以账本为准回改分镜。
- 每镜有唯一职责、明确来源、可见起止状态和合理时长。「来源」以《剧本.md》里真实存在的场景 ID 开头，
  ID 之后可以跟必要短引文，跨场次的镜头用 `、` 连写多条；`creator_markdown_check.py` 会核对每个 ID 都解析得到。
- 「来源」短引文应对应本镜承担的动作或声音。正文提到画外人物时，可在视觉依据写
  `；画外：<类别>「<名称>」`；这只声明其不在画面，不能代替必要动作的落实。
  需要看见的动作应另有镜头承载，或说明为何省略。

- 剧本里的每个场景都要有镜头承载。确实决定不拍某一场时，在《分镜.md》正文开头写一行
  `- 未拍场次：<场景 ID>（理由：……）`，多项用 `；` 连接。SHT-01 一直允许带理由的省略，
  但省略和漏拍在成稿文档里长得一模一样，所以理由要写下来，而不是留在对话里。
- 已声明原生时长时，每镜照常有自己的唯一职责、起止边界，镜长先按叙事需要定。短于最短秒数
  的镜头，向创作者提议把同场相邻的几镜装进一个多镜容器，在交付档案里声明。**切点由剧情决定，不由关键帧决定**：
  连续运镜走到视觉死角（遮挡、门框、视线落点转移）时自然切，这一刀不必有独立的关键帧图片；
  只有必须精确控制构图、机位或地点的切才补图。拆点必须落在可截取的状态上；不要在分镜里设计只靠文字把两段独立生成动作接成同一运动。2026-11-05的案例中文字承接为41.87、真实末帧接力为3.38，这只作该设置的证据，通道路线仍按当前执行档案判断。容器能否装、怎么装由 `$short-drama-video-prompts` 的方言决定。
  创作者没有声明多镜容器、或方言不支持时，**叙事镜长保持不变**：生成任务按最短秒数（并吸附到目标帧网格）出片，动作按
  叙事节奏写，剪辑阶段从素材里选出叙事镜长的采用区间。不要把动作压缩后让画面在尾部静止“保持终点”——
  那正是“头尾静止、一顿一顿”事故的成因。长于上限的动作按可见状态闭合点拆镜，
  拆出的每镜仍各有唯一职责与可信交界。
- **关键帧是参考，不是起点，也不是终点。** 每镜的核心参考画面（历史名称「冻结关键帧」）是这个镜头的构图与内容参考，
  是分镜的核心；在视频阶段它默认绑成 `用途：构图`，进 reference 多槽参考，镜头怎么开始、怎么结束由正文的
  「起点 → 唯一动作 → 终点」写。「冻结关键帧提示词」这段文字同时承担连续性锁面、视觉依据覆盖和跨镜核对
  （缺了它覆盖检查就空转），所以每镜都写；是否真的出图由「输入参考图」决定。
- **每张关键帧小节有一条独立七项镜头语言字段。** 放在可复制引用块外，正文只表达本帧可见事实；
  字段不替代 `景别/机位`、`机位锁` 或逐人 `人物构图`，也不能新增人物位置、动作或道具状态。
  配方与检查见 [关键帧镜头语言](references/keyframe-camera-language.md)。
- **起始帧、结束帧按真实用途选择。** 可以是已验收的相邻视频实际截帧，也可以是按本镜明确start/end计划生产的图；
  来源、时刻与状态都要核对。不为每镜自动新增端点图，也不把核心构图参考默认为first_frame。
  输入模式、参考共存与首尾帧能力读取当前执行档案；该档案包含本地 H3 的 `last_frame` 接口，具体可用组合仍由当前接口核实。本技能不缓存更多通道能力。
- 「唯一动作」写从本镜起点到终点的那条可见状态链；涉及交接、换手、放置或取回时，把接触者、
  接触方式和物件落点写在同一链里，不能让合法终点之间靠镜外瞬移衔接。
- 切镜必须带来信息、权力、情绪、空间或节奏变化；同义重复镜头删掉。
- 相对时间词约束的是事件首次可见或可听的时刻，不因前置动作已经完成就提前释放；分镜时间轴直接
  写出该边界，不把“稍后”“交接后”等叙事顺序当成数值时间的替代。
- 同一动作不跨镜重复发生，峰值处声明过的[冲击重复](references/shot-craft.md#动作落实表)除外；终点应能成为下一镜可信起点。
- 关键信息的可读性优先于装饰性运镜，竖屏构图优先保证主体和反应可见。
- 复杂群戏先锁空间锚点和屏幕方向，再决定景别变化。
- **打算做"看起来连续"的接缝时，两侧机位要在人物同一侧。** 相邻两镜若要走首尾帧接力或任何连续处理，机位应在**人物同一侧**：不要一镜从左侧拍、下一镜从右侧拍。（换场、时间跳跃、故意换机位、正反打都是合法剪辑，不受这条约束——这条只管"你想让观众看成同一个连续镜头"的那些切点。）机位反了就不是接缝问题——人物朝向、关键道具（方向盘、价格牌、门框）的屏幕位置会整体镜像，观众立刻读成"换了个人/换了个地方"，任何剪辑手法（叠化、遮挡、声音桥）都救不回来。**判断方法**：写完两镜后，逐项核对左/右方位词、关键道具在屏幕的左/右、人物面朝方向；任一项相反就重写其中一镜的机位，不要靠剪辑补救。2026-11-07 事故：相邻两镜一镜左侧脸、一镜右侧脸，方向盘与价格牌屏幕位置对调，实测结构相关 −0.03（完全无相关），剪辑无法修复。
- **切点优先落在遮挡发生的瞬间。** 遮挡物必须是**本镜已存在的不透明前景**（人物后背占满画面、车门、A 柱、门框、擦身而过的行人），不是后期加上去的。设计镜头时就把"什么时候被挡住"写进状态链，切点据此安排；不要出片后再找地方切，那时已经没有遮挡可用。参照 `night-banquet-remake` 的做法：末帧要求写成"小二背影居中、两侧红灯笼、栏杆外灯海初现（前景遮挡截点）"，下游才有遮挡可用。
- **每段开场给一个持续音当锚，别让动作音打头。** 端点在分镜上就是"这一段从哪个声音切进去"。设计成"场内底声已经在响"（空调、雨、引擎怠速、人群低鸣），而不是"这一段以关门声开始"。后者在独立生成的段里会变成第 0 秒的满刻度爆音（实测掉 40–50 dB 后才进正戏）。开场锚还顺带解决了切点声音对不对得上的问题——两段都有底声，接起来才不会一段静一段响。
- 起终边界除了逐人姿态，还要写清本镜依赖的身体—物件—空间关系。关系在镜内不变时两端都保留；确需改变时，过程与终点必须有剧本依据。
- 冻结关键帧只写该瞬间能看见的内容；文字、手指、反射和遮挡要可生成。
- 近景类关键帧挂着地点板生成时，图片常被拉宽成中远景；正文写具体取景（画面切在哪、脸在画面哪里、机位距离），出图仍偏宽就这一镜不挂地点板，把背景写进正文。
- 一集的关键帧共享已接受的介质、身份、Look和场景光态。换机位时重新投影世界光向与可见表面，
  不要求逐镜同一句画左光或同一曝光数字。已有定调图可按用途选用；需要新图才提出具体缺口，
  不因统一画风自动增加中远景生产或强制参考顺序。
- 《视觉设定.md》的连续性锁在生效镜头上原样写进冻结关键帧正文；锁面不因“参考图会交代”而省略。
- 检查发现遗漏就直接修正文档，不生成覆盖表来证明自己检查过。镜头块里的「视觉依据」是本镜的依据字段，不是这里说的覆盖表。

### 切点的导演语法（2026-11-04）

“切镜必须带来变化”的可用句式。不是每镜都要用，按戏选：

| 语法 | 用法 |
|---|---|
| Match on action | 在动作同一帧换视角，动作跨切点继续；最不易被察觉 |
| 视线匹配 | 上一镜看画外，下一镜给目标；建立“谁在看什么” |
| 180° 轴线 | 两人关系不跨轴；换侧必须用建立镜或运动过渡 |
| 30° 规则 | 同主体换角度至少 30°，否则读成跳切 |
| 景别推进 | wide → medium → close-up → detail → reaction → wide |
| J/L cut | 声音先入或后出，画面切了声音不断；接缝感知最低 |
| 遮挡过渡 / 动作承接 / 声音桥等 | 手法清单、本通道可用性、可复制句式与核对步骤的唯一权威源是 `$short-drama-video-prompts` 的 `../short-drama-video-prompts/references/seam-transition.md`。本节不复制它：32 种手法分七类，选路是先分类再选手法 |
| 首尾帧接力 | 按真实端点与当前执行档案判断是否可用、能否共存其他参考；制作条件见同一份 reference 的第17、18条，不在本表缓存通道能力 |

切点有信息增量就切，不要为了“无缝”把该切的戏压成一个长镜头。生成侧的多镜写法（`[Shot N]`、气闸、接力）见 `$h3-prompt-writing` 的 §Shot Joining: Three Layers。

### 连续段案例的适用范围

2026-11-05的本地七组渲染曾比较同次多镜、真实末帧接力、独立段与遮挡过渡；记录中有帧差3.38和41.87。
这些数值缺少完整输入与度量定义时只能作为来源案例，不足以证明文字承接必断或遮挡过渡普遍无效。
本阶段仍按完整动作、观看职责与可信状态设计切点；同次容器、分次接力或有动机的切镜各按当前执行档案评估。
需要续接时写清边界的手位、持物、朝向与声音；参考图/端点约束不能代替动作路径。
执行风险不授权删除剧情动作、强制停姿或换机位；提出具体问题交上游决定，制作与生成验证另行处理。

## 视觉依据与图片

- `IMG-...` 是《图片提示词.md》里的**提示词条目 ID**，不代表图片已生成、已提供或可用。
- 已有《图片提示词.md》且本镜需要其中条目时，写「图片提示词项」：ID 必须匹配该文档的可见二级标题，同时写中文名称和它控制的身份、造型、地理、构图或其他边界。ID 只用于查找，不让英文 slug 承担含义。
- 没有《图片提示词.md》或没有合适条目时，写「图片提示词项：无」，再以中文指向《视觉设定.md》的人物、地点或道具项及控制范围。这是正常直接入口；不为继续分镜而编造 ID，也不补造另一个阶段。
- 「视觉依据」是每镜必写字段：冻结关键帧成稿后按实际画面反查，需要保持身份、造型或地理的可见人物、地点和道具**必须**逐项写成
  `《视觉设定.md》·<人物|造型|地点|道具>「<名称>」（控制：<范围>）`，多项用 `；` 连接，名称必须能在《视觉设定.md》里找到同名标题。
  小比例或背景人物只要需要认出身份仍在范围内，画外人声和不可识别局部不算；本镜确实没有这类条目时写「视觉依据：无」。
- 关键帧正文出现了某个条目的名字，但它本镜确实不在画面里（物主已离场、名字只出现在屏幕文字上、和某个词同形），
  在「视觉依据」末尾追加 `；画外：<类别>「<名称>」`。这是如实记录，不是把不在场的人写成在场。
- 某个条目的名字在正文里根本不可靠（`道具「手机」` 会撞上「手机店」，`人物「小雨」` 会撞上「下着小雨」），
  在《视觉设定.md》该条目写 `画面代称：无`，机械核对就不再按名字找它；这一镜是否画到它仍由「视觉依据」如实回答。
- 三条依据都描述同一格画面，不是本镜的资产花名册。「控制」只写这一格承担得起的范围：手背特写不写「本集造型」，
  只出现屏幕和一根手指的镜头不写「体态」。上一镜的绑定不因为“角色还在这场戏里”就顺延到下一镜。
- 关键帧正文点名的人物、地点或道具（《视觉设定.md》条目名称或它声明的「画面代称」），必须出现在本镜「视觉依据」里；
  `creator_markdown_check.py` 会机械核对这一条。它只抓**被名字点到**的那一类：正文只描述不点名
  （"a boy in a hooded jacket"）时机器不发声，画面里有谁仍然要靠这一步自己读出来，不能等报错。
- 本镜需要保持一致、但《视觉设定.md》里还没有条目的可见物件（跨镜出现的道具尤其常见），不能因为
  「写不进视觉依据」就当它不需要一致性。四镜都出现的一支笔和一件外套是同一类问题。做两件事：
  正文里逐镜用完全相同的描述把它钉住，并在本轮末尾报告里点名它、建议 `$short-drama-assets` 补条目。
  不自行新增《视觉设定.md》条目，也不把它塞进「视觉依据」冒充已有条目。
- 「输入参考图」是独立的另一条轴：创作者已提供，或经确认生产且当前可读的实际图片，用不同于 `IMG-...` 的稳定 `REF-...` 槽位引用。每个槽位同时写显式顺序、仅用 `/` 分隔的项目相对路径、中文名称、「用途」、「控制」和「不得控制」范围；没有时必须区分「待补参考图」和「创作者已明确选择文生视频」，只准备了一部分时则保留已有 `REF-...` 并追加「；待补参考图：……」。不得把提示词条目、还没生成的图或对话中的描述写成 `REF-...`——`REF-...` 的意思是「文件此刻在项目里」。
  创作者会在生成时自己挂载的图片走下面的 `PLAN-...`：它同样不声称文件存在，只是把这一镜要挂哪几张写清楚。
- 每个 `REF-...` 必须逐字遵循唯一格式：`REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）`。注意「顺序：」后的全角冒号和路径前的中点 `·`；不得用 `/` 代替字段分隔符。多图只用中文分号 `；` 连接，部分缺图则在最后一个完整槽位后接 `；待补参考图：<缺口>`，缺口之间用 `、` 分隔。写完后按此格式回读一次再交付。
- `用途` 只能取 `身份`、`造型状态`、`地理`、`构图`、`尺度`、`效果`、`起始帧`、`结束帧`、`风格` 之一；逐条能控制什么见 `$short-drama` 的《参考角色》。
  本镜的核心参考画面写 `用途：构图`，人物图写 `用途：身份` 或 `造型状态`，场景图写 `用途：地理`，道具状态图按它决定的那一件写；
  一件道具被递出、接住、打开、换手或状态在本镜改变的，就该有它的道具板槽位——板没做好时写进「待补参考图」，不要只挂人物与场景两槽就当作齐了（判据见 `$short-drama`《参考角色》）；
  `起始帧` / `结束帧` 对应实际start/end状态，来自已验收截帧或明确端点图计划，不以核心参考画面的名称推断用途。
  一张图承担两件事就拆成两个槽位；一镜最多一张 `起始帧` 和一张 `结束帧`，写 `结束帧` 时必须同时有 `起始帧`。
  下游视频提示词靠 `用途` 说清「本镜送哪一张核心参考画面、哪些人物/道具/场景图」，所以缺 `用途` 的槽位不算准备好。
- 本镜确需起始画面图而尚无真实文件时，先有明确 `start` 记录与对应0s正文，不能直接采用镜内composition图。
  创作者授权本套件生产时由 `$short-drama-produce` 读取该start条目，准确记录来源SHOT/KF并归档真实结果；
  使用自己的工具时复制同一start正文，文件进项目后再绑 `REF-...`。暂时只规划挂图则写 `PLAN-...`，
  其目标必须能定位到本镜明确的start正文，并标用途起始帧。没有文件或计划时如实列待补，不伪装已就绪。
- 创作者在项目外出图、图片不进项目时，用 `PLAN-...` 槽位：语法与 `REF-...` 逐字相同，只把项目相对路径
  换成 `IMG-...` 或 `SHOT-...` 条目 ID，`IMG-...` 的中文名称必须与《图片提示词.md》标题一致。
  它声明的是「这张图由创作者在生成时按这个顺序挂载」，不声称项目里有文件，因此不是「待补」，
  也不能拿来投产。真实文件进了项目就改写成 `REF-...`。两种槽位可以混用，`顺序` 统一连续编号。
- 自动绑定不是把所有图都塞进一镜。只选本镜可见、且身份、造型、地理、关键道具状态或起始构图确实需要稳定的图；逐张写清它的用途、能控制什么、不得控制什么。
- 两条轴可以独立组合：有合法的图片提示词项时，输入参考图仍可为「待补」或创作者明确选择的文生视频；创作者给了真实参考图时，图片提示词项也可为「无」。

## 完成

点名范围的原文都有镜头落实，每镜职责不重复、空间与状态连续、起止边界可制作、关键帧可冻结，
每镜「来源」解析到《剧本.md》的真实场景、剧本里每个场景都有镜头承载或已记入「未拍场次」，
且每镜关键帧里的可见人物、地点、道具都在本镜「视觉依据」里；含人物的镜头有机位锁和逐人身体/头部/视线目标；每张关键帧正文有七项镜头语言锚点，即完成。画面需要、但《视觉设定.md》
还没有条目的可见物件，在末尾报告里逐项点名。本次请求同时修改
《图片提示词.md》与《分镜.md》时，当轮刷新受影响镜头的引用；不另建覆盖表。
视频提示词、生产和审查只有用户点名时开始。
启用 director-v1 时，每镜还必须有覆盖全镜的 reads 和完整画面证明计划，关键姿势不冒充首帧。
