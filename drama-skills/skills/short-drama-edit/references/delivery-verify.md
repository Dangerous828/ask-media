# 交付与验收

检查实际交付文件，并区分实测结果、人工判断和未测项。

| 项 | 怎么核对 |
|---|---|
| 时长与切点 | 对照实际渲染区间、帧边界和用户时长要求 |
| 内容覆盖 | 对照分镜和视频提示词，必要内容有承载，未采用镜头有原因 |
| 台词 | 在成片上回听，必要时转写辅助，逐句对照剧本 |
| 边界帧 | 查看剪辑点前后，检查意外黑白帧、画面断裂和漂移；先用 `verify` 的 blackdetect 结果定位黑帧/黑场，再逐帧查看疑似坏帧 |
| 声音 | 探测音频流、采样率、声道与码率；回听接缝、对白清晰度与已声明静默；测量整片响度并对照交付目标 |
| 字幕 | 检查逐字内容、发声时间、字号、折行和画内文字避让 |
| 画内文字 | 按剧本与视觉设定的文字政策检查载体、可读性和指定文字 |
| 画幅与帧率 | 探测输出文件的视频码率、分辨率与帧率，有声明规格时逐项对照 |
| 接镜运动 | 先查运动：`check_motion.py <成片> --cuts a,b,c` 定位两侧静止或运动比异常；回看是否无意起停，结合动作阶段、景别变化与有意反应判断，不以全非零或 ≤3 倍作统一门槛 |
| 接镜色彩 | 运动接上之后，再在同场景、同光态下比较可比区域，确认校正没有过冲；先看 `verify` 点名的切点 |

## `verify` 机械门禁

```text
python3 <本技能目录>/scripts/edit_tool.py verify <剧集/EP001> --project-root <project>
```

输出保留既有的时长、画幅、帧率、响度、分段色彩、落点和逐帧测量字段，并增加 `机械验收`：
`结果` 是 `PASS` / `WARN` / `FAIL`，`检查` 逐项给出同样的状态与实测说明，`汇总` 给出各级数量。
另增视频码率、音频流与基本规格、黑场区间、响度偏差等数字字段。

- `PASS`：列出的自动检查全部已测且通过。
- `FAIL`：没有音频流、声明的画幅或帧率不符、blackdetect 检出黑帧/黑场（最小时长为 0，含单帧），
  或 `|实测 LUFS - 剪辑单的交付响度| > 1 LU`。
- `WARN`：没有 `FAIL`，但有项目未测或无法判定。例如剪辑单未声明响度、画幅或帧率目标，
  loudnorm/blackdetect 没有可用结果，或 ffprobe 未报告流码率。未测项必须写原因，不计为通过；
  缺目标本身不阻断交付。
- 主命令存在任一 `FAIL` 时退出码为 1；`PASS` 或仅有 `WARN` 时为 0。输入或工具错误仍按命令错误处理。
- 视频与音频码率这里只探测、报告，不虚构交付目标；容器总码率不冒充某一条流的码率。
- `机械验收：PASS` 只覆盖上述自动项。`人工复核`、台词完整性、画内文字和边界帧仍明确标为未测，
  不能据此宣称内容质量或正式审查通过。

分段色彩观测按当前剪辑单读取中间分段，报告平均亮度和蓝减红像素值；它不代表成片局部区域的
接镜残差，也不要求各场景接近同一均值。改动剪辑单后先重新渲染，再测量并查看实际切点。
blackdetect 不推断创作意图：有意黑场也会保留为 `FAIL`，由人工复核和正式审查决定是否接受，不能把检测静默改成通过。
静默或光态变化则按创作意图判断，不只凭数值异常直接判错。

`verify` 还逐帧读成片：「切点亮度变化」是每个切点前后两帧的平均亮度差（0–255），超过 20 的
列进「请逐帧查看」；「疑似坏帧」是与前后两帧都明显不同、而前后两帧彼此相近的单帧，常见于解码
错位，画面文字入场的一两帧故障效果也会被列出并标明。两项都只指出该看哪里，不阻断交付。

`verify` 不自动调用 `check_motion.py`：后者会另行解码成片或分段并依赖 NumPy，跨脚本集成会在现有逐帧测量之外重复整条解码。
继续用上表命令取得头尾刹车与切点运动结果。两侧静止、头尾刹车或运动比异常只用于定位人工复核；有意停顿不直接判 `FAIL`。

## 交付

给出成片、剪辑单、可继续编辑的中间文件，以及外部混音或字幕工程（如使用）。
说明是否满足用户要求、仍有哪些内容缺口和取舍；测不了的必要项目写明原因。

需要补素材、改台词或改分镜时，指出对应镜头与发生时间并交给负责阶段。
渲染成功只证明工具完成执行，成片的内容判断需要观看和回听；正式审查由
`$short-drama-review` 或创作者进行。
