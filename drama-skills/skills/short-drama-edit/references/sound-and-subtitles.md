# 声音、字幕与音乐

## 声音接缝

在相邻镜头拼接后回听底噪、混响、环境声和音乐是否突然变化。
可按需要采用音轨交叉淡入、连续环境底、对白与画面分离或补充音乐。
保留有叙事作用的静默、音效和相对响度。

**内置工具范围**：`edit_tool.py render` 保留素材原声，按 `音效` 行把单个声音文件混进指定时刻，
并可做整片响度标准化；混音不压低原声，响度在混入音效之后测量。
CUT 的 `声音` 行是剪辑说明，工具不解析它，不执行静音、交叉淡入、配乐进入或 ducking。
需要这些处理时用 ffmpeg 或剪辑软件另行完成，记录命令或工程及实际输出；完成后再验收。
不能把写下声音方案或 render 成功当成已经混音。

### 做音桥的取样段里不能有台词

做声音桥（把下一镜的声先带进来，或把上一镜的尾音续过去）时，取样段必须是真环境声。
**凭听感判断会出事**：台词尾音拖得长、或者本来电平就低的时候，听起来像环境声，抬起来就是一句话。

实测事故（三镜短剧）：从镜2 末尾 8.0–8.5 秒取「笑声」垫进镜3，实际那里是「谢谢」的尾音
（8.2 秒说「谢谢」，8.4–8.5 秒是尾音，−12 dB）。抬 2 dB 垫进镜3 开头，观众在镜3 首帧听到一个「谢」。
镜2 末尾真正的笑声从不存在——8.45 秒之后只剩 −41 dB 房间底噪。

筛法：按 20 ms 窗口算语音频段（200–3500 Hz）能量占全频带的比例。占比长期 >50% 的窗口有台词，不能作取样段：

```bash
ffmpeg -ss <起> -t <时长> -i <素材> -ar 16000 -ac 1 -f wav probe.wav
python3 - <<'PY'
import wave, numpy as np
w = wave.open('probe.wav')
a = np.frombuffer(w.readframes(w.getnframes()), np.int16).astype(float)
sr = w.getframerate(); win = int(sr * 0.02)
for i in range(0, len(a) - win, win):
    sp = np.abs(np.fft.rfft(a[i:i+win] * np.hanning(win)))
    f = np.fft.rfftfreq(win, 1 / sr)
    voice = sp[(f > 200) & (f < 3500)].sum() / (sp.sum() + 1e-9) * 100
    print(f"{i/sr:5.2f}s 语音占比 {voice:5.1f}%  峰值 {20*np.log10(np.abs(a[i:i+win]).max()/32768+1e-9):6.1f} dB")
PY
```

找不到干净段时不要硬造。改用上一镜自己的环境声延长（同源不会叠词），或者让静默承担这一刀。

### 开头那段低电平剪不剪，看它后面接什么

独立生成的镜头常在开头留约 0.2 秒的极低电平（−90 dB 附近，波形上是平线）。这段剪不剪，
不取决于它有多低——同一批素材里几镜开头量出来是同一个值——而取决于**后面第一个有声事件是什么、起得多快**：

| 后面接的是 | 起音速度（20 ms 窗） | 剪掉 0.125 秒的后果 |
|---|---|---|
| 环境声（房间底噪、空调） | 0.24 秒才到 −40 dB | 听不出 |
| 台词 | 0.18 秒就到 −35 dB | 台词整体提前，贴到切点正后方，像一换镜就冒人声 |

判断方法：用 20 ms 窗扫前 0.3 秒，记下**第一个超过 −50 dB 的窗口**是第几个。那一刻之前才是可以自由裁的余地；
裁进它之后，就是把台词往前拽。实测一条三镜短片里，两镜开头的低电平段长度和电平都相同，
一个该剪一个该留，差别全在这个时刻。

台词提前本身不等于故障——切点合理时提前几帧没有影响。真正会出事的是它和切点音频处理叠加：
本来切点处就有一段电平坑，再让台词提前，坑和台词挤在一起，听感上就是「一换镜就冒出一句话」。

### 多轨相加会顶爆

`amix` 的 `normalize=0` 是**直接相加，不是取平均**。两条 −6 dB 的轨相加接近 −0.1 dB，峰值撞在一起还会削波。
实测：两轨各 −6.3 dB 与 −6.2 dB 相撞，混出来 −0.1 dB，比原始峰值还高。

多轨混音时各轨先降 6 dB 再相加，混完整体拉回；或用 `weights` 逐轨配比。
逐段单轨处理则不必，只有真正叠加时才要注意。

## 响度

两遍测量不保证归一化后恰好达到目标。线性增益会超过峰值或动态范围目标时，
`loudnorm` 会退回动态处理；短片和稀疏音效仍需测量编码后的实际 LUFS 与真峰。
内置归一化输出使用 48 kHz，避免动态处理的内部升采样直接决定 AAC 采样率。
不达标时按声音设计通过外部工具处理瞬态、限幅或混音，再核对成片；不要把目标值当实测值。

**单遍 `loudnorm` 常差一截，按实测差值补增益更稳。** 先用 `loudnorm=I=-16:print_format=json` 打印 `input_i`，
与目标做差，再给该文件加对应的 `volume` 增益；只是在原混音上整体平移，峰值不会因此受损。

实测：混出来的片子 `input_i` 为 −13.28 LUFS，目标 −16，加 `volume=-2.72dB` 后复测正好 −16.00、真峰 −4.09 dBTP。
同一条直接跑单遍 `loudnorm` 只到 −17.07；两遍带 `linear=true` 又因 LRA 不匹配退化成动态处理。
补完增益仍要复测，不要假设算对了就一定对。

## 台词与时间

先在源素材上定位发声区间，再在成片上逐句回听，核对留下的台词完整、可辨。
转写可以辅助查漏和定位，最终文字按剧本核对，识别有出入时回听确认。

重出素材会改变发声位置，应重测相关字幕时间并更新剪辑单。
`check` 会提示素材比剪辑单新；这个时间戳检查不能证明字幕已经重新对齐。

## 字幕

**字幕是选项，不是默认。** 先从创作者处取得明确答复；未答复时按无字幕渲染，并在交付报告写清楚。
创作者要字幕时，竖屏短剧通常用硬字幕。
字幕文字逐字取自《剧本.md》，剪辑单照抄剧本标点。转写仅辅助定位，不覆盖原文。

**例外：分镜阶段已批准精简台词时，以精简稿为准。** 若《分镜.md》的“对白处理”表已明确某句为精简版、且创作者已批准，
字幕写该精简版并在剪辑单记录这处偏离；不要拿剧本全长句去覆盖已批准的口播，否则字幕会明显长于声音。
render 烧录时按 GY/T 288 与短剧惯例改写显示形式：去掉句末标点，保留 `？` `！`，
句中的 `，。、；：` 换成全角空格；`字幕.srt` 用的也是这一形式，`check` 仍按剧本原文核对。

- 字幕一行显示。超过 12 个字的句子，render 在句中停顿处拆成先后显示的几条，
  按字数分配这句的时间；没有停顿的长短语按字数均分。重点词不会被拆到两条里。
- 一镜有多句时使用 `字幕 1`、`字幕 2` 等编号，每句给出时间。
- 字幕时间相对本 CUT 的入点，不相对源素材起点；落在该段使用区间内。
- 累计成片位置使用渲染后各段的实际时长，避免帧边界取整产生漂移。
- 抽帧检查字号、折行、安全区和画内文字遮挡。

两条路线用同一套尺寸：字高为画面高度的 4.3%，深色描边 0.42%，基线在距底边约 24% 处，
避开平台自己的底部界面；字色按来源区分，重点词标黄。内置 ffmpeg 路线用实际画幅作为 ASS PlayRes，
字号按该画幅像素计算；它采用全片统一样式，CUT 的字幕行不支持位置指令。需要逐镜避让或更复杂排版时，
用外部字幕编辑器或修改 Remotion 字幕层，并对输出抽帧检查。

### 渲染路线

| 路线 | 适用范围 | 开销 |
|---|---|---|
| `ffmpeg`（默认） | 本机的思源黑体粗体，描边与颜色同上 | 需要带 libass 的 ffmpeg |
| `remotion` | 思源黑体 Heavy（随叠层安装），描边压在字下、入场弹出、重点词 120 ms 放大 | Node 依赖，逐帧浏览器渲染；并发默认 2 |

Remotion 安装与样式调整见 [Remotion 叠层](../assets/remotion/README.md)。
两条路线都要在实际成片上检查字幕。

## 响度与时间线音乐

在剪辑单写交付响度；混音完成后对整片标准化并测量输出。
同时回听对白与环境的相对关系，整片响度达标不代表各句都清楚。

时间线音乐按已接受意图选择进入、退出、循环与对白压低区间。
素材不足时回生产阶段补齐；具体混音通过外部工具执行，并在剪辑单留下可复现记录。

### 没有音乐生成通道时的做法

家庭节点目前没有云端音乐 API（Magpie 网关只有文字与生图生视频模型）。要一条**跟着镜头走的配乐**，可行路线是本地合成器渲染，不依赖外部服务：

| 环节 | 做法 |
|---|---|
| 音色 | macOS 自带 `/System/Library/Components/CoreAudio.component/Contents/Resources/gs_instruments.dls`（General MIDI 完整音色库：钢琴、钢片琴、音乐盒、竖琴、拨弦、定音鼓等） |
| 渲染 | 一个小的 Swift 程序：`AVAudioEngine` 开 `enableManualRenderingMode(.offline)`，每个声部挂一个 `AVAudioUnitSampler.loadSoundBankInstrument`，逐块推进写 `AVAudioFile`；总线后接 `AVAudioUnitReverb` 补空间感。离线渲染不受实时播放限制，44 秒一条几秒跑完 |
| 音符 | 写成数据表（`inst / start / note / vel / dur` 五列），**按镜头事件手排时间点**，不套固定节拍网格——这样它跟画面的呼吸是贴的，不是“背景放首歌” |
| 电平 | **按镜头手画增益**，不用一条总音量。原则：稀疏段抬到比画面低 10–12 dB 才听得见，全奏段退到比台词低 3–6 dB 让路；段间 60 ms 交叉淡化避免音量台阶出咔哒；总线过 limiter 防削波 |
| 混音 | `amix weights=1 1:normalize=0` + `alimiter 0.94`，画面 `-c:v copy` 不重编码 |
| 复现 | 音符表与增益表都留在项目里，改旋律只动音符表、改平衡只动增益表，**画面不用重跑** |

一个本地验证过的完整实例（仅本地验证，产物未随公开版发布）由 `BGM设计.md`（动机与逐段结构）、`bgm/notes.tsv`（162 个音符）、`bgm/render.swift`、`bgm/mix_bgm.py`（按镜头增益表）组成。做法可整段搬用，旋律按各片自己的主题重写。

注意：这条路给的是**可用的一版**，不是影视级作曲。要真正的管弦编制或带人声的歌曲，仍需外部音乐服务；此时按上表把渲染环节换掉，音符表与电平表照旧可用。
